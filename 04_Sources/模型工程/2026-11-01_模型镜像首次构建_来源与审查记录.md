# 模型镜像首次构建：来源与审查记录

## 官方依据与推导边界

以下来源在本次会话中核对，外部依据先存入本记录，再用于知识正文的结构化补充。

| 来源 | 支持的事实 | 不支持的推断 |
|---|---|---|
| [Qwen3.5-9B模型卡](https://huggingface.co/Qwen/Qwen3.5-9B) | 发布Transformers格式的权重和配置，提供不同引擎的使用路径；页面有SGLang镜像使用示例 | 不能把推理引擎镜像认作模型公司原始预训练镜像；不能由页面当前安装命令倒推历史实验版本 |
| [PyTorch历史版本与安装命令](https://pytorch.org/get-started/previous-versions/) | 2.10.0提供cu126、cu128、cu130构建，配套torchvision为0.25.0 | 不证明其中任一组合在目标GPU、模型和扩展上通过验证；Python或torch版本不能唯一确定CUDA版本 |
| [NVIDIA CUDA次版本兼容](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html) | 驱动与CUDA应用存在兼容范围，次版本兼容具有功能和PTX等限制 | 不能只凭CUDA主版本相同或通用最低驱动号判断新GPU及所有算子都可用 |
| [NVIDIA Container Toolkit安装指南](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html) | GPU容器依赖宿主机驱动和容器运行时配置 | 镜像内安装CUDA库不能替代宿主机驱动 |
| [PyTorch扩展文档](https://docs.pytorch.org/docs/2.15/cpp_extension.html) | 编译C++/CUDA扩展需要相应工具链；CUDA扩展涉及目标计算架构 | 安装torch不代表编译环境齐全；此文档不作为历史torch版本的具体扩展兼容矩阵 |
| [Docker构建最佳实践](https://docs.docker.com/build/building/best-practices/) | 选择可信基础镜像；标签可能更新，可用digest固定输入；构建和运行阶段可分离 | 固定基础镜像摘要不等于所有软件包和训练结果完全可复现 |

“双向约束求交集—形成候选—逐层验证—冻结交付”是基于上述事实和用户问题作出的工程流程综合，不是某一家厂商规定的标准流程。

## 阅读路径的扩展关系

训练篇原导读为“验证训练 → 冻结依赖与实验输入 → 确定训练镜像组成 → 构建交付 → 独立验收”。该顺序仍适用于环境已经可用后的固化阶段；本次扩展为先完成首次候选环境设计，再进入原流程。新的完整入口是 [[01_Knowledge/模型/方法与流程/模型训练与环境固化流程#1.0 从模型与硬件约束设计首次环境]]，正文反向引用本记录。

这是一项范围扩展，不撤销原训练验收结论。原始预训练环境、公开权重运行环境、历史实验环境分别说明，避免用已有结果充当版本选择依据。具体版本未获独立支持时保留候选状态，不填造官方最低版本或已验证镜像标签。
