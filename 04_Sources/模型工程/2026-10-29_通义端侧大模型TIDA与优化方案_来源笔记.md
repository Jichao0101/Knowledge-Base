# 通义端侧大模型TIDA与优化方案：来源笔记

## 来源与阅读边界

本笔记整理用户提供的八张截图，主题涉及通义端侧大模型的训练、部署、推理、应用及配套优化。2026-10-29是本次整理日期，不代表原文发布日期。下文产品能力、技术说明和效果数字均为材料转述；原文链接、完整版本和测试报告尚未提供。

这份材料主要回答：客户如何把经过业务适配的模型部署到目标芯片，以及交付过程中有哪些性能优化手段和使用限制。它适合作为方案理解和验证线索，尚不能替代具体版本的接口文档或实测记录。

## 从模型训练到应用交付

材料将完整过程称为TIDA，即Training、Deployment、Inference、Application。训练先解决业务能力问题，部署再解决模型在目标硬件上的运行问题，推理优化则围绕运行表现展开，最终通过SDK接入应用。

| 阶段 | 材料所述工作 | 主要产出或关注点 |
|---|---|---|
| 训练 | 基于基础模型和场景数据进行SFT、LoRA、GRPO等增强 | FP16/BF16模型；先验证公开benchmark和下游业务效果 |
| 部署 | 面向芯片选择量化方法、调优精度，再通过芯片工具链编译 | target model，即目标端可运行的模型文件 |
| 推理 | 结合场景优化模型及推理引擎 | 加载时间、视觉/音频编码时间、prefill、decode、RAM、ROM、CPU/NPU占用及功耗 |
| 应用 | 将模型与插件组成的on-device SDK集成到系统服务或App | 智能座舱、意图分类、工具调用、交互百科及驾驶相关应用 |

材料将常规场景训练与蒸馏、剪枝、稀疏化等结构优化分开讨论。这里的FP16/BF16产物描述针对该方案，不定义所有模型训练的唯一输出格式。指标之间存在取舍，实际优化应根据业务确定优先级；材料特别强调首token时间（TTFT）、decode速度和RAM占用。

客户可以直接集成on-device SDK，也可以使用训练镜像、部署镜像和SDK打包工具自行迭代。部署镜像组合量化插件和芯片工具链；模型转换涉及计算图生成、算子映射等步骤，具体能力及产物依赖目标芯片。材料称通义提供相关工具，但模型转换主要由芯片厂商工具链承担。

## 训练环境与SDK使用边界

训练镜像基于LLaMA Factory和MS-SWIFT构建，材料称支持Nvidia GPU及PPU，展示了多个Qwen系列模型的适配情况；不同模型支持的全参数训练、LoRA、RM和DPO组合并不相同，不能据此推断所有方法均可用于所有模型。

材料中的“商业模型”可能涉及闭源授权、定制结构、蒸馏或剪枝、场景后训练，以及面向端侧量化的预处理等一种或多种特征。这是所述交付模型的分类，不应据此将同名开源模型也认定为闭源商业版本。

训练数据通常由客户准备。镜像和脚本以黑盒方式提供，权重加密，主要开放学习率、loss、warmup_ratio、epoch、batch size等常用配置。材料推荐使用阿里云相关训练资源；其他环境需要评估。开放模型结构、权重、完整脚本或引入源数据集等需求，需要另行商业约定。

SDK将指定模型版本、尺寸与一种或多种优化插件封装为C++接口。使用前需要确认以下条件：

- SDK绑定模型版本及尺寸、操作系统、芯片型号，并依赖具体芯片工具链版本；不同芯片型号间不能默认兼容。
- 模型权重和核心插件采用商业授权及加密保护，设备运行需要采集设备指纹并获取相应license。
- temperature和system prompt可通过接口动态配置；材料所述SDK的context size在编译时确定，调整需要联系开发方。
- 材料列举Nvidia、高通、MediaTek和ARM等平台，但实际型号、配置及插件支持范围仍需逐项确认。

## 推理优化：分别减少等待、内存和生成开销

TTFT指从提交prompt到输出首个token的时间。对材料讨论的多模态场景，视觉或音频编码以及LLM prefill是重要耗时环节，因此减少输入冗余是其优化思路之一。

**Vision Token Reduction**利用视觉token之间的冗余进行裁剪，减少后续计算，尤其面向大图、多图和视频输入。**Context Compression**则通过可学习的special tokens获取上下文压缩表示，并在后续推理中替代冗余上下文。前者主要减少视觉输入规模，后者主要缩短长文本或多轮会话的有效上下文。

当瓶颈是内存时，材料提出**Flash Embedding**：在模型转换阶段把embedding层从原网络剥离，将embedding表放在Flash中，运行时按token ID读取向量。其背景是材料所述静态图部署实现无法沿用训练侧embedding与lm_head的参数共享，可能产生额外内存占用；这不是对所有静态图后端的普遍结论。实际收益还需结合存储读取延迟和后端实现验证。

当瓶颈是逐token生成时，材料采用**投机采样**：先预测多个候选token，再验证并接受其中正确的部分。所述方案使用Eagle2/Eagle3及小于0.1B的草稿模型；草稿模型需要针对目标模型和任务训练，材料称暂不提供其训练镜像。截图列出的支持范围为：Nvidia Orin/Thor、MTK CX-1/CY-1支持Eagle3，高通和MTK其他芯片支持Eagle2。该列表仅记录材料中的状态，不代表当前完整兼容矩阵。

### 材料给出的效果数字

| 方法 | 材料声称的效果 | 尚缺少的判读条件 |
|---|---|---|
| 视觉token裁剪 | 在GQA、MME等数据集上保留50%视觉token时基本无精度损失；保留20%时精度损失约10% | 模型、任务子集、指标定义、损失计算方式及速度结果 |
| 上下文压缩 | BLEU Score能保持在95%以上 | 原始分数、相对保持率还是绝对分数、压缩率及推理任务验证 |
| Flash Embedding | 不同尺寸模型可减少约400～800 MB内存；以Qwen3-4B约777 MB的embedding为例 | 模型具体配置、MB口径、内存测量范围及读取延迟 |
| Eagle2/Eagle3 | 在4B及以上模型上分别可达2.x、4.x加速 | 基线、硬件、输入输出长度、接受率、任务分布及计时范围 |

这些数字只保留为来源声明。特别是BLEU结果不能单独证明通用推理能力不变，单项内存节省或decode加速也不等于端到端响应按同比例改善。

## 量化：数值分组与分布处理

材料将量化视为端侧部署中的关键环节：降低表示精度可以减少模型存储和运行资源需求，但需要控制任务精度损失，并匹配芯片实际支持。其介绍重点有两个：哪些数值共享量化参数，以及量化前如何处理异常值或分布差异。

| 粒度 | 材料中的参数共享方式 |
|---|---|
| Per-layer / Per-tensor | 整个张量共享一组scale、zero-point |
| Per-channel | 每个通道使用独立参数 |
| Per-token | 每个输入token使用独立参数 |
| Per-group | 按预定义分组共享参数，例如每组128个元素 |
| Per-block | 按固定大小的数据块共享参数 |

该表仅记录划分思路。不同实现的通道轴、分组方式和块形状需要另行定义，不能只根据名称建立统一的粒度粗细排序或精度优劣关系。额外参数、运行时计算和硬件支持共同影响收益。

在数值分布处理方面，材料列出以下方法：

- **SmoothQuant**：通过等效缩放，将部分激活量化难度转移到权重。材料用`Y = XW = (XS⁻¹)(SW)`说明其基本变换关系。
- **SpinQuant**：利用可学习旋转改善权重或激活分布，缓解低比特量化中的异常值影响。
- **FlatQuant**：使用可学习变换降低分布差异，使数值更适合低比特量化。
- **PrefixQuant**：材料将其描述为针对前缀敏感token及异常值的特殊处理。具体算法是否对应材料中的“前缀高精度保留”解释，仍需核对原论文或实现，暂不作为确定机制。

材料称这些方法会按模型和芯片组合使用，并作为部署镜像中的插件提供；内部权重/激活分析、搜索和自动优化工具暂未对外提供。其给出的常见公开benchmark量化精度损失准入目标是3%以内，但未说明相对百分比或绝对百分点，也未给出完整评测协议，不能直接用作业务验收阈值。
