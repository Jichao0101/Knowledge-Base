# Agent工程化边界核验

## 摘要

本来源笔记用于支撑本次对 Agent 系统文档的最小修复，重点核验 Skill-first、MCP/Tool/Skill/Knowledge-Base 边界、Tracing/Eval、Guardrails 和上下文管理相关表述。

## 来源

- Model Context Protocol Architecture: https://modelcontextprotocol.io/docs/learn/architecture
- OpenAI Codex Skills: https://developers.openai.com/codex/skills
- OpenAI Agents SDK overview: https://developers.openai.com/api/docs/guides/agents
- OpenAI Agents SDK integrations and observability: https://developers.openai.com/api/docs/guides/agents/integrations-observability
- OpenAI agent workflow evals: https://developers.openai.com/api/docs/guides/agent-evals
- OpenAI Agents SDK guardrails: https://openai.github.io/openai-agents-python/guardrails/
- OpenAI Agents SDK tracing: https://openai.github.io/openai-agents-python/tracing/

## 核验结论

- MCP 是连接 AI 应用与外部能力的协议层，核心 primitives 包括 tools、resources、prompts；Tool 是可执行动作接口，不等于 MCP 本身。
- Codex Skills 是可复用 workflow 的 authoring format，采用渐进式披露；Skill 应保持聚焦，并通过描述触发。
- Agents SDK 的工程关注点包括 orchestration、tool execution、approvals、state、MCP、guardrails、observability。
- Tracing 应记录 model calls、tool calls、handoffs、guardrails 和 custom spans；eval 可基于 traces、graders、datasets 和 eval runs 形成回归检测。
- Guardrails 有 input/output/tool 等运行位置差异；复杂 workflow 不能只依赖 agent-level guardrail。

## 适用范围

用于修正正式知识中 Agent 工程化分层的边界描述，不用于宣称任何具体产品能力永久稳定。

## 风险

- 官方文档和 SDK 行为会随版本变化。
