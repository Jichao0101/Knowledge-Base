# 1 概率模型视角的信息压缩与交叉熵

## 1.1 主线：预测越准确，描述真实数据越省 bit

压缩一段文本时，编码端和解码端都使用同一个模型。读到前缀 $x_{<t}$ 后，模型给出下一 token 的条件概率 $q_\theta(x_t\mid x_{<t})$。真实 token 概率高，编码时就能用更短的描述；概率低，就需要更长的描述。逐 token 累积后，熵编码器生成可供解码的 bitstream。

```text
已知前缀 → 模型预测下一 token 的概率
真实 token + 预测概率 → 理论码长 → 熵编码器 → bitstream
bitstream + 相同模型及约定 → 逐 token 恢复原文
```

这条主线将模型训练和数据压缩连接起来：模型学习可利用的统计规律，编码器把概率优势变成实际节省的 bit。[预测与算术编码机制：Delétang 等，第 2 节](https://arxiv.org/html/2309.10668v2#S2)。

## 1.2 模型、surprise、编码器分别做什么

| 对象 | 当前一步发生的事 | 最终作用 |
|---|---|---|
| 模型 $q_\theta$ | 根据已有 token 分配下一 token 的概率 | 利用词法、语法、共现、上下文等规律预测 |
| surprise $r_t$ | 计算真实 token 的 $-\log_2q_\theta(x_t\mid x_{<t})$ | 计量该 token 的理想编码成本 |
| 熵编码器 | 接收概率表和真实 token | 把概率对应的码长优势写入二进制流 |
| bitstream $B$ | 累积各步编码结果 | 配合相同模型与约定，支持无损恢复 |

例如模型给真实 token 分配 $0.5$，该步 surprise 是 $1$ bit；分配 $0.25$，则是 $2$ bits。这里的“剩余信息”指给定模型后还要说明真实结果的成本。熵编码器使用**概率表和真实 token**，surprise 则是理解码长的度量。

## 1.3 训练时：loss 衡量潜在的编码成本

将 $D=x_{1:n}$ 看作要编码的 token 序列，冻结某一时刻的模型：

$$
L_{\mathrm{ideal}}(D\mid M_\theta)
=-\log_2q_\theta(D)
=\sum_{t=1}^{n}-\log_2q_\theta(x_t\mid x_{<t})
$$

右侧是每步 surprise 的总和，也是该模型配合理想熵编码器时的数据理论码长。普通 next-token 训练计算这些负对数概率，并通过梯度调整参数；实际 bitstream 在编码阶段才出现。因此，“隐式 bitstream”指**可由 loss 估计的长度**，不是训练中已有的一段 01 序列。[来源：Delétang 等，第 2 节](https://arxiv.org/html/2309.10668v2#S2)。

总 NLL 转换为 bit 后，对应整段序列的理论成本；除以 token 数得到平均 bits/token。自然对数的 NLL 除以 $\ln2$ 才转换为 bit。比较模型时应冻结各自参数，在相同数据、tokenizer、上下文和计数口径下评估。若损失包含 label smoothing、样本权重或正则项，应单独取真实 token 的未加权 NLL 计算上述码长。

## 1.4 为什么交叉熵下降会缩短平均码长

令 $p$ 是真实序列分布，$q$ 是模型分布，且 $q$ 给 $p$ 可能产生的序列分配非零概率。按定义有：

$$
H(p,q)=H(p)+D_{\mathrm{KL}}(p\|q)
$$

$H(p)$ 是该来源的平均理想成本；KL 是模型分布与真实分布不一致带来的平均额外成本。模型更贴近来源时，失配成本减小，交叉熵随之接近来源熵。信息不等式保证这一平均额外成本非负。[来源：Grünwald，第 2.2.3 节](https://arxiv.org/html/math/0406077)。

对固定长度 $n$ 的文本，平均**总**成本对应联合熵 $H_p(X_{1:n})$；平均每 token 成本则要除以 $n$。即使 $q=p$，真实来源中仍可能存在下一 token 的不确定性，这部分仍需编码。对某份固定数据，NLL 下降说明其理论总码长下降；模型是否学会了跨样本规律，还需看独立数据上的表现。

## 1.5 实际编码与解码：概率优势怎样落到文件上

| 环节 | 普通训练 | 实际无损编码 |
|---|---|---|
| 模型参数 | 通过梯度更新 | 固定后供编码端与解码端使用 |
| 处理真实 token | 计算 NLL | 连同概率表送入熵编码器 |
| 产物 | 参数和损失数值 | 真实 bitstream |
| 下一步 | 继续训练或评估 | 解码端逐步恢复 token |

编码时，模型按已知前缀提供概率；熵编码器按真实 token 更新编码状态并输出 bit。解码时，已恢复的前缀让同一个模型重建概率，解码器再根据 bitstream 确定下一个真实 token。解码由 bitstream 选择结果，概率最高的 token 只是模型预测。

若编码器使用量化概率表 $\widetilde q$，实际长度可用下式估计：

$$
|B|\approx-\sum_t\log_2\widetilde q(x_t\mid x_{<t})
+\Delta_{\mathrm{coder}}+\Delta_{\mathrm{format}}
$$

这些附加项覆盖整数化、终止和文件格式等成本。解码双方需约定模型、tokenizer、上下文窗口、符号顺序、概率量化、初始状态和长度/结束方式。恢复原始字节还要求预处理可逆。具体编码器（如算术编码、range coding、ANS）各有状态和符号顺序要求。

## 1.6 两个例子：小数码长与条件规律

**偏置来源。** 若独立符号满足 $p(0)=q(0)=0.99$、$p(1)=q(1)=0.01$，则 0 的 surprise 约为 $0.0145$ bit，1 的 surprise 约为 $6.6439$ bits，平均约 $0.0808$ bits/symbol。训练阶段只计算这些数值；实际编码跨符号累积，最后输出整数个 bit。若模型始终给 0 和 1 各 $0.5$，平均成本变成 $1$ bit/symbol，多花约 $0.9192$ bit/symbol。

**交替序列。** `010101...` 的 0 和 1 各占一半；给定“每步交替”的规则后，下一个 bit 却可以从前一位推得。编码时主要需要说明起始位、长度，以及接收端尚未拥有的规则。这说明可压缩性取决于**条件预测能力**，而不只是 0/1 的边际比例。

## 1.7 压缩输出为什么可能看似随机

模型和编码器逐步利用来源的规律后，bitstream 中可供继续利用的结构往往减少，因此其载荷可能显得难以预测。这是判断冗余是否还存在的线索。若后级压缩器在计入自身元数据和解码约定后仍能稳定缩短总长度，当前模型、编码器或文件格式还有改善空间。

有限文件可能包含文件头、终止信息或偶然模式；“看起来随机”和“某个压缩器压不动”都不足以证明最短码长。后级方案应按完整成本评估，而非把“不可继续压缩”设为训练目标。

## 1.8 MDL：把模型成本计入总账

前面假设解码端已经拥有模型。如果模型需要随数据一起交付，就要计入它的表示成本。二段式描述给出：

$$
L_{\mathrm{total}}=L(M)+L(D\mid M)
$$

$L(M)$ 包括结构、参数精度及必要约定；$L(D\mid M)$ 是使用该模型编码数据的成本。普通 NLL 直接衡量后者的理想部分。模型记住训练实例可能降低训练 NLL，却增大模型成本；跨样本共享规律则有机会在多份数据上持续节省 bit。[二段式描述：Grünwald，第 1.3—1.4 节](https://arxiv.org/html/math/0406077)。

工程比较应说明模型是否预先共享，并记录模型大小、实际压缩文件大小和独立数据上的 NLL。研究中的“只计数据流”和“计入模型”两种压缩率也正对应这两个口径。[Delétang 等，第 3.2 节](https://arxiv.org/html/2309.10668v2#S3.SS2)。

## 1.9 适用边界与常见误区

本文讨论**离散符号、概率可重现的无损编码**。连续概率密度、摘要压缩、蒸馏和权重量化涉及不同的编码对象；使用本篇码长关系时，需要重新定义其符号、损失与恢复约定。

容易混淆的三个量是：模型输出分布的熵描述模型有多确定；真实 token 的 NLL 衡量模型对数据的预测和理论编码成本；实际文件长度还包含编码与格式开销。模型越自信，只有在真实结果也得到高概率时才会缩短 NLL。训练 loss 很低时，还要结合测试数据与模型成本判断是否形成可复用压缩。

## 1.11 核心总结

- 模型从上下文给出下一 token 的条件概率。
- 真实 token 的 surprise 是该步的理想码长。
- 总 NLL 汇总理论成本；平均交叉熵便于比较每 token 成本。
- 训练用 NLL 更新参数；实际编码器用概率和真实 token 生成 bitstream。
- 解码端凭相同模型与约定，从 bitstream 恢复真实 token。
- 模型越贴近来源，平均失配成本越小；来源自身的条件不确定性仍需编码。
- 完整比较还要计入模型、协议与文件成本。
