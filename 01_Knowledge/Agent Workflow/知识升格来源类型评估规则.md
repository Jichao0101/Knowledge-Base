# 知识升格来源类型评估规则

- 状态: verified
- 类型: governance_rule
- 来源: 用户在知识库维护过程中的审核指令
- 适用范围: `03_Inbox/`、`04_Sources/`、`02_Projects/` 内容评估是否进入 `01_Knowledge/`
- 风险或不适用范围: 不替代具体条目的事实核验；只定义不同来源进入知识区时应采用的评估口径

## 摘要

项目内容升格和外部资源升格应采用不同评估口径。

项目内容来自内部任务、实验、实现、review、board validation 或决策记录。它升格为知识时，重点是从具体项目中抽象出可复用机制、失败模式、验证模式或工程约束。

外部资源来自视频、文章、论文、教程或第三方总结。它进入知识库时，更像是建议、思路、启发或待验证模式；除非经过内部验证或与内部已验证机制对齐，否则不应标为 verified runtime fact 或 verified design pattern。

## 项目内容升格

项目内容可以通过泛化评估升格为正式知识。

评估重点:
- 是否有内部任务、实验、代码、日志、review 或 board evidence 支撑。
- 是否能从项目语境抽象为更通用的机制或模式。
- 是否写清适用范围、边界、风险和反例。
- 是否已从具体实现细节中提炼出可复用判断准则。

适合的知识类型:
- verified_runtime_fact
- verified_design_pattern
- failure_pattern
- validation_pattern
- project_decision_generalization
- engineering_constraint

## 外部资源升格

外部资源可以被知识化，但默认不等同于已验证知识。

评估重点:
- 来源是否清晰。
- 内容是否经过结构化整理，而不是原文堆叠。
- 是否明确标注为建议、思路、启发或待验证模式。
- 是否写清“尚未内部验证”的边界。
- 是否能映射到本地已有机制、项目经验或后续验证计划。

适合的知识类型:
- reviewed_advisory
- external_inspired_pattern
- heuristic
- research_note
- idea_candidate
- validation_candidate

## 升格判断

外部资源只有在满足以下任一条件时，才可以从“建议/思路”进一步升级为已验证知识:
- 被至少一个内部项目或真实 workflow run 验证。
- 与已有 verified knowledge 形成明确一致关系，并且边界已写清。
- 经过内部 review 后，被明确采纳为治理规则或工程约束。
- 形成可执行验证流程，并由验证结果支撑。

否则，外部资源即使进入 `01_Knowledge/`，也应标为 `reviewed_advisory` 或 `external_inspired_pattern`，不得标为 `verified_runtime_fact`。

## 写入要求

项目泛化条目应写:
- 内部依据
- 泛化过程
- 可复用结论
- 适用范围
- 风险和不适用范围

外部资源条目应写:
- 外部来源
- 建议或启发内容
- 与本地机制的关系
- 未验证边界
- 后续验证条件

## 反模式

- 把外部视频或文章中的建议直接写成 verified fact。
- 因为外部观点与本地设计相似，就声称本地已实证其效果。
- 把 synthetic fixture、host-only fallback 或演示材料当作真实验证案例。
- 把项目中的一次临时做法直接泛化为通用知识，未说明前提和风险。
