# 1 信息论在 LLM 训练与蒸馏中的核心联系

## 1.1 核心结论

信息论为语言模型提供了一套统一视角：模型输出概率分布，真实 token 的负对数概率既是预测损失，也可解释为理想编码长度。对大量真实样本取平均得到交叉熵；交叉熵相对真实分布熵多出的部分是 KL 散度。知识蒸馏则把教师分布作为目标分布，通过教师—学生交叉熵让学生逼近教师的完整概率结构。

模型负责输出条件概率，熵编码器负责把概率优势兑现为实际 bitstream。普通训练通常只计算损失，不运行熵编码器；因此要区分“理论编码长度”和“真实二进制输出”。模型可能学习可复用结构，也可能记忆实例细节，不能仅凭训练损失下降判断其泛化能力。

## 1.2 信息量、熵与交叉熵

### 1.2.1 信息量

事件 $x$ 的自信息为：

$$
I(x)=-\log_2 p(x)
$$

低概率事件发生时更意外，因此携带的信息量更大。这里的信息量描述事件发生后的意外程度，不等同于“对学习一定更有价值”。

使用模型 $q$ 衡量观测的意外程度时，写作 $r_q(x)=-\log_2 q(x)$。它是模型下的 surprise 或理想码长，不是“预测值减真实值”的数值残差；只有 $q=p$ 时才与上述真实分布下的自信息一致。若 $p(x)>0$ 而 $q(x)=0$，对应损失无穷大，实际编码必须避免给可能出现的符号分配零概率。

### 1.2.2 熵

真实分布 $p$ 的熵为：

$$
H(p)=\mathbb E_{x\sim p}[-\log_2 p(x)]
$$

它表示真实来源中每个符号的平均信息量，也是在理想概率编码下的平均编码成本。

### 1.2.3 交叉熵

使用模型分布 $q$ 预测或编码来自真实分布 $p$ 的数据时：

$$
H(p,q)=\mathbb E_{x\sim p}[-\log_2 q(x)]
$$

其中 $p$ 决定哪些事件实际出现及其频率，$q$ 决定模型为事件分配的预测概率或理想码长。若模型把很小的 $q(x)$ 分给实际经常出现的事件，该事件会产生较大的平均损失。

有限数据上的平均负对数概率是交叉熵的经验估计，单位为 bits/token 或 bits/symbol；将这些负对数概率相加得到总 NLL，单位为 bit。若使用自然对数，单位则为 nat，换成 bit 需除以 $\ln 2$。

## 1.3 KL 散度：错误概率预算的平均额外成本

交叉熵可以分解为：

$$
H(p,q)=H(p)+D_{\mathrm{KL}}(p\|q)
$$

其中：

- $H(p)$ 是真实分布自身不可避免的平均编码成本；
- $D_{\mathrm{KL}}(p\|q)$ 是错误使用 $q$ 代替 $p$ 带来的平均额外成本。

抽象地看，概率总预算必须归一化为 1。用 $q$ 给某些消息增加概率，会迫使另一些消息获得更少概率。若数据确实来自 $p$，这种重新分配可以使个别事件的编码变短，却不能使长期加权平均成本优于 $p$ 针对自身的最优分配。因此：

$$
D_{\mathrm{KL}}(p\|q)\ge 0
$$

非负性是平均意义上的结论，不表示使用 $q$ 后每个事件的编码都会变长。KL 散度还有方向性，$D_{\mathrm{KL}}(p\|q)$ 与 $D_{\mathrm{KL}}(q\|p)$ 通常不同。

因此，在固定真实分布与评估口径下，改善 $q$ 减少的是分布失配造成的平均额外编码成本，不是把真实来源的熵消除。对于语言序列，应使用联合分布及其条件分解；上下文能降低条件不确定性，但不保证剩余条件熵为零。

## 1.4 自回归 LLM 中的交叉熵

语言 token 不是独立事件。自回归模型使用此前上下文预测当前 token：

$$
q(x_{1:n})=\prod_{t=1}^{n}q(x_t\mid x_{<t})
$$

取负对数后，整段序列的乘积转化为逐 token 损失之和：

$$
-\log_2q(x_{1:n})
=\sum_{t=1}^{n}-\log_2q(x_t\mid x_{<t})
$$

单个训练样本通常提供 one-hot 真实 token，因此单步交叉熵就是 $-\log q(x_t\mid x_{<t})$。在大量训练样本上取平均，才近似对真实数据分布求期望。降低该损失会迫使模型提高真实后续 token 的条件概率，从而学习上下文中的语法、语义和统计规律。

### 1.4.1 四个对象及其职责

| 对象 | 输入与输出 | 职责与边界 |
|---|---|---|
| 模型 $q_\theta$ | 上下文 → 下一 token 的概率分布 | 捕获词法、语法、语义及长程依赖等结构；本身不输出压缩文件 |
| surprise $r_t$ | 真实 token 及其模型概率 → $-\log_2 q_\theta(x_t\mid x_{<t})$ | 度量观测的理想码长，不是数值残差，也不是待编码的独立符号流 |
| 熵编码器 | 概率分布与真实 token → 编码状态及二进制输出 | 如 arithmetic coding、range coding、ANS；利用概率分配码长，不自行理解语义 |
| bitstream $B$ | 编码器实际输出的二进制序列 | 与相同模型及解码约定一起，保留无损恢复真实序列所需的信息 |

“剩余信息”在此指给定模型及上下文后的描述成本，不意味着存在一份可以从原始数据中直接相减得到的残差文件。高概率 token 通常贡献较小的理想码长，低概率 token 贡献较大的理想码长。

### 1.4.2 训练阶段：NLL 是理论长度，不是一条具体 bitstream

令 $D=x_{1:n}$，冻结当前模型后，定义：

$$
L_{\mathrm{ideal}}(D\mid M_\theta)
=-\log_2 q_\theta(D)
=\sum_{t=1}^{n}r_t,
\qquad
\widehat H_{\mathrm{bit}}=\frac{L_{\mathrm{ideal}}}{n}
$$

若训练用自然对数计算总损失 $L_{\mathrm{NLL,nat}}$，则 $L_{\mathrm{ideal}}=L_{\mathrm{NLL,nat}}/\ln 2$。这里要求计数相同的 token、上下文及序列边界；被 mask 的 token 或外部提供的上下文不在该损失中，若解码端未共享它们，就要另计传输成本。

这一长度可以理解为：假设解码端已经拥有当前模型及必要约定，再连接理想熵编码器，对指定 token 序列编码的理论成本。普通训练通过反向传播改变参数，没有生成对应的 01 序列。“隐式 residual bitstream”只是这一长度的直觉说法；NLL 不能确定唯一 bitstream，也不包含模型本身的传输成本。

训练过程中参数持续变化，因此不能把不同训练步记录的 loss 相加，当成最终模型对整个训练集的码长；需要冻结同一模型重新评估。对相同数据，NLL 下降意味着总理想码长下降，不保证每个 token 的概率都上升，也不保证测试集效果改善。

### 1.4.3 实际编码与解码：把概率优势兑现为 bit

| 环节 | 普通训练 | 实际无损压缩 |
|---|---|---|
| 输入 | 训练 token 和上下文 | 待压缩 token、冻结模型及编码约定 |
| 模型输出 | 条件概率 $q_\theta$ | 同样的条件概率，再转换为编码器支持的概率表 |
| 核心操作 | 计算 NLL、反向传播、更新参数 | 编码真实 token，累积并输出整数长度的 bitstream |
| 结果 | 模型参数；损失对应理论码长 | 可供解码的真实 bitstream |
| 成本口径 | 通常报告平均 loss | 计入概率量化、终止、文件头等开销；是否计模型需明确 |

统一数据流如下；surprise 是度量分支，不是编码器必须先接收的“误差数组”。

```text
训练：
真实前缀 → 模型概率
模型概率 + 真实 token → surprise → 总 NLL → 梯度更新模型

实际编码：
真实前缀 → 冻结模型概率
模型概率 + 真实 token → 熵编码器 → bitstream

实际解码：
已恢复前缀 → 相同模型概率
模型概率 + bitstream → 熵解码器 → 下一个 token → 更新前缀
```

解码恢复的是实际发生的 token，不是简单选择 argmax。双方必须使用一致的模型、tokenizer、上下文窗口、起始/结束约定及编码概率表。外部上下文必须共享或传输；恢复原始文本还要求分词、预处理可逆，否则只能保证恢复 token 序列。ANS 等具体方案还需协调编码顺序和状态管理，不能默认所有编码器具有相同的流式接口。

以 $\widetilde q_\theta$ 表示实际量化后的编码概率：

$$
|B|\approx\sum_{t=1}^{n}-\log_2\widetilde q_\theta(x_t\mid x_{<t})
+\Delta_{\mathrm{coder}}+\Delta_{\mathrm{format}}
$$

附加项表示终止、整数化及格式等开销，不是每个 token 都单独取整。只有实际概率接近模型概率且开销足够小时，实际长度才接近原始 NLL。上述预测—编码对应与算术编码机制可参见 [Language Modeling Is Compression，第 2 节](https://arxiv.org/html/2309.10668v2#S2)。

更准确的恢复关系是：

$$
D=\operatorname{Decode}(B;M_\theta,\mathcal A)
$$

其中 $\mathcal A$ 表示共享约定。不写成 $D=M+B$，因为模型与 bitstream 不是原始数据的两个可相加分量。模型使统计依赖可被利用，编码器据此减少显式描述成本，同时保留区分真实序列所需的信息；数据的信息并未消失。

### 1.4.4 两个例子：小数 bit 与条件规律

**例 1：强偏置二值来源。** 假设符号独立且 $p(0)=q(0)=0.99$、$p(1)=q(1)=0.01$：

$$
r(0)=-\log_2 0.99\approx0.0145\ \mathrm{bit},
\qquad
r(1)=-\log_2 0.01\approx6.6439\ \mathrm{bit}
$$

平均成本约为 $0.99\times0.0145+0.01\times6.6439\approx0.0808$ bits/symbol。训练只计算这些数值；实际编码跨多个符号累积信息量，最后输出整数个 bit，并不会产生一段物理上的“0.0145 bit”。

**例 2：交替序列。** 对 `010101...`，边际上 0 和 1 各占一半，但知道交替规则和前一个 bit 后，下一个 bit 就确定了。给定规则，只需说明起始符号、长度及必要约定即可恢复整段序列；若规则未共享，还需计入规则描述成本。因此边际均衡不能证明序列不可压缩，关键在于是否还有可利用的条件规律。

### 1.4.5 最短码长、随机外观与不可继续压缩

对固定长度 $n$ 的序列，理想长度的期望满足：

$$
\mathbb E_{D\sim p}[L_{\mathrm{ideal}}(D\mid M)]
=H_p(X_{1:n})+D_{\mathrm{KL}}(p_{1:n}\|q_{1:n})
$$

$$
H_p(X_{1:n})=\sum_{t=1}^{n}H_p(X_t\mid X_{<t})
$$

模型逼近真实序列分布时，失配成本趋近于零，平均总理想码长接近联合熵；除以 $n$ 才是平均每 token 成本。只要条件不确定性仍存在，即使模型准确，剩余编码成本也不会归零。这里是分布上的平均结论，不是每条有限序列都达到同一个下界。

接近最优压缩的载荷通常表现得更难预测，因为可利用的冗余已被消除。理想化地，在相应来源与编码约束下，可将其理解为输出 bit 难以根据前缀持续预测得优于随机猜测；不能要求每个有限文件的每一位都严格满足条件概率为 0.5。文件头、终止信息、长度条件和偶然模式都可能造成偏离。

“不可继续压缩”是接近最短描述时的结果或诊断线索，不是独立训练目标。若第二级压缩器在计入额外元数据与解码成本后仍能系统性缩短输出，说明当前模型、编码实现或文件格式仍有可利用结构。反之，某个通用压缩器压不动它，也不能证明全局最优。随机外观更不等于加密安全。

### 1.4.6 MDL：模型本身也不是免费的

完整压缩视角需考虑：

$$
L_{\mathrm{total}}=L(M)+L(D\mid M)
$$

其中 $L(M)$ 包括按约定表示模型所需的成本，$L(D\mid M)$ 是给定模型后的数据描述成本；完整文件还需计入未共享的协议和元数据。模型已预先共享时，可以只比较后者；若模型专门为该数据训练且需要交付，就不能忽略前者。

普通 LLM 的 NLL 直接优化理想条件描述长度，而不是上述总成本。模型既可能学会跨样本规律，也可能记住训练实例；极低训练 loss 不能单独证明有效压缩或泛化。评价应同时考虑模型表示成本、数据规模及独立测试数据上的预测表现，不把“记忆”与“总描述更短”直接画等号。

## 1.5 困惑度不是候选 token 的实际数量

若交叉熵按平均 bits/token 计算，困惑度为（有限评估集使用经验平均 $\widehat H_{\mathrm{bit}}$，不能代入总 NLL）：

$$
\mathrm{PPL}=2^{H(p,q)}
$$

困惑度可理解为模型预测下一 token 时的“等效选择数”。例如 3 bits/token 对应困惑度 8，其难度等效于每一步从 8 个等概率选项中选择一个，但不表示模型在每一步真的面对 8 个等概率 token。

只有在 tokenizer、测试集、预处理和损失口径一致时，困惑度才适合直接比较。困惑度从 8 增加到 16，表示平均每个 token 多付出 1 bit 的信息损失。

## 1.6 熵低不等于模型正确

模型输出分布自身的熵 $H(q)$ 衡量模型有多不确定，不关心答案是否正确。模型可以对错误答案分配接近 1 的概率，此时自身熵很低，但在真实数据上的交叉熵很高。

因此：

- 低熵表示输出更确定；
- 低交叉熵表示真实结果获得了更高概率；
- 只最小化学生自身熵会产生任意 one-hot 的投机解，只能保证自信，不能保证正确或接近教师。

因此，降低模型输出分布自身的熵，不等于缩短真实数据的编码长度；后者取决于真实 token 获得的概率。

## 1.7 为什么交叉熵可用于大模型蒸馏

设教师和学生在同一上下文下的词表分布分别为 $q_T$ 与 $q_S$。蒸馏损失可以写为：

$$
H(q_T,q_S)=H(q_T)+D_{\mathrm{KL}}(q_T\|q_S)
$$

教师固定时，$H(q_T)$ 是常数，因此最小化教师—学生交叉熵等价于最小化定向 KL 散度，迫使学生逼近教师的完整概率分布，而不只是复制概率最高的 token。

教师软分布包含“暗知识”：它不仅指出最佳答案，还表达其他 token 错得有多近。例如教师给“猫、虎、狗、汽车”分配不同概率，能够传递类别或 token 之间的语义相似性。这里的价值来自完整分布中的相对关系，而不是简单因为“小概率事件的信息量大”。

这里“压缩模型”与前文“压缩数据”需要区分：蒸馏通常用更小的学生近似教师行为；熵编码则借助概率模型无损恢复数据。降低教师—学生 KL 不自动保证真实数据交叉熵降低，教师也可能存在错误和偏差。软分布的相对关系可能包含有用语义，也可能反映噪声或偏差，不能把每个小概率值都当作正确知识。

### 1.7.1 温度的作用

带温度的 softmax 为：

$$
q_i(T)=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)}
$$

当 $T>1$ 时，分布变得更平坦，原本几乎不可见的非最高概率 token 获得更明显的概率和梯度信号，从而展开教师分布中的相对结构。实践中常用 $T^2$ 补偿升温导致的梯度尺度变化。

### 1.7.2 硬标签与软标签互补

典型蒸馏目标同时包含：

$$
L=(1-\alpha)H(y,q_S)+\alpha T^2H(q_T^{(T)},q_S^{(T)})
$$

- 硬标签 $y$ 是事实锚点，规定任务最终要答对什么；
- 教师软分布传递替代答案之间的关系；
- 二者结合可减少学生完整继承教师错误、偏见或过度不确定性的风险。

## 1.8 常见误区与边界

1. **“小概率类别信息量大，所以蒸馏要学习它。”** 不准确。蒸馏的核心是学习教师完整分布中的相对结构，而非奖励所有小概率类别。
2. **“低熵就是好模型。”** 不成立。低熵只表示自信；错误且自信的模型仍可能有很高的测试交叉熵。
3. **“困惑度为 8 就是有 8 个等概率候选。”** 不成立。8 是跨样本平均后的等效选择数。
4. **“字符或 token 天然独立。”** 不成立。语言模型显式建模给定历史上下文的条件概率。
5. **“KL 非负意味着每个事件都付出额外成本。”** 不成立。个别事件可以更省，非负性约束的是按真实分布加权后的平均值。
6. **“随机噪声绝对不可压缩。”** 应限定为：在给定概率模型和编码约束下，缺乏可利用结构的高熵来源不能被无损压缩算法在平均意义上进一步压缩；个别有限字符串仍可能偶然具有较短描述。

7. **“训练时模型直接产生压缩 bitstream。”** 不成立。普通训练计算 NLL；只有接入具体编码过程后才产生真实 bitstream。
8. **“surprise 就是预测误差，bitstream 就是误差数组。”** 不准确。surprise 是负对数概率；bitstream 与模型和约定一起支持无损恢复。
9. **“交叉熵最小意味着全部信息已存入模型。”** 不成立。剩余条件不确定性仍要编码，而且训练 loss 下降也可能来自记忆。
10. **“低交叉熵保证更小的完整压缩文件。”** 需固定 tokenizer、数据和上下文口径，并计入模型、概率量化和格式开销。
11. **“噪声是最高层次的压缩。”** 不准确。难预测的输出可能是消除冗余的结果，但随机外观不是最优压缩的证明，也不是加密保证。
12. **“每个 token 都应占用整数个独立 bit 片段。”** 不成立。理想码长可以是小数，熵编码器跨符号累积后输出整数长度的序列。

### 1.9.2 核心总结

- 模型输出条件概率，可能学到共享规律，也可能记忆实例细节。

- 普通训练更新参数，不生成压缩 bitstream。

- 更好的概率建模减少失配冗余，但不消除来源剩余的不确定性。
- 完整压缩还要计算模型与协议成本；随机外观不能单独证明压缩最优。
