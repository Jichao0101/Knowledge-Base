# 1 OMS Demo 项目总览

## 1.1 项目目标

在高通 8775 端侧算力和内存受限的前提下，验证一种不依赖完整 VLM 的 OMS 架构：轻量 CNN 持续完成舱内视觉感知，时序状态引擎将多帧结果压缩成结构化语义状态，小型 LLM 以较低频率完成场景理解、意图归纳和策略选择。

本项目中的 OMS 面向座舱内人员、物体、姿态、交互和上下文的综合理解，不按“DMS 功能扩展”定义，也不把安全报警链路作为设计中心。

## 1.2 当前范围

- CNN 以约 10～30 FPS 输出 gaze、object、posture 等感知结果。
- 时序状态引擎负责 EMA、迟滞、持续时间、置信度校准和事件形成。
- Semantic State Store 保存可追溯、可增量更新的座舱语义状态。
- Event Scheduler 根据状态变化、歧义、超时、策略请求和资源预算触发 LLM。
- 100M～1B 级小型 LLM 使用固定 JSON 输入输出和约束解码。
- Policy Engine 将已校验的 LLM 决策映射到 HMI、座舱交互或其他应用策略。

## 1.3 暂不纳入

- 将 OMS 等同于 DMS 扩展版。
- 以疲劳、分心等安全报警作为核心业务闭环。
- 让 LLM 直接处理原始图像、逐帧检测列表或未经压缩的 CNN 特征向量。
- 让 LLM 直接改写感知事实或绕过策略白名单执行任意动作。
- 在缺少实测数据时声明具体帧率、端到端延迟、模型常驻方式或量化配置已经达标。

## 1.5 当前状态

项目处于架构方案阶段。芯片侧算子支持、模型内存峰值、CNN/LLM 并发方式、100M 与 1B 模型能力边界，以及真实 OMS 场景数据集均待实测确认。
