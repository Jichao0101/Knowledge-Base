# 1 设计目标

针对当前睁闭眼分类模型，尤其在 `eye_narrow` 与 `eye_occluded` 类别上的识别不足，构建一套**可复现、可归因、可部署对齐**的对照实验流程，从以下两个维度定位主因并评估优化收益：

- **Loss 设计**：评估类别不平衡与难样本学习问题对模型性能的影响
- **输入构造方式**：评估 padding 伪特征、有效区域占比捷径以及真实上下文保留方式对模型性能的影响

同时，由于原 **MobileNetV3** 模型在量化后掉点严重，当前 backbone 已切换为 **MobileNetV2**。因此，实验流程需先完成 **V2 基线重建**，在训练超参数与量化表现稳定后，再开展 loss 与输入构造方式的单变量对照实验。

实验设计遵循以下原则：

1. **先稳定 backbone 基线，再做单变量对照**
2. **训练输入与部署输入尽量对齐**
3. **评估基准冻结，保证版本间可比**
4. **除被比较变量外，其余训练与评估配置保持一致**

---

# 2 实验阶段划分

为避免 backbone 切换与 loss / 输入策略改动相互耦合，整体实验分为四个阶段。

## 2.1 Stage T1：MobileNetV2 基线重建

目标：

- 在固定数据版本、固定 split、固定输入基线的前提下，重新确定适用于 **MobileNetV2** 的训练超参数
- 先完成当前代码链路下可执行的 **FP32 基线重建**
- 若量化链路已接通，则在 FP32 基线稳定后补充量化评估
- 选择一个可作为后续所有对照实验公共底座的训练配置

本阶段**不比较**：

- Weighted CE / Focal / Label Smoothing
- 多种输入构造方式
- 大范围 bbox jitter
- 复杂增强组合

本阶段仅调节：

- learning rate
- weight decay
- EMA
- 基础增强强度

## 2.2 Stage T2：Loss 对照实验

在 T1 确定的 **V2 稳定基线** 上，仅调整 loss 类型，评估当前性能瓶颈是否主要来自：

- 类别不平衡 
- 难样本学习不足
- 监督信号过硬或过软

## 2.3 Stage T3：输入构造对照实验

在 T1/T2 确定的公共训练配置上，仅调整输入生成策略，评估：

- padding artifact 是否为主要干扰项
- 减少 padding 是否能直接带来收益
- 引入真实上下文是否有助于 `eye_occluded`
- 上下文增加是否会污染 `eye_open / eye_closed` 的局部判别

## 2.4 Stage T4：联合优化验证

在前述实验完成后，选取最优或次优的 loss 与输入策略组合进行联合实验，验证不同优化项之间是否存在正向叠加效应，并确定最终候选配置。

---

# 3 实验原则

所有正式对照实验需满足以下一致性要求：

- 使用同一版本数据集
- 使用同一 `split` 文件与 `seed`
- 使用同一 backbone（正式实验统一为 `MobileNetV2`）
- 使用同一优化器、学习率策略与训练轮数
- 使用同一评估代码与指标统计方式
- 除被比较变量外，其余训练与评估配置保持一致

所有实验统一输出以下结果：

- `Macro-F1`
- `Accuracy@1`
- `Macro-Precision`
- `Macro-Recall`
- 各类别 `Precision / Recall / F1`
- confusion matrix
- 训练日志与最终 checkpoint
- 量化后评估结果（若进入量化验证阶段）

其中，**Macro-F1 为主指标**，并重点关注：

- `eye_narrow` 的 Recall / F1
- `eye_occluded` 的 Recall / F1
- `eye_open` 的 Precision 是否显著下降
- confusion matrix 中关键误分类迁移方向是否改善

# 4 MobileNetV2 基线重建（Stage T1）

## 4.1 背景与必要性

原先实验是在旧 backbone 或旧训练配置基础上逐步开展的，但当前主干网络已切换为 **MobileNetV2**。尽管输入尺寸保持不变，以下机制已发生变化：

- 特征提取结构变化
- 激活分布变化
- BN 统计稳定性变化
- 对学习率、weight decay、EMA 的敏感性变化
- 对量化的鲁棒性变化

因此，原有实验中关于 loss 或输入构造方式的结论，不能直接平移到当前 V2 模型上。

正式结论必须建立在以下前提之上：

```text
MobileNetV2 已经在当前正式数据版本上完成稳定训练，并具备明确的 FP32 验证结果；
若量化链路尚未接通，则量化结果不作为本轮 T1 的阻塞前提，而作为后续补充 gate
```

## 4.2 T1 阶段控制变量

固定以下配置不变：

- 数据集版本
- split 文件
- seed
- backbone：`MobileNetV2`
- loss：`CrossEntropyLoss`
- 输入方案：使用**单一部署对齐输入基线**
- optimizer：`AdamW`
- scheduler：`CosineAnnealingLR`
- batch size：`1024`
- workers：`128`
- epoch：`100`
- input size：`128`
- lr_min：`1e-5`
- AMP：`on`
- 评估代码与指标统计逻辑

仅调整以下变量：

- learning rate
- weight decay
- EMA 开关
- 轻量数据增强开关

## 4.3 T1 推荐输入基线

由于部署侧不支持 `reflect / replicate padding`，且当前正式主线要求 Stage D 仅使用 `SquareCrop + OOB Const Padding`，T1 阶段固定采用下述部署对齐输入基线。

### 4.3.1 方案 T1：SquareCrop(1.0x) + OOB Const Padding

- 以眼框中心为中心
- 以 `max(w_bbox, h_bbox)` 为边长构造最小方形 crop
- 若 crop 越界，仅对越界区域使用 constant padding
- 该方案优先减少 padding 占比，同时保持输入更接近真实图像上下文

当前代码口径约束：

- Stage D 负责正式 ROI 生成，训练入口直接消费 `stage_d_roi_manifest.json` 对应的 ROI 图像
- 训练与评估侧不再引入 `reflect / replicate padding`
- 当前训练代码会对 ROI 做统一尺寸 resize 与 normalize；只要部署前处理采用同一 resize 规则，则本轮 T1 视为当前可执行的部署对齐基线
- 若后续确认部署侧 resize 规则不同，则需先补齐输入协议，再重跑 T1

## 4.4 T1 训练配置搜索范围

采用小规模网格搜索，扫以下变量。
### 4.4.1 学习率
- `1e-3`
- `2e-3`
- `3e-3`

### 4.4.2 weight decay
- `1e-5`
- `1e-4`
- `5e-4`
- `0`（仅 `lr=1e-3` 补充）

### 4.4.3 EMA
- `on`
- `off`

### 4.4.4 基础增强
T1 固定仅保留轻量增强：

- `RandomHorizontalFlip`
- 轻量 `ColorJitter`

暂不启用：

- Weighted CE

## 4.5 T1 结果选择原则

T1 阶段的结果选择分两层：

### 4.5.1 当前正式执行口径：FP32

当量化链路尚未接通时，本轮 T1 的正式选择标准先基于 FP32 结果完成。

- `Val Macro-F1`

- `Test Macro-F1`

1. `test_fp32/Test Macro-F1` 更高

3. `eye_open` Precision 不出现明显下滑

5. 训练过程收敛平滑、无明显不稳定现象

- `Quant Macro-F1`
- `Drop = FP32 Macro-F1 - Quant Macro-F1`

最终优先选择：

1. `Quant Macro-F1` 更高
2. `Drop` 更小
3. FP32 与量化结果均稳定
4. 训练过程收敛平滑、无明显不稳定现象

# 5 Loss 对照实验（Stage T2）

## 5.1 实验目标

验证当前性能瓶颈是否主要来自类别分布不均衡，并评估不同 loss 设计对小类识别能力的改善效果。

注意：

```text
Loss 对照实验必须建立在 T1 已完成、V2 训练基线已稳定 的前提下
```

## 5.2 控制变量

固定以下配置不变：

- 输入方案：使用 T1 确定的部署对齐输入基线
- backbone：`MobileNetV2`
- 数据增强、优化器、学习率策略、训练轮数与 batch size
- 数据集版本、split 文件与 seed

仅调整 loss 类型。

## 5.3 实验分组

### 5.3.1 A1 基线方案：CrossEntropyLoss

作为默认训练基线，用于衡量后续改动收益。

### 5.3.2 A2 类别加权交叉熵：Weighted CrossEntropyLoss

根据训练集类别频次设置权重，从**温和加权**开始，避免过强压制大类：

```text
weight_c ∝ α / sqrt(freq_c)
```

并加入裁剪约束：

```text
clip(weight_c, w_min, w_max)
```

其目标是缓解高频类别对整体梯度的主导作用，同时避免 `eye_open` 被过度压低。

### 5.3.3 A3 Focal Loss

采用 focal loss 抑制易分类样本对总损失的贡献，增强对难样本的学习能力。从较小 `gamma` 开始：

- `gamma = 0.5`

### 5.3.4 A4 Label Smoothing（可选）

用于验证当前问题是否与监督过硬、预测过置信相关。仅作辅助验证项，不作为主优化方向。

## 5.4 结果判定原则

- 若 `Weighted CE` 已显著提升 `eye_narrow` 与 `eye_occluded`，则说明当前主因包含明显的类别不平衡因素
- 若 `Weighted CE` 效果有限，而 `Focal Loss` 继续带来提升，则说明难样本学习不足也是主要因素
- 若 `Focal Loss` 提升小类 Recall，但显著降低大类 Precision，则说明其对边界模糊样本或噪声样本较敏感
- 若 `Label Smoothing` 明显恶化 `open / narrow / occluded` 边界，则说明当前问题不是“过置信”，而更接近“类别边界本身狭窄且模糊”

## 5.5 实验顺序

按以下顺序推进：

```text
CE -> Weighted CE -> Focal Loss -> Label Smoothing(optional)
```

# 6 输入构造对照实验（Stage T3）

## 6.1 实验目标

评估不同输入构造方式对分类性能的影响，重点分析：

- padding 是否引入伪特征
- 减少 padding 占比是否能直接提升性能
- 真实上下文是否有助于 `eye_occluded` 识别
- 输入构造方式是否影响 `eye_narrow` 与 `eye_open / eye_closed` 的边界区分

## 6.2 控制变量

固定以下配置不变：

- loss：使用 T2 中的最优方案；若尚未完成，则默认采用 `Weighted CE`
- backbone：`MobileNetV2`
- 优化器、学习率策略、训练轮数与评估方式保持一致
- 数据集版本、split 文件与 seed 保持一致
- padding 模式固定为 `OOB Const Padding`

仅调整 `SquareCrop` 的上下文比例 `k`。

## 6.3 实验设计原则

当前正式主线不再比较 `RectROI + ConstPad`。输入实验仅在 `SquareCrop + OOB Const Padding` 主线上比较不同 `k`，用于判断上下文比例对性能的影响。

### 6.3.1 第一步：固定最小方窗基线

- 使用 `SquareCrop(1.0x) + OOB ConstPad` 作为当前正式输入基线
- 该基线用于提供最小上下文、最小 OOB padding 和稳定的部署对齐实现

### 6.3.2 第二步：验证“增加上下文”是否有效

在 `SquareCrop(1.0x)` 基础上继续放大 crop 尺度：

- `k = 1.4`
- `k = 1.8`
- `k = 2.2`

该对比用于判断：

- `eye_occluded` 是否确实依赖更大范围的真实上下文
- crop 过大是否会引入背景噪声并污染 `open/closed` 判别

## 6.4 实验分组

### 6.4.1 B1 基线方案：SquareCrop(1.0x) + OOB constant padding

以眼框中心为中心，从原图裁取最小包围方形区域：

```text
crop_size = 1.0 * max(w_bbox, h_bbox)
```

若 crop 越界，则仅对越界区域使用 constant padding。

优点：

- 尽量减少人工 padding
- 降低 aspect ratio shortcut
- 输入更接近真实原图分布
- 变量更干净，可单独检验“方形化/减 padding”的收益

缺点：

- 若中心点不稳，可能导致眼部位置偏移
- 对大 yaw 或遮挡样本可能仍不够大

### 6.4.2 B2 候选优化方案：SquareCrop(1.4x)

```text
crop_size = 1.4 * max(w_bbox, h_bbox)
```

用于引入适度上下文，重点观察：

- `eye_occluded` 是否提升
- `eye_narrow` 是否更易与 `open/closed` 分离

### 6.4.3 B3 候选优化方案：SquareCrop(1.8x)

```text
crop_size = 1.8 * max(w_bbox, h_bbox)
```

用于引入中等范围上下文，重点验证真实上下文是否为 `occluded` 判别的关键因素。

### 6.4.4 B4 候选优化方案：SquareCrop(2.2x)

```text
crop_size = 2.2 * max(w_bbox, h_bbox)
```

用于验证更大上下文是否继续带来收益，或是否因背景噪声过大而导致性能下降。

## 6.5 结果判定原则

- 若 `SquareCrop(1.4x / 1.8x)` 继续提升 `eye_occluded`，说明真实上下文是关键判别信息
- 若 crop 尺度继续增大后 `eye_open / eye_closed` 性能显著下降，说明背景噪声已超过上下文收益
- 若 `eye_narrow` 提升有限，则说明该类瓶颈更可能来自：
  - 类别定义边界连续
  - 标注标准不够硬
  - 局部判别特征本身弱于预期

## 6.6 实验顺序

按以下顺序推进：

```text
SquareCrop_1.0x -> SquareCrop_1.4x -> SquareCrop_1.8x -> SquareCrop_2.2x
```

其中：

- `SquareCrop_1.0x` 作为当前正式输入基线
- `1.4x / 1.8x / 2.2x` 用于评估“加上下文”效应

# 7 联合实验设计（Stage T4）

在 Loss 对照实验与输入构造对照实验分别完成后，再进行联合优化验证。

建议评估以下组合：

- `CE + SquareCrop(1.0x)`：当前正式基线
- `Weighted CE + SquareCrop(1.0x)`：类别平衡基线
- `Weighted CE + SquareCrop(k)`：输入优化方案
- `Focal + SquareCrop(k)`：难样本强化方案（仅在 T2 结果支持时保留）

联合实验的目标是：

1. 确定最终候选配置
2. 验证各优化项之间是否存在正向叠加效应
3. 观察量化后是否仍能保留收益
4. 在最终收敛阶段关闭强数据增强，避免联合收益被增强噪声掩盖

### 8.1.1 历史实验1分析

- Weighted CE 权重过强
  - 它把 `open` 压得太低，导致大量 `open -> narrow`
- Focal 过度关注边界模糊样本
  - `narrow` 这种中间类天然噪声更大，focal 在认真学习这些“坏硬样本”
- 并不是单纯“小类召回不足”
  - 类别不平衡
  - `narrow` 边界模糊
  - `occluded` 可能需要上下文

### 8.1.2 历史实验1结论

- loss 设计可以影响小类召回，但过强权重或过强 hard sample 强化都会破坏大类与中间类边界
- 后续若继续使用 Weighted CE，应限制权重范围
- 后续若继续验证 Focal，应从更小 `gamma` 开始

### 8.2.1 历史实验2分析

#### 8.2.1.1 A5 相对 A4：有效且方向正确的改进

- 总体指标同步提升
  - 并不是靠牺牲整体准确率来换小类指标
- `narrow` 小幅改善
  - 不只是类别频次低导致的召回不足，更可能包含定义模糊、边界连续问题
- `occluded` 提升最明显
  - 减少了 `occluded` 被大类 `open` 吸走的现象
  - 命中真实偏差：大类先验压制小类判别
- `open` 没有明显塌陷

#### 8.2.1.2 A6 相对 A4：难样本强化不是当前主导矛盾

- `narrow -> closed`：**291(A4) → 345(A6)**，显著恶化
- `open -> narrow`：**276(A4) → 309(A6)**，也在恶化

这通常说明：

> focal loss 仍在放大边界模糊样本、噪声样本或天然中间态样本的影响，使决策边界更“紧张”，但没有真正改善类间可分性。

推断：

- 当前任务的主导矛盾**不是 easy/hard sample 不平衡**
- `narrow` 并不是一个适合通过 focal 强化学习的“纯 hard class”
- 相反，它更像一个**语义中间态类别**，天然分布更宽、边界更模糊

#### 8.2.1.3 A7 相对 A4：过置信不是当前主导矛盾

- `open -> narrow`：**276(A4) → 390(A7)**，显著恶化
- `narrow -> closed`：**291(A4) → 318(A7)**，也较差

说明 label smoothing 在当前任务中的副作用大于收益。机制上更像：

> 当前类别边界本来就不够硬，尤其 `narrow` 处于多类之间的连续变化带；label smoothing 进一步削弱了监督信号，导致模型对 `open / narrow / occluded` 的边界更不敏感。

判断：

- 当前模型瓶颈不是“预测过于自信”
- 也不是“校准差导致泛化差”
- 而更像是**类间边界本来就窄，小类又容易被大类吸走**

### 8.2.2 历史实验2结论

- `occluded` 可以通过温和类别加权修正一部分
- `narrow` 改善有限，说明其瓶颈更可能来自：
  - 类别定义边界模糊
  - 输入信息不足
  - 表征质量不足
- 后续重点应转向：
  - 部署对齐输入方案
  - 减少 padding
  - 引入真实上下文
  - 重新在 V2 稳定基线上验证结论

# 9 当前主要判断

基于已有历史实验与当前部署约束，现阶段判断如下：

1. **MobileNetV2 的训练基线必须先重建**
   - 否则 loss / 输入实验的结论会混入 backbone 训练未调稳的因素

2. **当前主导矛盾不只是类别不平衡**
   - `occluded` 部分受类别先验压制影响
   - `narrow` 更像语义中间态类别，边界天然模糊

3. **Focal 与 Label Smoothing 目前都不是优先优化方向**
   - 它们更容易放大边界模糊带来的副作用

4. **后续重点应转向输入构造**
   - 减少 padding
   - 去除 aspect ratio shortcut
   - 评估真实上下文对 `occluded` 的帮助
   - 验证大上下文是否会污染 `open/closed`

# 11 结论

当前实验文档已更新为以下统一路线：

1. **先做 MobileNetV2 基线重建**
2. **再做 Loss 单变量对照**
3. **再做输入构造单变量对照**
4. **最后做联合验证**
5. **历史结果仅保留为趋势参考，不作为当前正式结论**

该更新后的实验路线能更好地满足以下目标：

- 与部署约束保持一致
- 控制变量更干净
- 结论更可归因
- 量化后结果更具工程意义
- 后续版本间更易复现与比较
