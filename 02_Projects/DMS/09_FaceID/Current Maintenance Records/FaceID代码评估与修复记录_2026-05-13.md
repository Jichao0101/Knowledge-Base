# 1 Summary

本次对照 `A核FaceID功能需求流程文档` 完成静态评估，并修复可直接在代码仓内验证的问题：

- `FaceIdStorage` 从空实现改为本地二进制特征库读写，支持保存、加载、查询、删除指定 ID、删除全部 ID。
- 录入流程支持保存新 Face ID，并在同一人重复录入时复用已有 ID。
- 登录流程不再仅信任模型 `faceName`，改为使用当前特征与本地 Face ID 特征库比对。
- 解绑流程改为使用 `VCU2FaceId` 指定目标特征，比对通过后只返回解绑成功，不删除本地特征。
- 恢复出厂设置删除全部本地 FaceID 数据，并重置下一次生成 ID。
- 删除、check、恢复出厂设置等命令型流程不再依赖当前帧 `AtomicResult`。
- 新增 `face_id_algorithm_test` 专项单元测试目标，保留伪输入单测在代码仓。

# 3 Residual Items

- 第 9 节提到关键步骤之间重复执行 `JudgeState()`。当前代码仍是每次 `Process()` 入口判断一次；如果 R 核信号会在同一次 `Process()` 执行中异步改变，需要后续引入明确的最新信号读取机制。
- `FaceIdStorage::Unbind` 保留为旧接口，但当前算法解绑路径不再调用该接口，避免把“解绑”误实现为按任意特征匹配。
- `face_id_params.json` 的 `feature_file` 当前是相对路径；运行环境需保证工作目录或配置路径符合部署预期。
