# 1 Summary

本轮修正重点：

- 顶层 `CMakeLists.txt` 在 `ELSEIF(J6M_X86_VERSION)` 分支打开 `add_subdirectory(test)`，让 `scripts/run_j6m_x86.sh` 的本地仿真配置直接进入测试目录。
- 撤回根目录下为 FaceID 单独创建测试目标的做法，避免绕开仓库既有 `gTestsdk` 单元测试入口。
- `test/CMakeLists.txt` 保持 `gTestsdk` 为统一测试目标；FaceID 单测通过原有 `aux_source_directory(.)` 纳入。
- `test/CMakeLists.txt` 给 `gTestsdk` 增加 `DMS_SOURCE_DIR`，用于定位仓库内测试数据目录。
- J6M_X86 下给 `gTestsdk` 增加 `-no-pie` 链接参数，原因是当前 `thirdparty/third_party_j6/lib_x86/libgtest.a` 是非 PIE 静态库。
- 删除 `FACE_ID_ALGORITHM_TEST` 方式暴露的算法私有测试辅助接口，单测改为通过公开输出、后续命令行为和存储状态验证。
- FaceID 单测存储从 `/tmp` 移到 `test/face_id_algorithm_storage/`，目录内保留 `README.md` 说明运行时生成和清理的文件。
- 增加状态切换相关注释，覆盖 J6M_X86 测试入口、取消命令匹配、关键步骤重检、解绑不删除本地特征、业务失败仍返回框架 `SUCCESS`、best match 选择逻辑。
- FaceID 匹配逻辑保持现有 loss 计算和阈值语义，只把“第一个低于阈值的 ID”优化为“阈值内 loss 最小的 ID”。

# 3 Current Decision

FaceID 单测应按仓库既有方式进入 `gTestsdk`，不应通过根目录单独 target 绕开 SDK 依赖。

原因：

- 其它模块单测也是通过 `gTestsdk` 依赖 SDK 和模块库实现。
- FaceID 单测要验证的是算法在现有工程结构中的行为，不是孤立编译单元。
- 单开 target 可以临时定位问题，但不应作为最终 CMake 入口。

# 4 Residual Items

- 需要先修复 J6M_X86 全 SDK 构建阻塞项，才能用 `gTestsdk --gtest_filter='FaceIdAlgorithmTest.*'` 完成最终闭环验证。
- `scripts/run_j6m_x86.sh` 的 protobuf 生成副作用需要纳入后续验证流程管理，避免生成物污染本次 FaceID 代码 diff。
- FaceID 测试运行时会在 `test/face_id_algorithm_storage/` 下短暂生成 `.bin` 和 `.tmp` 文件；测试结束应清理，仅保留 `README.md`。
