## 0.1 Task

- task_type: `bug_fix.design_mismatch`
- defect: 多目标跟踪实现与方案文档在生命周期衰减、body 重建清理、hand 关联机制和 hand 输出契约上不一致

## 0.2 Expected vs Actual

### 0.2.1 Expected

- body / face / hand 生命周期满足 `match -> hit++ capped, miss=0`，`miss -> hit-- to 0, miss++`
- body 以新 id 重建时，旧 body 绑定的 face / hand 状态立即清理，并基于新 body 重建
- hand 按每个 body 维护 `left/right` 两个槽位，左右手轨迹继承 body `trackId`
- hand 使用 `预测 + 损失矩阵 + 匈牙利` 做一对一关联，并保证左右手唯一
- 输出层直接暴露 `leftHandMap` / `rightHandMap`，不再组装单一 `handMap`

### 0.2.2 Actual

- body / face / hand 的 miss 衰减未统一按规范执行
- body 删除前，旧 face / hand 仍可能在旧 id 下继续存在
- hand 仍使用贪心式逐 body/逐侧匹配，且 trackId 不继承 body id
- 输出层仍尝试把左右手合并进统一 `handMap`，与左右手同 bodyId 设计冲突

## 0.3 Root Cause

1. `track.cpp` 中 body / face / hand 生命周期更新规则分别演化，miss 衰减未统一遵循方案文档。
2. hand 内部状态以独立 hand track map 建模，导致“每个 body 维护 left/right 槽位并继承 bodyId”的设计未落实。
3. hand 初始化与匹配未采用统一的扩展损失矩阵 + 匈牙利流程，而是混用局部先验和贪心选择。
4. output / proto 层仍以单一 `m_handTrackResultMap` 为契约，与左右手同 bodyId 的目标输出不兼容。

## 0.4 Code Changes

- 在 `source/utils/track.cpp` 中引入统一的 `AdvanceHit` / `AdvanceMiss` 规则，使 body / face / hand 都满足设计要求
- 在 `include/utils/track.h` 与 `source/utils/track.cpp` 中将 hand 状态改为 `m_bodyHandTracks[bodyId].left/right`
- hand 匹配改为：
  - 先预测左右手轨迹
  - 对 body 局部 hand 候选构建损失矩阵
  - 以匈牙利算法完成左右手一对一分配
  - 左右手输出 key 直接使用 body `trackId`
- 修正 hand 初始几何先验，保证 left/right 首次分槽与 body 中线方向一致
- body 衰减到删除或不再进入当前 body 输出时，立即清理旧 face / hand 状态，避免旧 id 自维持
- 在 `include/fuse_algos/serialize_result.h`、`source/fuse_algos/serialize_result.cpp`、`source/fuse_algos/fuse_algorithm.cpp` 中移除 hand 合并路径，改为直接输出：
  - `m_leftHandTrackResultMap`
  - `m_rightHandTrackResultMap`
- 修改 `prebuild/tools/sdk_output.proto`，新增 left / right hand map 字段，并通过正常编译流程重生成 protobuf 代码
