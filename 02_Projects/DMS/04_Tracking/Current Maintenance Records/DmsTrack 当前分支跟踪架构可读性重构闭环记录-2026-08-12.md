## 1. 背景与事实基线

当前会被合入主分支的真实修改是 `feat/ljc/track_0812` 的提交 `244e5300 Refactor DmsTrack phase readability`。本轮目标是先降低 Tracking 架构的阅读成本，为后续处理“主驾 body 消失后误跟副驾”和“同一只手反复归为左/右手”建立可维护边界；不得借重构修改现有跟踪行为。

头部跟踪已经稳定并经过量产车型验证，因此 Face phase 只允许可读性优化，不能改变匹配、门禁、生命周期或输出语义。

## 2. 已落地的结构重构

- Face：把检测按类别收集、assignment loss 构造抽为 `.cpp` anonymous namespace 的纯计算 helper；Face 主流程仍负责状态更新与输出。
- Body：把 track-box loss、已有 body 预测匹配、face-anchor body 选择抽为无状态 helper；删除仅包一层调用的 `computeMatchLoss` member，未改变 owner 遍历、fallback 或发布规则。
- Hand：`updateHandTracks` 保留预测与阶段编排，将复杂逻辑拆为 `updateOwnedHandSlots`、`recoverUnmatchedHandSlots`、`cleanupOrphanAndExpiredHandSlots`、`publishHandSlots` 四个 private 子阶段。
- 接口：`DmsTrack::Init/Update` 与四类 legacy result map 不变；没有引入 View、Payload、Context、Row、Result 等新的稳定中间类型。

## 3. 注释治理

对仅凭函数名无法恢复具体计算逻辑的 helper 补充了简短中文注释，包括归一化中心距离、Face/Body 几何关系、加权 loss、dummy/forbidden assignment、输出 sanitize、miss 生命周期和 Hand owner/slot 清理语义。注释解释“为什么这样算或有什么边界”，不逐行复述代码。

## 4. 明确保留的当前行为

- `Update` 每帧依次执行 Face、driver selection、Body、Hand，没有 2m/5m profile gate。
- Body 先处理 selected driver face，再处理其他 active face owner；已有 track 匹配失败时仍允许 face-anchor acquisition/reselection，稳定非 driver body 也可能发布。
- Hand 从 `curResult->m_bodyTrackResultMap` 读取 stable DRIVER body evidence，未匹配恢复阶段仍可能回退内部 `m_bodyTracks`。
- 本轮未处理主驾 body 消失后误跟副驾、同一只手左右槽反复归属等行为缺陷。

6 月维护记录中的 profile gate、selected-driver-only Body 和 body-to-hand finalized snapshot 属于历史分支方案，没有进入本次待合入提交；相关记录继续保留供追溯。

## 5. 验证与边界

- `git diff --check` 通过；提交后工作区另有一处把 Face loss 注释澄清为“二倍尺寸连续性损失”的未提交文本修改，不改变代码行为或本记录的架构结论。
- 最终注释补充前的同一结构重构版本执行 `bash scripts/compile_j6b.sh`，达到 `[100%] Built target sdk`。
- 最终 clean-commit 的两次全量重跑均被中断，因此不把它记录为一次完整通过。
- 未执行 runtime replay、新增单元测试、代表性视频或板端验证；本记录只关闭结构重构与知识同步，不关闭功能问题。

## 6. Current 同步结论

Tracking 五份 current 文档已以 `244e5300` 重新基线化；DMS 项目总览和知识库结构审计同步更新。默认入口、恢复顺序和 `recoverability_status: partial` 不变，也未声明 `single_pass_recoverable: true`。

## 7. 2026-08-12 追加更正：face-first 口径与流程完整性

本记录原有结论继续有效，但 current 的架构名称统一更正为 `face-first`：Face 先完成 identity/id、匹配、人员类型稳定化和唯一 DRIVER 选择；Body 随后绑定 active Face；Hand 最后绑定 stable DRIVER Body。不得把 Body 对 Hand 和 HumanPose 的重要性误写为 body-first，也不得把历史文档中的 head-first 文件名当作当前规范术语。

同时补强 `tracking_design_current` 与 `tracking_implementation_current`，使其覆盖 Face 损失矩阵及公式、CV 卡尔曼预测/修正、人员类型投票、DRIVER Face 过滤评分、Body tracking/acquisition、Hand first/second pass、miss/cleanup/publish 的完整代码对应流程。
