# 1 DmsTrack 匹配、状态、清理、输出分层优化实施前方案

## 1.1 背景

当前架构的主要问题不是 stage 数量，而是短期匹配层、长期状态层、清理层和输出层被摊平成同一层级：

- `AssignmentResult` 泄漏到长期状态和输出相关函数签名。
- `publishAllowedHandSlots` 层级过高，同时做 sanitize、matched 判断、miss 推进和 output map 写入。
- cleanup 顺序属于长期状态边界，但夹在 apply 和 publish 之间，语义不够清楚。
- 已取消 `AssignmentPolicyMatrix` 的方向保留：edge evaluator 和 rejection reason 属于 solver 内部机制，不回退。

## 1.2 分层目标

目标分层：

```text
short-term matching:
  SolveAssignment / AssignmentResult，只在 match/apply 局部链路内存在

long-term state apply:
  修改 m_faceTracks / m_bodyTracks / m_handTracks
  输出领域事实，如 matched owner / matched hand slot

state finalize:
  cleanup / sanitize / lifecycle boundary
  可以调用 PrepareTrackForOutput，也可以在 sanitize fail 时 AdvanceMiss

projection:
  生成 FrameBodyView / FrameHandView
  frame view 不是 authoritative state

publish:
  pure output write，只写 curResult maps
```

## 1.3 具体方案

### 1.3.1 Body

保留 body 阶段外部顺序：

```text
collect detections / owners
predictBodyTracks
matchAndApplyBodyDetections -> matchedOwnerFaces
advanceAndRetireBodyTracks
prepareBodyTracksForOutput
publishBodyTracks
```

`AssignmentResult` 只在 body match/apply 内部存在，不进入 cleanup、finalize、publish。

### 1.3.2 Hand

新增领域 key：

```cpp
using HandSlotKey = std::pair<track_id, InstanceType>;
```

只允许 `InstanceType::LEFT_HAND` / `InstanceType::RIGHT_HAND`。

Hand 阶段目标顺序：

```text
collect hand detections
allowedOwners = collectAllowedHandOwners(bodyOutputView)
predictInitializedHandSlots
matchedHandSlots = matchAndApplyHandDetections(...)
cleanupRetiredOwnerHandSlots
resetExpiredHandSlots
eraseEmptyHandOwnerStates
handOutputView = prepareHandTracksForOutput(..., matchedHandSlots, frameSize)
publishHandTracks(handOutputView)
cleanupRetiredBodyAnchors
```

`AssignmentResult` 不进入 cleanup / prepare / publish；`prepareHandTracksForOutput` 使用 `HandSlotKey` 判断 sanitize fail 是否来自本帧 matched slot。

### 1.3.3 Output layer

- `prepareHandTracksForOutput`：finalize + projection，允许 `PrepareTrackForOutput` 和 sanitize fail `AdvanceMiss`。
- `publishHandTracks`：pure publish，只写 `curResult->m_leftHandTrackResultMap` / `m_rightHandTrackResultMap`。
- `publishBodyTracks` 保持 pure publish。

### 1.3.4 cleanupRetiredBodyAnchors

当前语义只清理 `m_retiredBodyTracks` 中不再被 body/face/hand 引用的长期 retired anchor，不影响本帧 hand output，因此放在 publish 后作为尾部 GC 可接受。若后续发现它会清 hand/body state，则必须前移到 prepare 前。

## 1.4 不变边界

- 不修改 `hungarian()`。
- 不修改 `SolveAssignment` 的 strict `< rejectCost` 语义。
- 不回退 edge evaluator 方向。
- 不修改 body/hand output key。
- 不修改 left-before-right slot 顺序。
- `FrameBodyView` 仍是单帧只读 body projection，不是第二套 body state。
