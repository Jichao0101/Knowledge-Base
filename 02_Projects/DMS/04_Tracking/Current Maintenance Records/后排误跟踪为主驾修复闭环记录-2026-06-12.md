# 后排误跟踪为主驾修复闭环记录

## Retrieval Summary

- topic: 2m 回灌中主驾遮挡后后排 face/head 被误选为主驾。
- anchors: `stable=BACK_PASSENGER`, `FaceSmallerThanReferenceLoss`, `FaceLargerThanReferenceGain`, `driver_face_anchor`, `face-first driver face select`。
- fix: driver face 选择拒绝稳定 BACK_PASSENGER 候选，并将 size continuity 拆成变小惩罚与变大增益。
- validation: 二次修复后板端日志中 `face=1` 被选为 driver 为 0 次，后排候选被 stable BACK 规则拒绝。
- boundary: 结论只覆盖本次 2m 回灌样本，不代表所有车型、姿态和遮挡序列完成代表性验收。

## 1 问题

2m 回灌中，15:53 左右主驾捂脸导致主驾 face 未被检测到，后排头部移动到 driver ROI 附近后被误匹配为主驾。随后后排因为连续性 loss 更小被持续跟踪为主驾，直到后排头部偏转未检出后主驾才恢复。

## 2 根因

本次日志显示，原 driver face 选择过度依赖对称 size continuity。后排小脸一旦接管当前 driver face reference，后续匹配会把“后排自身的连续性”当作 driver 连续性；真实主驾恢复时脸变大反而触发原 `size_loss > 0.70` 拒绝，导致恢复失败。

第一轮修复后，板端日志仍发现 2 次 `face=1` 被选为 driver，其中一次前文为 `stable=BACK_PASSENGER`。原因是当时只拒绝 `stable=BACK_PASSENGER && instant != DRIVER`，后排探头瞬时落入 driver ROI 时可被算作 `instant=DRIVER` 并绕过拒绝。

## 3 修复

- driver face 选择中拒绝 `stablePersonType == BACK_PASSENGER` 的候选，不再允许其因单帧 `instant=DRIVER` 进入主驾选择。
- 将原对称 size continuity 拆为：
  - `FaceSmallerThanReferenceLoss`：候选比 driver reference 变小时强惩罚，超过阈值拒绝。
  - `FaceLargerThanReferenceGain`：候选比 reference 变大时作为增益，支持主驾遮挡后恢复。
- 新增配置化 `driver_face_anchor`，包含 anchor 点和三个权重，不在代码里写死 preferred anchor。
- 未收紧 `distanceLoss` 或 face match distance gate，避免主驾转头恢复时因 KF 预测和观测距离较大被误拒。

结论：本次回灌样本中，后排 face/head 不再被选为主驾；主驾选择稳定落在 `face=0`。

## 5 残余风险

- 本结论是本次 2m 回灌样本级闭环，不代表所有车型、所有后排探头姿态和所有遮挡序列已完成代表性验收。
- `stable=BACK_PASSENGER` 一律不能直接作为 driver face 候选；若未来出现真实主驾轨迹被稳定投成 BACK 的样本，需要先改善 person type 投票或新增更强 evidence，而不是放开 BACK 稳态候选。
- anchor 坐标和权重已配置化，但仍需要更多样本调参验证。
