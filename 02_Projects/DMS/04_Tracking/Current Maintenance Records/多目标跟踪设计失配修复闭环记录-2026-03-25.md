- anchors: `AtomicResult`, `m_bodyTrackResultMap`, `m_faceTrackResultMap`, `m_leftHandTrackResultMap`, `m_rightHandTrackResultMap`, `InstanceType`。
- fix: 恢复 body/face/leftHand/rightHand 为上游事实源，下游 handpose、humanpose、visualizer、handoff 和 fuse export 按新边界适配。
- validation: `bash scripts/compile_j6b.sh` 编译通过，独立 review 完成。
- boundary: 未包含代表性帧集 runtime smoke test，仓外消费者对 `InstanceType` 的整数契约仍需联调确认。

## 0.1 Task

- task_type: `bug_fix.design_mismatch`
- defect: 上游 tracking 接口被下游使用方式反向塑形，导致接口与设计边界不一致，且 body/hand 输出链路在下游不可见

## 0.2 Expected vs Actual

### 0.2.1 Expected

- 上游 `AtomicResult` 以 `m_bodyTrackResultMap`、`m_faceTrackResultMap`、`m_leftHandTrackResultMap`、`m_rightHandTrackResultMap` 为权威接口
- body / head / hand 跟踪结果都能进入下游消费链路
- 下游需要的兼容结构仅在导出层适配，不反向污染上游

### 0.2.2 Actual

- body/human 语义被下游 `m_humanTrackResultMap` 反向牵引
- hand 相关消费链路仍依赖统一 `m_handTrackResultMap` 与不存在/不稳定的下游类型概念
- 结果表现为 head 可见，但 body/hand 框未在下游闭环显示

## 0.3 Root Cause

1. `AtomicResult` 的上游接口与设计方案不一致，body 结果被要求兼容成 human 语义，hand 输出也未按左右手拆分后的事实源被消费。
2. `track.cpp`、`handoff`、`handpose`、`humanpose`、`visualizer`、`sdk export` 对 tracking 结果的读取边界不一致，出现“上游一种结构、下游另一种假设”的断裂。
3. `m_handPoseResultMap` 依赖不存在的 `ClassType` 概念，进一步放大了接口失配。

## 0.4 Code Changes

- 保持上游 `AtomicResult` 以 `body/face/leftHand/rightHand` 为事实源，不回补 `humanMap`、不引入 `clsType`
- 在 `source/utils/track.cpp` 中让 tracking 结果分别写入：
  - `m_bodyTrackResultMap`
  - `m_faceTrackResultMap`
  - `m_leftHandTrackResultMap`
  - `m_rightHandTrackResultMap`
- 在 `source/models/handpose_model.cpp` 中分别读取左右手 map，并将 hand pose 结果按 `InstanceType` 写回
- 在 `source/models/humanpose_model.cpp` 中改为直接读取 `m_bodyTrackResultMap`
- 在 `source/utils/visualizer.cpp` 和 `include/utils/visualizer.h` 中移除对下游 `ClassType` 的依赖，统一按 `InstanceType` 渲染
- 在 `source/fuse_algos/handoff_algorithm.cpp` 和 `include/fuse_algos/handoff_algorithm.h` 中改为直接消费 body / leftHand / rightHand
- 在 `source/fuse_algos/fuse_algorithm.cpp` 中仅于导出层做兼容：
  - `bodyTrackResultMap -> m_humanTrackResultMap`
  - `left/rightHandTrackResultMap -> m_handTrackResultMap`
