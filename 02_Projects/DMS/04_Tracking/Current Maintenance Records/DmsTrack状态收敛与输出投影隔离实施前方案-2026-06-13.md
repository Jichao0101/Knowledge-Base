# 1 DmsTrack 状态收敛与输出投影隔离实施前方案

## 1.1 背景

当前 DmsTrack 已完成 assignment / policy / solver 语义统一，但仍存在结构性复杂度：

- `curResult->m_bodyTrackResultMap` 既作为 legacy output，又作为 hand 阶段输入。
- `prepare*ForOutput` 名义上接近输出层，但仍会 sanitize 内部状态并在失败时推进 miss。
- `allowedHandOwners`、`HandPublishEligibility` 等帧内派生状态与内部 state / output map 混用。
- `body` 命名为团队和下游既有概念，不能通过重命名消除语义复杂度。

## 1.2 设计约束

- 不改变 `DmsTrack::Init/Update` public API。
- 不改变 `AtomicResult` 四类 legacy output map。
- 不改变 `hungarian()` 实现。
- 不改变 face/body/hand assignment 行列方向。
- 不改变 strict `< dummyLoss` 拒绝语义。
- 不改变 face -> body -> hand 高层依赖。
- 不引入解释层、debug layer 或新的外部架构对象。
- 保留 `body` 命名，但内部契约明确：body 是 full-person detection evidence / search envelope，不是 identity owner。

## 1.3 权威状态模型

目标状态模型：

```text
m_faceTracks       = identity truth
m_bodyTracks       = body evidence truth
m_handTracks       = hand evidence truth
m_retiredBodyTracks = cleanup anchor truth
curResult maps     = pure output projection
FrameBodyView      = one-frame, read-only projection, not state
```

## 1.4 最小侵入式设计

引入单帧只读 body 输出视图：

```cpp
struct FrameBodyView {
    track_id ownerFaceId;
    TrackInfo body;
};
```

硬约束：

- 只在单帧 `Update()` 调用栈内存在。
- 不作为 `DmsTrack` member。
- 不跨帧缓存。
- hand 阶段只读消费。
- 不允许写回 `m_bodyTracks`。
- 内容必须等价于当前会写入 `curResult->m_bodyTrackResultMap` 且 hand 可见的 body 输出。

目标数据流：

```text
updateBodyTracks
  -> update m_bodyTracks
  -> finalize body lifecycle/sanitize
  -> produce FrameBodyView
  -> project FrameBodyView to curResult->m_bodyTrackResultMap

updateHandTracks
  -> consume FrameBodyView
  -> update m_handTracks
  -> project hand outputs
```

## 1.5 实施步骤

1. 引入 `FrameBodyView`，由 body finalize / publish 边界生成。
2. 修改 hand 阶段 body 输入：
   - `collectAllowedHandOwners`
   - `buildHandSlots`
   - `cleanupRetiredOwnerHandSlots`
   - `publishAllowedHandSlots`
3. 确保 hand 阶段不再读取 `curResult->m_bodyTrackResultMap`。
4. 保持 `curResult->m_bodyTrackResultMap` 写入结果与旧行为一致。
5. 清理本次修改造成的废弃参数、函数签名和无用中间状态。

## 1.6 验证要求

最低验证门禁：

- `git diff --check`
- `bash scripts/compile_j6b.sh`

静态检查重点：

- `curResult->m_bodyTrackResultMap` 不再作为 hand 内部输入。
- `FrameBodyView` 不作为 member，不跨帧保存。
- hand 阶段只读消费 `FrameBodyView`。
- `curResult` 仍只承担 legacy output map 写入。

## 1.7 风险边界

- 当前方案不声明 runtime replay 等价。
- 当前方案不声明板端验证通过。
- sanitize 失败 miss、retired body cleanup、left-before-right slot 顺序均为高风险行为边界，实施时不得改变。
