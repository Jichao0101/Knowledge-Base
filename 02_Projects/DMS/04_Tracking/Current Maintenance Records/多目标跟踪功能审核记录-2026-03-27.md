## 0.3 Acceptance Items

1. `body` 使用 KF + Hungarian + 生命周期管理
2. `face` 使用 KF + 生命周期管理
3. `hand` 使用匀加速 KF，且更新位置与尺度
4. `body`/`face`/`hand` 都按 `hitCount` / `missCount` 阈值输出与删除
5. `face` 仅在稳定 `body` 后启动，且轨迹 `trackId` 继承 `body`
6. `hand` 仅在稳定 `body` 后启动，且轨迹 `trackId` 继承 `body`
7. `face` 在启动后与 `body` 存在解耦，`body` 暂失时可继续存在
8. `hand` 在启动后与 `body` 存在解耦，`body` 暂失时可继续存在
9. `body` 支持驾驶员 / 副驾 / 后排的长期稳定属性判定
10. 驾驶员 `body` 最终输出唯一
11. `face` 在同一乘员区域最终输出唯一
12. `left_hand` / `right_hand` 在同一乘员区域最终输出各自唯一
13. 双手可区分左右手
14. 对“短时漏检、局部遮挡、检测抖动下较好的 ID 连续性”有充分实现证据

## 0.5 Key Findings

1. `face` / `left_hand` / `right_hand` 的输出唯一化未真正闭环。虽然每个当前稳定 `body` 会先选一个最佳候选，但随后又将其余稳定候选直接透传到输出，不能满足“同一乘员区域仅保留一个最终输出”的设计要求。
2. `face` 和 `hand` 的“启动依赖 body、运行后可解耦”在代码中已实现，旧审核记录中对此项的“不满足”判定与当前代码不符。
3. `hand` 删除粒度已经细化到左右手槽位，旧审核记录中关于“删除粒度不符合规范”的结论与当前代码不符。
4. 对效果性目标“较好的 ID 连续性”，目前只能确认机制存在，不能把静态实现直接当成验收通过。
