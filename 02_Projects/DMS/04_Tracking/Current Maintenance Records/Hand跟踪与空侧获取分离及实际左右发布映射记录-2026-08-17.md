## 1 问题与原因

日志锚点从 `FrameTimestamp: 10700000` 开始：同一只手 detection 仍存在，但 Hand 输出短时消失，随后在另一侧重新建立。旧实现把已初始化 Hand track 与未初始化 left/right acquisition row 放进同一个 Hungarian 竞争矩阵；空侧使用幅度更小的 `HandAnchorLoss`，可能抢走本应由已有轨迹以 `HandMatchLoss` 延续的 detection。因此问题不是 detection 幅度过大导致 tracking 必然失败，而是 tracking 与 acquisition 没有形成先后边界。

此外，旧内部 left/right 由图像横坐标定义，而外部结果需要表达驾驶员实际左右手。直接反转内部侧别会同时影响 anchor、连续跟踪和生命周期状态，因此将转换限制在发布边界。

## 2 代码变更

### 2.1 `04da47b8 Separate Hand tracking from slot acquisition`

- `trackExistingHands` 只收集同一继承 `trackId` 下已初始化 Hand track。
- tracking assignment row 表示已有轨迹，真实边统一使用 `HandMatchLoss`；命中推进 hit，未命中直接推进 miss。
- `acquireEmptyHandSlots` 只处理尚未初始化的图像侧，并只消费 tracking 后剩余的 detection；真实边使用 `HandAnchorLoss`。
- 删除 `HandSlotKey`、`matchedSlots`、`updateOwnedHandSlots` 和 `recoverUnmatchedHandSlots`，不再保留旧的 unmatched recovery/Internal Body fallback。
- Body 只提供同一继承 id 下的候选域；Hand 不创建或迁移 identity id。

### 2.2 `13efd826 Map image-side Hands to physical sides`

- 内部 `m_handTracks.left/right`、预测、matching、acquisition 与 cleanup 保持图像坐标侧语义。
- `publishHands` 将 image-left 发布到 `m_rightHandTrackResultMap`，并把输出副本的 `instanceType` 设置为 `RIGHT_HAND`。
- image-right 发布到 `m_leftHandTrackResultMap`，并把输出副本的 `instanceType` 设置为 `LEFT_HAND`。
- 正常发布和 fallback 发布使用相同映射；输出 key 仍是继承 `trackId`。
- `PublishSanitizedTrack` 继续作用于内部轨迹，保留 sanitize 失败时推进 miss 的既有行为；只在成功发布后修正 map 中的输出副本类型。

## 3 接口与生命周期边界

- `DmsTrack::Init/Update` public API 不变。
- `AtomicResult` 的 body/face/leftHand/rightHand 四类 legacy map ABI 不变。
- Face-first identity 主线不变；Body 删除时级联删除同 id Hand 的生命周期契约不变。
- 此次变更只调整 Hand 内部阶段职责和发布侧别，不反向改变 Face、Body 或 driver identity。
