# 2 设计结论

head-first 不是把 body/hand 生命周期绑定到 face 生命周期，而是把 driver identity owner 收敛到 face/head：

- face/head 决定 owner identity 和 legacy key 来源；
- body/torso evidence 继承 owner key，但按自身 motion state、hit/miss、handoff 和 cleanup 推进；
- left/right hand 继承 owner key，但按各自 slot 的 prediction、match、miss、reset/cleanup 推进；
- 对外发布仍受当前 owner 证据、稳定门槛、sanitize 和唯一性约束。

# 3 Body 四态 Edge

Body 全局 assignment 的业务解释应由 body phase 完成，不进入通用 solver：

| 模式 | 条件 | 处理 |
|---|---|---|
| Track | owner 有 body track；tracking loss 可信；face consistency 不明显冲突 | `CorrectMotion`、`AdvanceHit`，生命周期连续 |
| Reacquire | owner 有 body track；tracking loss 不可信；acquisition loss 高可信 | 保持 ownerFaceId；重置或强校正 motionState；不重置稳定 hitCount；保持输出连续 |
| Bootstrap | owner 没有 body track；acquisition loss 可信 | 新建 body evidence；`hitCount` 从 1 开始 |
| Forbidden | tracking/acquisition 都不可信或 face consistency 冲突 | owner unmatched；已有 body miss，必要时 retire |

Reacquire 是标定后目标。标定前的保守实现仍应关闭已有 body / initialized hand 的 acquisition fallback。

# 4 未闭合项

- 阶段 2A：Conservative Body global assignment，保持 Track / Bootstrap，不打开 Reacquire。
- 阶段 3A：Conservative Hand global slot assignment，保持 initialized slot 只走 tracking、uninitialized slot 只走 acquisition。
- 阶段 4A：Owner / body / hand 独立生命周期闭环，覆盖 face 短时消失、owner 确认退休、新 stable owner 接管、face id 复用时 body/hand cleanup。
- 阶段 4B：Loss instrumentation + replay 标定，在生命周期候选域闭合后采集 body/hand tracking/acquisition loss、driver/non-driver bias、face consistency gate 与 `dummyLoss` 分布。
- 阶段 4C：Body Reacquire 打开，并验证 ownerFaceId、hitCount、output continuity 与 motion reset/strong correction。
- 阶段 4D：评估 Hand 是否需要类似 Reacquire，基于 hand slot replay 数据决策。
- 阶段 5：phase/header 表示收敛。
