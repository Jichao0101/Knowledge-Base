# 哈欠检测头部偏转误报兜底记录

状态：project_record / pending_board_validation

## 背景
头部偏转时，嘴部 2D 关键点会受到投影影响，嘴角水平距离变短或局部形变，导致原始嘴部纵横比 MAR 假高，进而误报打哈欠。

## 本次实现
代码仓：`/home/jichao/dms`

变更文件：
- `source/fuse_algos/fatigue_algorithm.cpp`
- `include/fuse_algos/fatigue_algorithm.h`
- `etc/fatigue_params.json`

实现内容：
- `getAtomicResult` 接口保持不变，driver track id 在函数内部完成判断，并保存到 `FatigueAlgorithm::m_driverTrackId`。
- 哈欠检测新增头姿门控：当 driver 对应 `HeadPosture` 存在且有效，并且 yaw、pitch 或 roll 超过配置阈值时，本帧哈欠输入置为 `0`。
- 头姿缺失或无效时不强制抑制，继续走嘴部关键点兜底计算。
- 嘴部 MAR 从原始全嘴计算改为左右半嘴分别计算，取较小值的一半作为哈欠输入，用于降低头部偏转造成的单侧投影误报。
- `FATIGUE_YAWN_DETECT` 为 false 时，本帧哈欠输入保持为 `0`。
- 哈欠分支日志已区分三类原因：灵敏度配置关闭哈欠检测、头姿异常触发抑制、嘴部关键点计算失败。

新增配置：
- `threshold.yawnHeadPoseYawGate`
- `threshold.yawnHeadPosePitchGate`
- `threshold.yawnHeadPoseRollGate`

当前默认值均为 `15.0`。

## 风险与待验证
- 如果 `m_headPostureResultMap` 在疲劳算法执行时为空，头姿门控不会生效；本轮未修改 pipeline 或上游头姿计算，符合“不改上下游模块”的范围。
- 头姿门控将当前输入置为 `0`，但哈欠滤波器仍可能受历史窗口影响，头偏转后 `isYawn` 是否立即清除需板端时序验证。
- 半嘴 MAR 改变了哈欠输入分布，需用正脸真实哈欠、偏头闭嘴、偏头真实哈欠样本确认 `yawnHigh/yawnLow` 是否需要重标定。
