# 1 量化部署流程与验证框架

部署的目标是让模型在目标硬件上保持可接受的任务精度，同时满足时延和内存要求。量化通过降低数值表示精度改变计算与存储需求，但是否加速取决于后端支持和实际执行路径。因此，本项目把量化看作部署流程的一部分，并以分阶段对比定位问题。

本文说明部署阶段之间的关系及验证思路，不依赖具体仓库的目录、工具或参数。外部方法依据集中于 [[04_Sources/VLM部署/2026-10-30_量化部署官方资料学习导航]]；不同工具链可以调整步骤顺序，但需要保留可比较的输入、输出和数值语义。

## 1.1 从模型到设备经过什么

首先要固定浮点模型、预处理和评估样本，建立可对比的基线。随后将模型整理为工具链能处理的计算图，例如改写不支持的算子、固定某些输入维度或显式传入缓存。这个过程即使不降低精度，也可能引入行为变化，所以应先检查适配后的浮点结果。

在图语义可控后，依据硬件能力选择位宽、量化粒度和混合精度。静态量化使用代表性数据估计激活范围；若误差过大，再考虑权重优化、精度恢复或调整敏感层。量化仿真用于估计数值影响，本身不能证明设备端获得了低比特加速。

最后导出图、权重及量化参数，由目标编译器生成设备可执行产物。模型参数和运行时输入约定必须贯穿这些阶段，否则可能出现各阶段单独成功、整条链路失败的情况。

| 环节 | 应保留的产物或依据 |
|---|---|
| 浮点基线与模型准备 | 模型与预处理器身份、样本、浮点输出 |
| 精度方案与恢复 | 位宽配置、所用方法及前后精度对比 |
| 校准及导出 | 校准数据身份、模型图、权重与量化参数 |
| 硬件编译 | 工具链与目标配置、编译日志、设备可执行产物 |
| 设备运行与验收 | 运行配置、输出、任务精度及性能结果 |

## 1.2 校准与精度恢复分别解决什么问题

校准与精度恢复的目的不同。静态量化校准根据代表性输入估计激活的数值范围，从而确定量化参数；精度恢复则在量化误差不可接受时，通过调整权重、量化配置或训练等方式改善模型表现。因此，可以不执行某种精度恢复算法，但仍需完成所选量化方案要求的校准和验证。是否需要恢复精度应由评估结果决定，不能仅根据位宽作统一判断。

视觉语言模型还需要校准视觉与文本融合后的输入分布。自回归生成则分为处理提示词的 prefill 和逐 token 生成的 decode；两阶段的激活分布和图形状不同，不能假定全部量化参数可直接互换。缓存或循环状态跨图传递时，应核对两侧对同一状态的量化解释是否兼容。

## 1.3 如何判断问题出现在哪一阶段

假设最终设备输出明显异常，仅比较输入和最终文本不足以定位原因。应固定相同的图像、提示词、tokenizer、预处理及生成设置，从上游到下游逐项比较。以下对比用于区分误差来源，不表示已经完成相应测试。

| 对比 | 主要回答的问题 | 建议保留的观察 |
|---|---|---|
| 原始浮点模型 ↔ 适配浮点模型 | 算子改写、位置编码、padding或缓存是否改变行为？ | logits、必要中间张量与状态、同条件输出 |
| 适配浮点模型 ↔ 量化仿真模型 | 量化误差是否在允许范围内？ | 同一评估集的任务指标及敏感层误差 |
| 量化仿真模型 ↔ 设备模型 | 导出、编译与运行配置是否保持预期语义？ | 同输入输出差异、状态衔接、首个异常位置 |
| 设备模型 ↔ 部署目标 | 真实使用条件是否满足需求？ | 视觉任务精度、首token时延、解码速度、峰值内存和持续运行表现 |

生成过程中，早期 token 的微小差异会改变后续输入，因此不能将两条自由生成文本的所有后续差异都归因于同一个算子。定位时可固定 token 输入或比较同一解码步的 logits；任务验收则仍需完整生成评估。PPL可辅助观察语言部分，但不能独自代表图像理解能力。

## 1.4 何时进入下一轮优化

先排除适配和部署错误，再讨论量化精度恢复。若精度达标但设备性能不达标，再依据测量结果选择调整精度、图拆分、prefill宽度或其他执行配置。每次只改变能够解释影响的实验变量，并记录上下文长度、图像规格及冷热启动条件；验收阈值待实际任务和设备明确后制定。
