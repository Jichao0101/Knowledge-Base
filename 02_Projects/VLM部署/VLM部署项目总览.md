# 1 VLM部署项目总览

本项目研究如何将视觉语言模型（VLM）从框架中的浮点模型转为可在目标设备运行、并满足精度与性能要求的部署产物。以 Qwen3.5_VLM_Basic 仓库为首个案例，逐步学习模型适配、量化、编译和设备验证；项目范围不绑定某一个模型或平台。

## 1.1 当前进展与证据边界

2026-10-30 已完成首轮仓库静态分析、官方资料检索和学习框架建立。尚未执行量化、QAIRT 编译或设备推理，没有可作为部署验收依据的实测精度、时延或内存结果。仓库中的说明与代码观察也不等于本项目复现成功。

本项目起点来自同日对话中对 `/home/jichao/Qwen3.5_VLM_Basic` 的分析及用户确认的建库方案。项目记录保存案例和工作假设；官方依据先放来源区；经过审核、明确适用边界的通用结论才考虑提升为正式知识。

## 1.3 学习与实践顺序

1. 学习量化基础：能解释 scale、zero point、校准、量化仿真及权重/激活位宽的区别。
2. 学习 AIMET 流程：理解精度恢复与激活校准的不同职责，说明为什么跳过 AdaScale 不等于跳过量化。
3. 对照仓库：追踪 checkpoint、ONNX、encodings 和设备 binary 的生产与消费关系。
4. 确认运行条件后，尝试 0.8B 默认 W8 路径；这是首轮实验建议，尚未确认资源可用或成功运行。
5. 用流程文档中的四组对比定位误差，再测量端到端时延和资源占用，最后考虑 W4、AR256 或其他模型与平台。

## 1.4 首轮实践前需要确认什么

开始实验前，先明确目标设备与 SDK 版本、模型和 processor 文件是否齐全、校准及评估数据是否可用、主机显存与磁盘是否满足需求。随后制定任务精度与性能验收目标，避免将“脚本退出成功”作为完成标准。

首次运行应记录模型版本或文件指纹、代码快照、环境版本、量化配置、数据划分、产物路径和原始日志。当前仓库目录未发现 Git 元数据，暂时不能用提交号复原分析快照。实验记录产生后再加入本入口，不提前填写通过状态。

## 1.5 后续沉淀规则

通用机制在有明确依据和适用边界后再提炼；平台补丁、算子编号和单次实验配置保留在案例记录。校准集与评估集应区分用途，正式评估不复用调参结论冒充独立验收。新增实验不覆盖既有观察，发生结论替代时保留原因和证据。
