# 1 AI Career 学习文档维护规范

## 1.1 目标

本规范解决三个问题：规划、教学和进度不再混写；诊断过程不再污染可复用学习正文；进入新阶段时先有完整但可迭代的教学骨架，再根据真实缺口调整深度与顺序。

## 1.2 文档职责

持续实验工作包采用“独立方案+连续主实验记录+原始工件”。本轮规则及追加机制见1.7；旧单次记录保持原用途。

| 文档类型 | 只负责什么 | 不负责什么 |
|---|---|---|
| 整体学习方案 | 职业目标、阶段顺序、任务范围、阶段门禁 | 逐题诊断、运行日志、个人掌握结论 |
| 阶段学习文档 | 稳定教学骨架、机制、例子、设计方法、适用边界 | 日期化答题过程、个人状态、当前下一步 |
| 阶段学习记录 | 诊断题、用户回答、缺口、掌握状态、未验证项、恢复任务 | 展开完整教学正文 |
| 实践记录 | 固定输入、配置、命令、原始输出、指标、失败分析 | 用一次运行结果替代稳定机制说明 |
| 当前阶段检查点 | 当前阶段、恢复顺序、门禁和最近未完成项 | 全量教学内容和长期诊断历史 |
| 项目总览/索引 | 当前入口、状态摘要和文档关系 | 重复下层正文 |

同一事实只保留一个主要承载位置，其他文档使用链接和短摘要，不复制整段内容。

## 1.3 新阶段生命周期

进入新阶段或新主题时按固定顺序执行：

```text
确认任务合同与阶段边界
→ 创建阶段学习文档骨架
→ 创建对应学习记录
→ 按骨架教学
→ 一次一个主动重建或诊断问题
→ 在学习记录中保存回答、缺口和证据状态
→ 形成缺口映射
→ 受控更新学习文档
→ 执行最小实践并写实践记录
→ 更新滚动检查点与入口
```

“先建骨架”不要求第一次就写成最终教材。它要求在开始诊断前，至少明确：学习目标、输入输出或数据流、核心模块、关键边界、最小例子、实践接口和完成证据类型。未知部分可以标记为待补，不得用连续考试代替教学。

## 1.4 诊断如何驱动学习文档更新

诊断结果先写学习记录，再形成缺口映射：

| 诊断信号 | 学习文档允许的更新 | 不允许的更新 |
|---|---|---|
| 大面积缺失 | 补充最小数据流、术语和贯穿例子，调整教学顺序 | 只增加更多问题 |
| 局部混淆 | 加入对比、反例、shape 或失败边界 | 把错误回答原样写进正文 |
| 能复述但不会迁移 | 增加迁移例、故障场景和实践接口 | 直接标记“已掌握” |
| 实践失败 | 补充机制边界、配置约束和可观察信号 | 用单次失败否定全部机制 |
| 主干稳定 | 减少重复解释，保留核心结构并转向实践 | 静默删除仍有复用价值的核心知识 |

更新学习正文时遵守以下约束：

1. 只写从诊断中抽象出的稳定教学补充，不写“用户答对/答错”等个人结果。
2. 允许增补、重排、合并重复内容和调整深度；删除稳定核心内容前必须说明原因并确认不影响后续恢复。
3. `working`、`partial`、`waived_by_scope` 和 `not_verified` 只写在学习记录、实践记录或检查点，不用它们装饰教学正文。
4. 诊断驱动补充保留在对应大章末尾，新增或实质重写时标题采用“<章节号> <主题>知识补充”。组织单位是知识薄弱点及其前置关系，不是题目顺序。先解释概念和依赖，再说明机制、适用条件及与主干的联系；公式需说明符号与前提，例子只用于帮助推导，不能替代解释。不要求每个知识点机械套用相同模板。已经理解的简单算术不默认进入正文，个人错误、提示与复测状态留在学习记录。
5. 写后从未见过对话的读者角度检查：是否无需原题即可理解，是否说明“为什么”，是否能迁移到不同数字或场景，是否与现有正文重复。已有主干足够时使用交叉引用，不为每个答题点各造一节。若补充成为理解主干所必需，再评估并入基础小节并同步引用；历史章节标题不强制整组改名。

2026-09-14 组织规则调整：本节第4～5条接替2026-09-11仅以“易混机制与诊断例子”统一形式的规则。此前规则强调章末位置与例子，未充分约束解释质量；本次保留章末组织，明确以知识薄弱点及其因果联系为主。依据为本次用户反馈及学习记录第1.11节，不改变个人能力或实践验证状态。

## 1.5 阶段切换与恢复

阶段切换前检查：

- 学习文档仍是纯教学内容，并链接对应学习记录。
- 学习记录保存诊断结论、范围决定与未验证项。
- 实践记录保存运行配置和原始证据；未运行时明确为 `not_verified`。
- 当前检查点只保留恢复所需的最近状态和门禁。
- 学习文档索引与项目总览已同步入口。
- 未经独立 recoverability verification，不声明 `single_pass_recoverable: true`。

## 1.6 命名与放置

- 规划与规范：`00_规划/`。
- 学习正文：`10_学习文档/P<阶段>-<序号>_<主题>_学习文档.md`。
- 学习记录：`20_学习记录/P<阶段>_<主题>_学习记录.md`。
- 实践记录：`30_实践记录/P<阶段>_<主题>_<日期>_实践记录.md`。
- 模板：`00_规划/模板/`，复制后必须替换全部占位符。

重命名、移动、新增入口或改变事实源前，仍需遵守知识库写前门禁与入口同步要求。

## 1.7 连续实验记录与逐步写回（2026-09-16）

### 1.7.1 职责与授权

用户明确授权本项目每次实验步骤更新记录。对已经授权的当前工作包，后续收到用户执行输出/截图、代理实际执行、配置改变、理论预测修正、失败/重试或阶段决定时，主动更新同一主实验记录，不要求用户重复“回写”。如果本轮只提供待运行命令或脚本，指导保留在对话中，不为下发指导单独写入知识库；不得记为已执行。只有口头讨论、无新证据或决定时不重复刷文档；用户明确“先不写”时暂停该轮写回。

本规则仅为知识记录维护授权，不授权新目录读取、费用操作、模型训练启动、受保护事实改写或正式知识提升；仍按AGENTS实际语义影响做写前检查。例行同范围事件追加读主记录/直接证据和相关约束；结论替代、当前事实源变化或保护事实涉及完整preflight，先处置冲突再应用。

### 1.7.2 统一组织

- 持续工作包在30_实践记录建立一份稳定命名的主记录，不按命令、日期、每个小步骤拆文件；单次实践仍可用旧模板。
- 每步围绕“目标与决策→已知条件→理论预测→测量重点→结果与差异解释→决定与下一步”；正文以Sxx步骤组织；Sxx-Rnnn执行事件单独保存在证据附录。
- 已发生事件为append-only：失败、OOM、调整与旧数字保留；更正通过新事件说明双向替代和依据，不静默覆盖。正文摘要和进度表可据新结果更新，依据与替代关系在附录中关联。
- 区分用户报告、文件检查、代理执行、理论估算与未验证项。截图成功不等于整个训练/服务通过；静态header不证明GPU占用或payload完整性。
- 工件包含精确命令/代码、环境、配置、输入身份、原始输出和指标。大文件存独立路径；需要作为正式验证依据的派生报告，由主记录链接的证据附录明确引用路径/hash。不可访问的远端文件和临时截图只标报告来源，不假装已归档核验。
- 不为了填表新增无价值实验，不把复用已处理数据变成重复全量审计。必要的加载错误检查保留。

### 1.7.3 更新顺序与同步范围

1. 恢复学习先读全局《当前阶段学习检查点》，确认整个学习方案中的当前阶段和任务；再进入其指向的学习文档、学习记录或实验记录。仅当前任务属于某实验时才读取该实验当前步骤。项目总览用于导航，实验记录不得成为全局检查点的上级入口；仍有效上下文可复用。
2. 写前确认授权、目标、变化及冲突；新输入与原快照不一致则重新审查。
3. 先在附录追加执行事件与来源，再将有效结果整理到正文的预测/实测对照、分析、决定与当前状态；正文不堆积事件日志。
4. 下一步、阻塞或步骤状态改变时，同轮同步检查点；步骤完成后才进入下一阶段。
5. 新主记录维护实践索引/项目总览。重大范围、模型角色、事实源/恢复入口改变同步方案和总览；涉及结构策略/恢复状态时同步结构审计。普通单次指标追加不要求全套总览重写，结束时说明不需同步的原因。
6. 验证新增链接、实际diff与证据边界；无法写入时明确哪些结果未持久化，不声称已更新。

### 1.7.4 全局检查点与实验步骤的层级

全局检查点属于整个学习方案，实验记录属于其中一个实践工作包。二者更新关系为“实验产生证据后同步全局指针”，这不等于读取时先实验后检查点。2026-09-16用户纠正后，本条与1.7.3接替实验记录原先颠倒的恢复顺序；逐步追加实验结果的授权与证据边界不变。

### 1.7.5 正文可读性与证据附录

连续实验正文面向人类阅读，按目标、配置、理论、测量重点、结果分析和下一步展开。来源类型、执行事件表、截图标识、hash、授权及文档修订历史统一放入独立附录，正文只保留按需查阅链接，不逐项添加“用户截图”“代理执行”等前缀。正文仍明确区分理论估算与实测、已完成与待验证，不因简化表述扩大结论。

本条及修订后的1.7.2～1.7.3接替原先正文中“执行与证据”事件表、摘要逐项引用事件的安排。依据是2026-09-16关于阅读连续性的明确要求；旧组织规则及迁移说明保存在[[02_Projects/AI-Career-Transition/30_实践记录/Qwen3.5-9B睁闭眼分类微调与部署实验附录]]C～D节。事件追加与双向更正规则继续有效；全局学习检查点始终优先于实验记录。

### 1.7.6 实操指导与实验记录的边界

上传脚本、保存位置、运行命令和逐步操作指导只在对话中提供，不默认写入知识库，也不转存到附录。正文保留有助于理解的关键机制、测量口径、必要配置、实际结果、分析与决定；重点解释按需纳入，避免把全部操作换名为“解释”。仅提供指导时不触发实验事件写回。

已发生执行的来源及必要工件标识仍可在附录记录，用于追溯结果；这不要求复制操作教程或完整命令。既有历史事件与工件保留。此条依据本次明确要求，接替1.7.1原“只提供待运行命令，可记issued_pending_result”、旧模板“操作步骤”以及正文内脚本上传/运行指导的安排。更正说明见实验附录F节。

## 1.8 VLM实验文档的解释与写作约定（2026-10-18）

### 1.8.1 适用范围与职责

本约定适用于本项目VLM基线、prompt/ROI诊断、模型对照、微调、性能、部署及扩展实验的方案、正文与附录，包括后续新增实验。它细化1.7.2的结果解释和1.7.5的正文/附录分工，不改变任务合同、实验验收、证据等级或历史事件追加规则；非VLM材料可按需要参考，不统一改写。

| 文档用途 | 阅读者应得到什么 | 组织重点 |
|---|---|---|
| 实验方案 | 要回答什么问题，为什么这样设计，什么结果能区分假设 | 问题、对照变量、指标含义、接受与停止条件；不把预期写成实测 |
| 分析报告／连续记录正文 | 观察到什么，数据如何支持解释，当前决定是什么 | 按问题串联证据、推理与行动；Sxx保留为步骤导航，日期用于区分轮次 |
| 实验附录 | 如何追溯和复核结果 | 完整运行条件、统计口径、原始输出、调用形状、资源配置与必要工件入口 |
| 历史记录 | 当时发生了什么，判断后来如何接续 | 保留原事实与判断；必要时补充后续入口，不批量改写历史 |

### 1.8.2 正文解释要求

1. **以问题组织。** 标题优先写工程或研究问题，例如“为什么增大batch后吞吐收益收窄”，而不是仅以工具、日期或“分析补充”命名。简单单次实验无需增加多层标题。
2. **补齐推理。** 关键结论对应“观察数据→比较或计算→解释→决定”。说明分母、单位和对照条件，解释数字变化为什么支持判断；无需机械地给每段加四种标签。没有足够证据时说明待区分的假设，不用顺畅叙事掩盖缺口。
3. **明确证据层次。** 性能分析区分计算图/调用形状、GPU kernel执行效率、系统提交/同步与端到端表现。质量分析区分预测现象、评分与分组结果、原因假设及干预验证。跨层推断需交代连接依据：逐图调用不直接证明硬件利用不足；高匹配后准确率也不直接证明整体分类可靠。
4. **按作用范围放置限制。** 直接改变当前数字含义、结论强度或配置选择的限制紧邻结果；全实验共用的身份、样本覆盖、采集扰动或验证缺口集中到“尚未验证的问题”。优先正面说明已知范围与待测对象，减少每段重复“不能”；正文结论本身仍保持准确。
5. **正文能够独立理解。** 保留支持决定的关键数字、代表性形状和必要测量条件。完整Q/K/V、kernel grid、寄存器与共享内存、逐次数据和复算过程按需引用附录。正文与附录按是否参与当前推理分工，不按“数字一律移走”处理。
6. **下一步连接决定。** 写清固定什么、改变什么、测什么，以及什么结果会改变采用、调整、暂缓或停止的选择。区分推进实验的必要验证与进一步解释机制的研究，避免把所有未知项都列为前置阻塞。

### 1.8.3 更新与验收

新建和后续实质更新的VLM实验按本节组织。存量整理优先覆盖正在使用的方案和分析正文；附录核对证据对应关系，日期化历史材料保留原貌。先检查现有结构是否已经清楚，避免为统一格式制造重复章节。通常通过附录保留取证和历史关系，不默认在每份正文附上完整折叠旧文；确需保留历史原分析时明确其日期和用途，当前阅读主线只保留一处。

写前沿用知识库按语义影响分级的门禁。风格调整保留数值、分母、实验状态、任务合同和已有决定；发现事实冲突或需要替换结论时单独处理，不能作为文风修改静默覆盖。写后从未参与对话的读者视角检查：

- 能否说明实验要解决的问题及其对后续决定的作用？
- 能否找到每条关键判断对应的数据，并复述中间推理？

## 1.9 性能优化补充学习的专题写作原则（2026-11-20）

本节适用于因模型性能优化发现知识短板而新增或实质修订的AI Infra学习专题，依据2026-11-20本会话用户确认。它细化新专题的内容组织与深度分配，保留1.4对既有正文诊断补充、1.7对实践记录的约束，不改变学习阶段、实验门禁或能力状态。

### 1.9.1 按内容组织，借助课程建立完整框架

专题合集以知识内容和理解依赖组织，标题描述主题，不以课程名、讲次或日期作为主要分类。CS336与NVIDIA等课程可以提供成熟的解释顺序与覆盖清单；一节课恰好形成完整框架时可以借用，但不机械规定一讲一篇。跨来源材料可以共同支撑一篇，多个强依赖内容也可以合篇。

核心原则是：**用课程帮助建立完整框架，用工程目标确定组织主线，用讨论暴露的理解缺口分配讲解深度。** 对话决定哪些内容着重解释，不单独决定内容范围。即使未在对话中追问，GPU/TPU、SIMD/SIMT、存储层级和显存优化等建立主题认知所需的内容也应保留。完整性不意味着平均分配篇幅：框架部分讲清职责、联系与边界，难点部分补足连续推导。

单篇围绕能够独立理解的主题展开，不拆成零散问答，也不把整套课程不断追加为一篇综合长文。先建立实际需要的专题，再按内容增长决定拆分；不预建整套课程空文件。主题边界以完整解释链为准，不能为了减少篇幅迫使读者频繁跳转才能读懂一个算例。

### 1.9.2 主线、重点与来源的组织

写前明确读者要建立的整体认识，列出必要前提、核心机制及本次难点，再按理解依赖安排正文。可采用“主题问题与背景→完整框架→重点机制与连续算例→优化取舍→验证与迁移”的顺序，不要求每篇套同一章节模板。

重点解释应先固定数据身份、shape、存储布局、线程分工等前提，再展示观察、计算与判断。例如矩阵乘法先说明M/N输出分块和K归约分块，再讨论加载/计算映射及地址对齐；不能尚未交代线程映射就判断coalescing。术语、参数和指标在推导需要时出现，表格用于比较，正文负责因果解释。

课程摘要服务于完整框架，可以融入导读；来源部分记录年份、讲次、链接及已核对范围。区分课程直接内容、其他官方资料补充、教学推导与对话中的难点；未经核验不归属为讲师原话，不虚构字幕、时间戳或图示结论。外部信息先建来源记录，再形成项目学习正文，不直接提升正式知识。

交付前按读者顺序通读受影响正文，检查：整体框架是否因只记录对话难点而残缺；重点是否真正补齐中间推导；段落是否承接前文问题；案例能否迁移到不同shape或条件；理论估算、示意模型与实测是否清楚区分。再核对数值、单位、来源、链接和边界。机械lint通过不能替代可读性检查。

### 1.9.4 简繁分配与图解承接（2026-11-20反馈补充）

完整框架不要求重复讲解已有基础：跨篇已有清晰图示时，优先复用图与定位链接，正文只交代当前推导需要的前提。硬件比较围绕设计取舍和性能影响，不堆部件名称；SIMD/SIMT在本专题聚焦共享指令下的分支、predication与mask取舍，不重复线程层级。

重点难点必须占据正文主要解释篇幅。对话中的有效图像应检查并保留；不足以独立理解时补画连续示意，明确原图、重绘图和教学模型的身份。先告诉读者看哪里，再沿数据、线程和阶段解释变化，最后给公式和适用边界；不能用大表格或结论替代图中的过程。Tiling需明确区分单GPU片上工作集/显存流量优化与跨GPU切分，不将“放不进显存”设为必要前提。本条细化1.9.1～1.9.3，不改变事实与验证标准。


### 1.9.5 用具体过程解释，采用直接、正面的叙述

本条依据2026-11-20用户对整篇P02A-03的反馈，适用于本项目后续学习文档的新写与实质修订。

1. **先展示过程，再命名术语。** 解释机制时给出具体输入、参与者、执行步骤和结果，让读者先看清发生了什么，再引入便于后文使用的名称。例如说明predication，先展示各线程的条件、执行的指令与结果。
2. **按解释价值决定详略。** 影响理解的难点展开例子和推导；只提供背景的术语用一句话交代，缺少实际用途的介绍直接删减。避免用更多术语解释一个尚未理解的术语。
3. **优先正面说明机制。** 直接写“什么在变化、怎样执行、为什么影响性能”。“不是X、不能理解为Y、不等于Z”仅在确有易混对象且比较能帮助理解时使用，并紧接具体例子；不以连续否定句代替解释。
4. **让边界参与当前判断。** 把假设、条件和风险放在它所影响的数字或结论附近，说明该条件怎样改变结果。全篇共用的未验证事项集中说明，避免反复打断主线。保留必要边界与证据强度。
5. **通读整篇检查。** 每段应推进问题、展示过程或支持判断。将抽象总结改成可跟随的过程，合并重复提醒，删除没有新增信息的句子；检查重点章节是否仍承担主要解释篇幅。完成后复核数值、来源和结论边界。


### 1.9.6 图像清晰度与数学关系表达

正文优先使用清晰的重绘图、表格、函数或公式。对话中的低清截图只作为理解来源，呈现时重新组织图示或转换为表格；1.9.4要求保留的是有效解释关系与出处，正文无需嵌入原截图。

多个线程、矩阵元素或阶段之间的对应关系，用映射表列出分工，用公式写出计算依赖，再用短句解释关键联系。例如先列线程向共享数组写入哪些值，再以带来源标注的公式说明C00使用哪些值。避免在长段落里反复切换T0/T1、A00/A01等符号，迫使读者在脑中追踪。公式出现前交代符号，公式后点明本段要观察的关系；图、表、公式各承担明确职责。
