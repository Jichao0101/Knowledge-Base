# 1 AI Career 学习文档维护规范

## 1.1 目标

本规范解决三个问题：规划、教学和进度不再混写；诊断过程不再污染可复用学习正文；进入新阶段时先有完整但可迭代的教学骨架，再根据真实缺口调整深度与顺序。

## 1.2 文档职责

持续实验工作包采用“独立方案+连续主实验记录+原始工件”。本轮规则及追加机制见1.7；旧单次记录保持原用途。

| 文档类型 | 只负责什么 | 不负责什么 |
|---|---|---|
| 整体学习方案 | 职业目标、阶段顺序、任务范围、阶段门禁 | 逐题诊断、运行日志、个人掌握结论 |
| 阶段学习文档 | 稳定教学骨架、机制、例子、设计方法、适用边界 | 日期化答题过程、个人状态、当前下一步 |
| 阶段学习记录 | 诊断题、用户回答、缺口、掌握状态、未验证项、恢复任务 | 展开完整教学正文 |
| 实践记录 | 固定输入、配置、命令、原始输出、指标、失败分析 | 用一次运行结果替代稳定机制说明 |
| 当前阶段检查点 | 当前阶段、恢复顺序、门禁和最近未完成项 | 全量教学内容和长期诊断历史 |
| 项目总览/索引 | 当前入口、状态摘要和文档关系 | 重复下层正文 |

同一事实只保留一个主要承载位置，其他文档使用链接和短摘要，不复制整段内容。

## 1.3 新阶段生命周期

进入新阶段或新主题时按固定顺序执行：

```text
确认任务合同与阶段边界
→ 创建阶段学习文档骨架
→ 创建对应学习记录
→ 按骨架教学
→ 一次一个主动重建或诊断问题
→ 在学习记录中保存回答、缺口和证据状态
→ 形成缺口映射
→ 受控更新学习文档
→ 执行最小实践并写实践记录
→ 更新滚动检查点与入口
```

“先建骨架”不要求第一次就写成最终教材。它要求在开始诊断前，至少明确：学习目标、输入输出或数据流、核心模块、关键边界、最小例子、实践接口和完成证据类型。未知部分可以标记为待补，不得用连续考试代替教学。

## 1.4 诊断如何驱动学习文档更新

诊断结果先写学习记录，再形成缺口映射：

| 诊断信号 | 学习文档允许的更新 | 不允许的更新 |
|---|---|---|
| 大面积缺失 | 补充最小数据流、术语和贯穿例子，调整教学顺序 | 只增加更多问题 |
| 局部混淆 | 加入对比、反例、shape 或失败边界 | 把错误回答原样写进正文 |
| 能复述但不会迁移 | 增加迁移例、故障场景和实践接口 | 直接标记“已掌握” |
| 实践失败 | 补充机制边界、配置约束和可观察信号 | 用单次失败否定全部机制 |
| 主干稳定 | 减少重复解释，保留核心结构并转向实践 | 静默删除仍有复用价值的核心知识 |

更新学习正文时遵守以下约束：

1. 只写从诊断中抽象出的稳定教学补充，不写“用户答对/答错”等个人结果。
2. 允许增补、重排、合并重复内容和调整深度；删除稳定核心内容前必须说明原因并确认不影响后续恢复。
3. `working`、`partial`、`waived_by_scope` 和 `not_verified` 只写在学习记录、实践记录或检查点，不用它们装饰教学正文。
4. 诊断驱动补充保留在对应大章末尾，新增或实质重写时标题采用“<章节号> <主题>知识补充”。组织单位是知识薄弱点及其前置关系，不是题目顺序。先解释概念和依赖，再说明机制、适用条件及与主干的联系；公式需说明符号与前提，例子只用于帮助推导，不能替代解释。不要求每个知识点机械套用相同模板。已经理解的简单算术不默认进入正文，个人错误、提示与复测状态留在学习记录。
5. 写后从未见过对话的读者角度检查：是否无需原题即可理解，是否说明“为什么”，是否能迁移到不同数字或场景，是否与现有正文重复。已有主干足够时使用交叉引用，不为每个答题点各造一节。若补充成为理解主干所必需，再评估并入基础小节并同步引用；历史章节标题不强制整组改名。

2026-09-14 组织规则调整：本节第4～5条接替2026-09-11仅以“易混机制与诊断例子”统一形式的规则。此前规则强调章末位置与例子，未充分约束解释质量；本次保留章末组织，明确以知识薄弱点及其因果联系为主。依据为本次用户反馈及学习记录第1.11节，不改变个人能力或实践验证状态。

## 1.5 阶段切换与恢复

阶段切换前检查：

- 学习文档仍是纯教学内容，并链接对应学习记录。
- 学习记录保存诊断结论、范围决定与未验证项。
- 实践记录保存运行配置和原始证据；未运行时明确为 `not_verified`。
- 当前检查点只保留恢复所需的最近状态和门禁。
- 学习文档索引与项目总览已同步入口。
- 未经独立 recoverability verification，不声明 `single_pass_recoverable: true`。

## 1.6 命名与放置

- 规划与规范：`00_规划/`。
- 学习正文：`10_学习文档/P<阶段>-<序号>_<主题>_学习文档.md`。
- 学习记录：`20_学习记录/P<阶段>_<主题>_学习记录.md`。
- 实践记录：`30_实践记录/P<阶段>_<主题>_<日期>_实践记录.md`。
- 模板：`00_规划/模板/`，复制后必须替换全部占位符。

重命名、移动、新增入口或改变事实源前，仍需遵守知识库写前门禁与入口同步要求。

## 1.7 连续实验记录与逐步写回（2026-09-16）

### 1.7.1 职责与授权

用户明确授权本项目每次实验步骤更新记录。对已经授权的当前工作包，后续收到用户执行输出/截图、代理实际执行、配置改变、理论预测修正、失败/重试或阶段决定时，主动更新同一主实验记录，不要求用户重复“回写”。如果本轮只提供待运行命令或脚本，指导保留在对话中，不为下发指导单独写入知识库；不得记为已执行。只有口头讨论、无新证据或决定时不重复刷文档；用户明确“先不写”时暂停该轮写回。

本规则仅为知识记录维护授权，不授权新目录读取、费用操作、模型训练启动、受保护事实改写或正式知识提升；仍按AGENTS实际语义影响做写前检查。例行同范围事件追加读主记录/直接证据和相关约束；结论替代、当前事实源变化或保护事实涉及完整preflight，先处置冲突再应用。

### 1.7.2 统一组织

- 持续工作包在30_实践记录建立一份稳定命名的主记录，不按命令、日期、每个小步骤拆文件；单次实践仍可用旧模板。
- 每步围绕“目标与决策→已知条件→理论预测→测量重点→结果与差异解释→决定与下一步”；正文以Sxx步骤组织；Sxx-Rnnn执行事件单独保存在证据附录。
- 已发生事件为append-only：失败、OOM、调整与旧数字保留；更正通过新事件说明双向替代和依据，不静默覆盖。正文摘要和进度表可据新结果更新，依据与替代关系在附录中关联。
- 区分用户报告、文件检查、代理执行、理论估算与未验证项。截图成功不等于整个训练/服务通过；静态header不证明GPU占用或payload完整性。
- 工件包含精确命令/代码、环境、配置、输入身份、原始输出和指标。大文件存独立路径；需要作为正式验证依据的派生报告，由主记录链接的证据附录明确引用路径/hash。不可访问的远端文件和临时截图只标报告来源，不假装已归档核验。
- 不为了填表新增无价值实验，不把复用已处理数据变成重复全量审计。必要的加载错误检查保留。

### 1.7.3 更新顺序与同步范围

1. 恢复学习先读全局《当前阶段学习检查点》，确认整个学习方案中的当前阶段和任务；再进入其指向的学习文档、学习记录或实验记录。仅当前任务属于某实验时才读取该实验当前步骤。项目总览用于导航，实验记录不得成为全局检查点的上级入口；仍有效上下文可复用。
2. 写前确认授权、目标、变化及冲突；新输入与原快照不一致则重新审查。
3. 先在附录追加执行事件与来源，再将有效结果整理到正文的预测/实测对照、分析、决定与当前状态；正文不堆积事件日志。
4. 下一步、阻塞或步骤状态改变时，同轮同步检查点；步骤完成后才进入下一阶段。
5. 新主记录维护实践索引/项目总览。重大范围、模型角色、事实源/恢复入口改变同步方案和总览；涉及结构策略/恢复状态时同步结构审计。普通单次指标追加不要求全套总览重写，结束时说明不需同步的原因。
6. 验证新增链接、实际diff与证据边界；无法写入时明确哪些结果未持久化，不声称已更新。

### 1.7.4 全局检查点与实验步骤的层级

全局检查点属于整个学习方案，实验记录属于其中一个实践工作包。二者更新关系为“实验产生证据后同步全局指针”，这不等于读取时先实验后检查点。2026-09-16用户纠正后，本条与1.7.3接替实验记录原先颠倒的恢复顺序；逐步追加实验结果的授权与证据边界不变。

### 1.7.5 正文可读性与证据附录

连续实验正文面向人类阅读，按目标、配置、理论、测量重点、结果分析和下一步展开。来源类型、执行事件表、截图标识、hash、授权及文档修订历史统一放入独立附录，正文只保留按需查阅链接，不逐项添加“用户截图”“代理执行”等前缀。正文仍明确区分理论估算与实测、已完成与待验证，不因简化表述扩大结论。

本条及修订后的1.7.2～1.7.3接替原先正文中“执行与证据”事件表、摘要逐项引用事件的安排。依据是2026-09-16关于阅读连续性的明确要求；旧组织规则及迁移说明保存在[[02_Projects/AI-Career-Transition/30_实践记录/Qwen3.5-9B睁闭眼分类微调与部署实验附录]]C～D节。事件追加与双向更正规则继续有效；全局学习检查点始终优先于实验记录。

### 1.7.6 实操指导与实验记录的边界

上传脚本、保存位置、运行命令和逐步操作指导只在对话中提供，不默认写入知识库，也不转存到附录。正文保留有助于理解的关键机制、测量口径、必要配置、实际结果、分析与决定；重点解释按需纳入，避免把全部操作换名为“解释”。仅提供指导时不触发实验事件写回。

已发生执行的来源及必要工件标识仍可在附录记录，用于追溯结果；这不要求复制操作教程或完整命令。既有历史事件与工件保留。此条依据本次明确要求，接替1.7.1原“只提供待运行命令，可记issued_pending_result”、旧模板“操作步骤”以及正文内脚本上传/运行指导的安排。更正说明见实验附录F节。
