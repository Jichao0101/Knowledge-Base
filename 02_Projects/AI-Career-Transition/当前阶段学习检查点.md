# 1 当前阶段学习检查点

## 1.1 检查点用途

本文件是项目内固定的滚动学习恢复入口。项目总览长期只链接本路径；阶段切换时先生成持久的阶段系统学习文档，再把本文更新到下一阶段。

本文不是五份 current 文档组，不承担项目总体事实源，也不保存完整历史。历史由阶段系统学习文档保存。

滚动规则：

```text
阶段中：更新当前焦点、评测结果、薄弱项和下一步
阶段结束：生成持久系统学习文档
完成校验：在项目总览登记持久文档
阶段切换：把本检查点改为下一阶段
```

状态解释：

```text
已验证：能够主动解释主要机制或完成检查题。
部分闭合：理解主干，但在边界题中仍需提示或纠正。
待学习：当前回答表明心智模型尚未建立。
未评测：尚未进入该覆盖区。
```

## 1.2 当前阶段结论

2026-08-09，用户完成 Phase 1-B 主动学习诊断。四类任务、评分方法、评测合同、abstain/失败标签、评分一致性和留出集污染等概念达到对话诊断意义上的 `working`。持久关闭记录见 [[02_Projects/AI-Career-Transition/AI评测基本功系统学习文档]]。

原计划中的 seed cases 持久化、隔天重复评分、确定性规则基线和逐 case 运行属于简单传统评测实现。用户基于目标岗位与学习投入产出明确将其标记为 `waived_by_scope`，不再作为阶段阻塞项。对话中形成的四类 seed case 只作为概念草案，不声明已落盘、已重复评分或已运行基线。

本滚动检查点现切换为 `Phase 1-C - VLM baseline and benchmark draft`。当前先建立 VLM 从图像输入到文本输出的数据流，再运行一个开源小型 VLM，形成可复现的图像问答最小基线。

2026-08-10，用户修正主动学习方法：Phase 1-C 以及后续阶段不得把主动学习误用为连续考试。知识大面积缺失时，应先建立教学骨架，再用主动重建、诊断题、微型补课和实践验证闭合。Phase 1-C 的教学骨架见 [[02_Projects/AI-Career-Transition/Phase1-C_VLM基线与benchmark草案系统学习文档]]；该文档是当前学习材料，不是阶段完成证明。

2026-08-10，Phase 1-C 首轮主动学习诊断完成一部分：用户能说明图片经 image encoder / visual tokens / projector 后与 text token embeddings 组成连续输入序列；能区分普通 projector 的维度对齐作用与 token 数量压缩；能解释训练得到的 `Wq/Wk/Wv` 使推理时文本问题和相关视觉 patch 通过 attention 建立关联；能把单帧闭眼检测和 10 秒持续闭眼超过 2 秒区分为空间判别与时序证据任务。视频采样边界、持续时长漏检风险和 benchmark case 完整设计仍为部分闭合；开源小型 VLM baseline 尚未运行。

## 1.3 上一阶段完成证据

- 能按输出是否唯一、证据依赖和外部副作用区分确定性、开放生成、检索/证据和工具执行任务。
- 能把混合任务拆成检索、决策和工具执行子合同，并区分候选级业务判断与顶层任务状态。
- 能区分 exact match、规则、语义、模型和人工评分的适用边界，并采用“语义抽取 + 规则判断”的分层评分。
- 能说明评测合同冻结的是输入、可接受结果、证据、abstain、失败标签、权限和预算，而不是唯一执行轨迹。
- 能解释评分者不一致、人工标签边界、rubric 漂移、留出集污染和最简单基线的证据边界。
- 已完成正常合规、证据不足、合法空结果和政策不可读四类 seed case 的对话推演。

证据边界：以上为主动学习对话、反例题和费曼复述证据。seed cases 未持久化，未执行隔天重复评分、规则基线或逐 case 运行；这些实践为 `waived_by_scope`，不写成已验证。

## 1.4 上一阶段已完成且不重复展开的内容

- 任务事实确定不等于答案字符串唯一；输出不唯一也不等于无法使用规则评分。
- 工具执行成功需要验证权限、外部状态、副作用和重复执行边界，不能只相信接口返回。
- 评测合同规定“什么算成功、失败或应当拒绝”，参考实现只描述一种可能路径。
- 评分者不一致时先修订合同或 rubric，不先扩充案例。
- 人工标签不天然是真实标签；Agent 与人工一致只能证明一致性。
- 留出集参与规则修改后即成为调试集，最终评估需要新的未查看案例。
- 规则基线只能验证 schema、规则、标签和评分链路，不能证明语义理解或 Agent 能力。

这些内容只在 Phase 1-C 的 VLM 任务暴露相关缺口时回补，不恢复低价值的传统规则脚本练习。

## 1.5 Phase 1-C 当前覆盖区

### 1.5.1 学习内容

1. **VLM 数据流**：ViT、视觉 token、图像 encoder、projector 和语言模型的连接方式。
2. **推理约束**：图像/视频采样、上下文长度、KV cache 和推理成本。
3. **任务与证据**：图像问答的输入输出、可复核期望行为和主要失败类型。
4. **评测分组**：按输入质量、场景难度和任务类型解释结果，不只看总体指标。

### 1.5.2 当前诊断状态

| 覆盖区 | 状态 | 证据边界 |
|---|---|---|
| 单图 VLM 数据流 | 已验证 | 能闭卷说明 image encoder、visual tokens、projector、text embeddings 与 LLM 输入序列的主链。 |
| projector 与 token 压缩 | 已验证 | 能用 `576 x 1024 -> 576 x 4096` 说明普通 projector 对齐特征维度，不自动减少 token 数量。 |
| 视觉证据与问题语义 | 已验证 | 能说明 attention 在推理时用固定参数生成当前输入的 `Q/K/V` 和权重，使问题语义关联相关视觉 patch。 |
| 视频与多帧输入 | 部分闭合 | 能说明上下文预算、ROI、时间采样和持续闭眼任务的时间证据需求；采样间隔、漏检风险和策略设计还需结合实践继续检查。 |
| benchmark case 设计 | 部分闭合 | 能区分单帧 yes/no 和时序阈值任务的证据要求；尚未完整设计并落盘 4 至 8 个可复核 case。 |
| 最小 VLM baseline | 未评测 | 尚未选择并运行开源小型 VLM，未形成可复现命令和逐样本输出。 |
| 分组评测与微调边界 | 未评测 | 尚未产生 baseline 结果，因此不能做失败分组或微调判断。 |

### 1.5.3 实践任务

1. **已完成对话诊断**：闭卷解释 VLM 从图像输入到文本输出的数据流，并定位与纯 LLM 不同的模块。
2. **当前项**：运行一个开源小型 VLM，完成最小图像问答与可复现命令。
3. **待执行**：从公开、合成或明确授权的数据构造小型任务集，并记录来源与证据边界。
4. **待执行**：先运行 zero-shot 与 few-shot 基线；只有错误分类表明微调可能解决主要误差时，才考虑参数高效微调。
