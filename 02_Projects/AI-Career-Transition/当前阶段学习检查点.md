## 1.3 已验证内容

### 1.3.1 Cross-entropy 与正确 token 概率

- 能说明 one-hot next-token 监督下，正确 token 概率越高，cross-entropy 越低。
- 能说明正确 token 概率趋近 1 时 loss 趋近 0，概率趋近 0 时 loss 趋向无界增大。
- 已纠正一次“高正确概率对应更大 loss”的反向判断，后续检查回答正确。

### 1.3.2 Softmax 与 logits 梯度

- 能解释 softmax 分母耦合整个词表，因此一个正确标签仍会让全部 vocabulary logits 收到梯度。
- 能解释正确 token 的 logit 应增大、错误 token 的 logit 应减小；错误概率越高，受到的压制越强。

### 1.3.3 反向传播主干

- 能说明 LM Head 反向传播需要同时形成参数梯度和返回 hidden state 的梯度。
- 能按高层顺序描述误差信号穿过 MLP、residual 与 attention 返回更早层。
- 能解释 residual 恒等路径保留直接梯度通道；鉴于已有 CNN 背景，本阶段不继续深挖通用反向传播细节。

### 1.3.4 Train / eval / autograd 边界

- 已确认 `model.eval()` 只切换 dropout、BatchNorm 等模块行为，不会自动关闭梯度。
- 已确认 `torch.no_grad()` 关闭求导记录，但不会自动切换 dropout 行为。
- 已确认 `loss.backward()` 计算梯度，真正修改参数的是 `optimizer.step()`。
- 能说明常规推理需要组合 `model.eval()` 与 `torch.no_grad()`。

### 1.3.5 Mask 的基础分工

- 能区分 causal mask 屏蔽未来 token，attention mask 屏蔽无效 PAD 输入。
- 能说明某位置不能读取右侧 EOS 是因为未来信息边界，不能读取 PAD 是因为 PAD 不是有效输入。
- 理解 label mask / `ignore_index=-100` 用于排除不参与 loss 的位置。

## 1.4 部分闭合内容

### 1.4.1 梯度累积

已理解：

- 不调用 `zero_grad()` 会累积 `.grad`。
- 梯度累积可用多个 micro-batch 模拟更大 batch，而不是用“大梯度逃离局部最优”。
- 累积 4 次但不做相应缩放，会使梯度尺度约放大 4 倍。
- `F.cross_entropy` 默认 `reduction="mean"`，会对非 `ignore_index=-100` 的有效 label 取平均。
- 不等长 micro-batch 应累计 `reduction="sum"` 的梯度，再除以整个累积窗口的有效 token 总数，才能与大 batch 的 token mean 对齐。
- 归一化必须发生在 gradient clipping 之前；sum 梯度随 token 数变大不等于梯度爆炸。
- 混合精度与变长累积组合时，顺序为 `unscale → 除以有效 token 总数 → clipping → optimizer.step`。

概念续测已闭合，仍需实践复核：

- 在真实代码中验证不等长 micro-batch 累积与合并大 batch 的梯度一致性。
- 验证 dropout、BatchNorm 和不同裁剪时机对严格等价性的影响。

### 1.4.2 LM Head 的矩阵梯度

已理解需要分别计算 LM Head 参数梯度与返回 hidden state 的梯度，但未独立写出完整矩阵关系和 shape。该局部不是当前主阻塞项，后续以计算图和 ASCII shape 复核，不在 CLI 中要求依赖 LaTeX 渲染的矩阵推导。

## 1.5 薄弱项与续测结果

### 1.5.1 Adam / AdamW 自适应更新（闭卷主干已通过）

历史误区：

- 曾把梯度一阶移动平均理解为“平均速度”，把梯度平方移动平均理解为“平均加速度”。
- 曾推断“统计阶数越高，拟合程度越高”，这不适用于 Adam 的设计目的。

2026-07-25 闭卷结果：

- 能从“mini-batch 梯度方向不稳定”和“不同参数梯度尺度差异大”两个问题解释 Adam。
- 能说明稳定且较小的梯度会保留方向并获得相对更大的有效步长；大而正负振荡的梯度会同时受到一阶矩抵消和二阶矩分母放大的抑制。
- 能解释 L2 正则项若直接进入 Adam 梯度，会同时影响一阶矩和二阶矩，使实际收缩强度被自适应机制改变。
- 能说明 AdamW 将任务梯度更新与 weight decay 解耦，使权重收缩更可控。
- 经纠正后已明确：一阶矩会趋于稳定而非无限增强；L2 梯度项为 `+\lambda\theta`，参数收缩来自后续减法更新。

仍需在代码实践中观察 optimizer state，并复核 bias correction、epsilon 对早期更新和数值稳定性的作用。

### 1.5.2 SFT prompt 与 label masking（续测已闭合）

初始误区：

- 曾把用户 prompt 的 `attention_mask` 设为 0，同时保留其 label token ID，实际方向相反。
- 后续独立检查已正确设置 System/User、Assistant 与 PAD 的 attention mask 和 labels。

目标判断规则：

```text
System/User prompt：attention_mask = 1，label = -100
Assistant answer：attention_mask = 1，label 保留 token ID
PAD：attention_mask = 0，label = -100
```

已能解释：prompt 虽然不直接计算监督 loss，answer loss 仍会通过 attention、prompt K/V 与 hidden states 反向传播到共享参数。

### 1.5.3 训练恢复与单 batch 过拟合判据（续测主干已闭合）

- 能说明 `global_step` 记录实际执行 `optimizer.step()` 的参数更新次数，而不是 micro-batch 数。
- 能区分 dropout ratio 与 RNG state：前者是模型配置，后者决定下一次随机操作从伪随机序列的哪个位置继续。
- 能说明恢复时应先重建并加载 model、optimizer、scheduler 与 global step，再在下一次随机操作前恢复 CPU/CUDA RNG state。
- 能说明 AdamW 的精确续训至少需要 model weights、optimizer 的一阶矩/二阶矩/step、scheduler state 和 global step；混合精度还需要 GradScaler，严格数据轨迹还需要 RNG 与 DataLoader/Sampler 状态。
- 能说明单次非零梯度和参数变化只证明更新链路工作；单 batch 过拟合还要求更新后在 `model.eval()` 与 `no_grad()` 下重新 forward，并同时满足 eval loss 阈值和有效 token accuracy 为 100%。
- 能区分职责：`train_step()` 执行一次有状态参数更新并返回标量指标，外层循环负责 global step、日志、停止条件、评估和 checkpoint；独立评估函数不接收 optimizer，并在结束后恢复原 train/eval 状态。
