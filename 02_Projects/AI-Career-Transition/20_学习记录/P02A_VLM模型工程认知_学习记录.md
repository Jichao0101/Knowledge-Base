### 1.8.2 作答、纠正与补充位置

| 主题 | 本轮观察 | 教学补充 |
|---|---|---|
| 带宽与延迟隐藏 | 能判断带宽已饱和时增加计算单元无明显收益；起初把就绪 warp 不足描述为调度速度瓶颈，后续能区分驻留与就绪。 | 15.1 |
| Tile、block 与 warp | 能指出 shared memory 和寄存器容量限制；曾把大 tile 等同于更多 block，把寄存器不足等同于 compute-bound。512 threads/block 的例子中把两个 block 算为 64 warp，已解释正确值为 32；纠正后未另做独立算术复测。 | 15.2 |
| Tiling 与同步 | 能说明无复用的向量加法不应仅为了使用 shared memory 而额外搬运；覆盖前同步能解释为防止破坏其他线程仍在读取的数据。加载后同步最初只答“一致性”，后补充读写先后关系。 | 15.3 |
| Coalescing 与缓存 | 两次将连续访问收益归因于 shared memory 或缓存命中；在冷缓存、32 字节块的例子中能算出搬运 32×32 字节、实际需要 32×4 字节，并最终区分搬运利用率与数据复用率。 | 15.4 |
| Fusion | 能说明省掉中间读写与缓冲区，以及资源占用上升可能减少驻留 warp；已补充 shared memory 增长依实现而定，等待更难隐藏不等于单次延迟变长。 | 15.5 |
| 在线 softmax | 起初将独立分块 softmax 的问题归因于局部最大值；经反例能判断全局权重偏向大分数，并独立给出旧状态重缩放因子 exp(old−new)。最终复述仍使用“通信更新 softmax”，已说明单卡逐块状态更新与最终归一化。 | 15.6 |
| FlashAttention 复杂度 | 能指出序列长度的二次计算复杂度；“在线 softmax 必然增加总计算量”已作边界澄清，未再独立复述。 | 15.6 |
| 测量与端到端收益 | 提出用显存占用和同输入推理时间比较；预热、重复、同步、峰值口径由教学补充。能接受局部加速与总耗时收益不一致，并提到 kernel 启动因素；未实际 profiling，下一步瓶颈证据题未作答。 | 15.7 |

本轮覆盖了延迟隐藏、资源驻留、tiling、同步、coalescing、fusion、在线 softmax 和端到端性能边界。多项解释在提示、反例或公式条件下完成，不能全部记为独立闭卷掌握。
