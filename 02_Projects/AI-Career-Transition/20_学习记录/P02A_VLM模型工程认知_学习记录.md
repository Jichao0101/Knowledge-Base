### 1.8.2 作答、纠正与补充位置

| 主题 | 本轮观察 | 教学补充 |
|---|---|---|
| 带宽与延迟隐藏 | 能判断带宽已饱和时增加计算单元无明显收益；起初把就绪 warp 不足描述为调度速度瓶颈，后续能区分驻留与就绪。 | 1.4.1 |
| Tile、block 与 warp | 能指出 shared memory 和寄存器容量限制；曾把大 tile 等同于更多 block，把寄存器不足等同于 compute-bound。512 threads/block 的例子中把两个 block 算为 64 warp，已解释正确值为 32；纠正后未另做独立算术复测。 | 1.4.2 |
| Tiling 与同步 | 能说明无复用的向量加法不应仅为了使用 shared memory 而额外搬运；覆盖前同步能解释为防止破坏其他线程仍在读取的数据。加载后同步最初只答“一致性”，后补充读写先后关系。 | 1.4.3 |
| Coalescing 与缓存 | 两次将连续访问收益归因于 shared memory 或缓存命中；在冷缓存、32 字节块的例子中能算出搬运 32×32 字节、实际需要 32×4 字节，并最终区分搬运利用率与数据复用率。 | 1.4.4 |
| Fusion | 能说明省掉中间读写与缓冲区，以及资源占用上升可能减少驻留 warp；已补充 shared memory 增长依实现而定，等待更难隐藏不等于单次延迟变长。 | 1.4.5 |
| 在线 softmax | 起初将独立分块 softmax 的问题归因于局部最大值；经反例能判断全局权重偏向大分数，并独立给出旧状态重缩放因子 exp(old−new)。最终复述仍使用“通信更新 softmax”，已说明单卡逐块状态更新与最终归一化。 | 1.4.6 |
| FlashAttention 复杂度 | 能指出序列长度的二次计算复杂度；“在线 softmax 必然增加总计算量”已作边界澄清，未再独立复述。 | 1.4.6 |
| 测量与端到端收益 | 提出用显存占用和同输入推理时间比较；预热、重复、同步、峰值口径由教学补充。能接受局部加速与总耗时收益不一致，并提到 kernel 启动因素；未实际 profiling，下一步瓶颈证据题未作答。 | 1.4.7 |

### 1.9.2 作答证据与局部诊断

| 主题 | 作答与纠正证据 | 本轮判断 |
|---|---|---|
| Batch 与显存 | 起初把参数梯度和 optimizer states 也计为随 batch 线性增长；随后独立给出 dW 的形状 [d_in,d_out]，说明 batch 维被累加消去。Adam OOM 题再次提到减小 batch 可减少“grad 缓存”，已澄清参数梯度与 activation 梯度的区别。 | 主干能解释；显存分类仍需复习，不能记为无提示完全掌握。 |
| Activation 与冻结 | 能说明 dW 依赖层输入，缺失输入可重计算；能沿冻结层向前传递输入梯度。冻结编码器且原始输入不需梯度时，内部状态无需为 backward 保留；训练线性头仍需保存或重建编码器输出。 | 对话机制解释可用；“产生 activation”与“保存到 backward”的混淆已纠正。 |
| Checkpointing | 能说明主要节省 activation，对参数和 Adam 状态主导的 OOM 帮助有限；能指出非 attention 中间状态也可重计算。Dropout 需保持原 mask，已补充原因是梯度必须对应原前向的 loss。 | 主干达到对话诊断意义上的 working；正确性细节有教学提示，无运行证据。 |
| 梯度累积 | 能说明小 micro-batch 降低 activation 峰值；等大小四份 loss 各除以 4，有效 token 数为 10/30 时加权 0.25/0.75；zero_grad 在周期前，optimizer.step 在全部 backward 后。 | 归一化与更新顺序达到对话诊断意义上的 working。 |
| 混合精度 | 起初认为参数与 activation 都有 FP32 副本、梯度恒为 FP32；纠正后能计算 BF16 权重加 FP32 master 为 6 bytes/参数，并解释小更新的舍入。已澄清每步均可转换 BF16，而非达到阈值才转换。 | 数值动机能够解释；具体 dtype 布局仍需结合实现复核，partial。 |
| Adam OOM 与 LoRA | 能指出首次 Adam step 初始化状态，并说明状态取决于可训练参数数量；能说明 LoRA 减少 Adam 需更新的参数。TP 与状态分片的区别曾由教学补充。 | 能判断该场景的优化方向；完整 PEFT/QLoRA 与分布式选择仍未系统评测。 |
