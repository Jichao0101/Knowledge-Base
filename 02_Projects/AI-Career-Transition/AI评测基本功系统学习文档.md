# 1 AI 评测基本功系统学习文档

## 1.1 阶段目标与关闭边界

Phase 1-B 用于建立简单 AI/Agent 评测的判断骨架，而不是建设完整评测平台。2026-08-09 的主动学习覆盖了任务类型、评分方法、评测合同、可靠性风险和 seed case 边界设计。

本阶段按调整后的职业学习范围关闭：概念主干达到对话诊断意义上的 `working`；规则脚本、逐 case 运行和重复评分属于传统实现练习，记为 `waived_by_scope`。关闭不表示这些实践已经执行，也不表示练习集已经成为 benchmark。

## 1.2 四类任务的判断骨架

- 确定性任务通常存在唯一结果或可由明确规则验证的结果。
- 开放生成任务允许多个合理输出，不要求依赖外部证据。
- 检索/证据任务要求结论受指定外部材料约束，但表达方式不一定唯一。
- 工具执行任务会改变外部状态，除结果正确外还需验证权限、目标状态、幂等性和副作用。

混合 Agent 任务应拆成检索、决策和工具执行等子任务，再分别定义合同；不能只按最终输出形式给整个任务贴单一标签。

## 1.3 评分方法的适用边界

- `exact match` 适合字符串或结构完全确定的结果，不适合评价允许合理转述的证据答案。
- 规则评分适合价格、舱位、时间、订单状态等结构化约束。
- 语义、模型或人工评分适合判断转述是否被原文支持、开放答案是否满足语义要求。
- 评分应分层：先做非结构化信息抽取，再用确定性规则判断可计算条件。

任务事实确定不代表答案字符串唯一；输出不唯一也不代表无法使用规则验证其中的硬约束。

## 1.4 评测合同

评测合同冻结“什么算成功、失败或应当拒绝”，而不是固定唯一实现轨迹。最小合同包括：

- 具体输入及版本。
- 可接受结果与必要条件。
- 证据要求。
- `abstain` 或暂停条件。
- 失败标签。
- 权限、时间、成本和重试预算。

工具名称与步数只有在安全或外部副作用要求下才需要成为硬约束；一般情况下应允许不同但同样授权、可验证的执行路径。

## 1.5 可靠性边界

- 评分者不一致时先修订任务合同或 rubric，不先扩充数据。
- 人工标签不天然是真实标签；应对照政策快照和真实外部状态，并通过争议仲裁形成参考标签。
- Agent 评分器与人工一致只能证明一致性，不能单独证明正确性。
- rubric 修改必须由任务定义、事实依据或反例驱动，不能以当前模型涨分为接受条件。
- 留出集一旦参与规则修改，就已经成为调试集；最终评估需要新的未查看案例。

## 1.6 Seed case 设计边界

学习对话形成了四种最小案例类型：

1. 正常合规与明确不合规航班。
2. 必要字段缺失，返回 `insufficient_evidence`。
3. 信息完整但没有合规航班，任务仍为 `completed`，合法结果为空集合。
4. 政策无法读取，按原因返回 `needs_authorization`、`input_error` 或 `failed`，不能伪装成空合规结果。

候选级 `decision_status` 与顶层 `task_status` 必须分开；前者表达业务判断，后者表达评测流程是否完成。

## 1.7 最简单基线的证据边界

确定性规则基线若运行通过，只能证明输入 schema、固定规则、预期标签、输出 schema 和评分链路基本自洽。它不能证明政策检索、自然语言理解、语义抽取、Agent 工具选择或对新政策的迁移能力。

本阶段未实际运行该基线。相关实现、重复评分和逐 case 结果按用户范围决定记为 `waived_by_scope`。
