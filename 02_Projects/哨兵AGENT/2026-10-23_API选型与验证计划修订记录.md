## 1.2 API 选型与成本

### 1.2.1 试点组合

按照“视觉能力优先、项目效果验证、成本优化”的顺序选型。公开图像 benchmark 用于筛选候选，并结合价格最终采用的模型。

以 Qwen 为首个试点供应商，分别配置视觉 Embedding 与多模态判别接口。将 Qwen3.8-Max 列为效果基线候选、Qwen3-VL-Plus 列为成本对照候选、Qwen3-VL-Embedding 列为检索候选。

DeepSeek 与 Kimi 作为判别侧的对照候选。比较时固定查询事件、图像预处理、参考图预算和评价标准，分别记录各家的图像计费量与推理延迟。视觉理解能力和向量检索质量分别验收，避免用通用图像问答分数代替检索指标。

### 1.2.2 成本核算

成本分为一次性建库和在线事件处理两部分：

- 建库成本：实际提取图像 token 数×Embedding 单价，加上失败重试、存储和索引开销。
- 在线成本：首轮图像与文本输入、模型输出，以及触发检索后的查询 Embedding、参考图输入和复判输出。
- 总体预算：事件量×平均单事件费用，加上新增参考图和索引升级的增量费用。

若单价按百万 tokens 计，建库 API 费用可写为：

`C_build = N × V × T_embedding × P_embedding / 1,000,000`

其中 N 为图像数、V 为每图提取视图数、T_embedding 为平均每视图计费 token 数。在线平均费用可写为：

`C_event = C_first_pass + r × (C_query_embedding + C_second_pass)`

其中 r 为进入检索增强分支的事件比例。实际费用以 API usage 和对应计费规则核算，包含适用的推理输出、缓存与重试费用。

通过分辨率抽样、候选帧预算、参考图预算和缓存复用控制费用。先确保接触细节可辨认，再逐步降低图像数量与分辨率。

## 1.3 验证计划

### 1.3.1 对照实验

| 实验 | 输入与流程 | 主要验证目标 |
|---|---|---|
| A：人工选帧 | 人工选择实施帧及必要邻帧→云端识别 | 模型分类能力的参考上限 |
| B：自动选帧 | 自动组织事件窗口→选帧→云端识别 | 选帧对识别效果的影响 |
| C：检索增强 | 自动选帧→直接识别→按需检索复判 | 检索的净收益、额外成本与延迟 |

参考库、开发集和测试集按事件隔离，尽量按车辆或场景进一步分组。同一事件的相邻帧保持在同一分组，避免相似画面泄漏导致结果偏高。

### 1.3.2 核心指标

| 指标 | 关注点 |
|---|---|
| 实施帧 Recall@B | B 张候选帧是否覆盖人工确认的实施瞬间 |
| 逐类 Precision、Recall 与宏平均 F1 | 九类行为的识别效果和类别不平衡 |
| 正常行为误报率 | 正常接触车辆、擦车、合法拔枪等场景的表现 |
| 拒判率与已判定样本准确率 | 证据覆盖和可靠性之间的关系 |
| 端到端漏检率 | 同时覆盖本地未报警事件和云端未识别事件 |
| 平均单事件费用、P95 延迟与失败率 | 部署成本和服务稳定性 |

评测需覆盖白天、夜间、遮挡、不同视角、小目标和多人的情况。针对“恶意拔枪”，分别统计动作识别效果与业务证据充分时的最终标签效果。

上线阈值根据可接受漏报、误报、延迟和费用共同确定，并在测试前固定。模型、提示词或索引升级后，使用固定回归集复核。
