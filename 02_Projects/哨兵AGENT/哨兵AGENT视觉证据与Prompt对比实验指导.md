# 哨兵 AGENT 视觉证据与 Prompt 对比实验指导

## 1. 本轮要解决什么问题

当前阶段按用户约束使用千问 API，不进行微调，优化范围为图像预处理、数据库与 Prompt 工程。用户反馈了三类现象：四路鱼眼拼接图中的人物与另一子图车辆被错误关联；模型选出的关键帧并非行为实施帧；即使输入了正确片段，仍可能混淆踢正步与踢车。这些是本轮问题来源，尚未通过原始图像、请求日志和人工标注完成归因。

本计划把任务拆成“输入属于哪个视角—动作发生在哪段时间—是否存在接触证据—满足什么标签定义”。优化目标是让每个结论都有可检查的输入依据，再通过对照实验确定瓶颈。阶段名称和 JSON 格式可以减少任务歧义，但不能补回未采集的画面，也不能保证模型看清接触点。

本文作为下一轮实验指导，不替代既有运行设计或声明效果已提升。九类标签、部位边界及业务状态沿用 [[02_Projects/哨兵AGENT/哨兵AGENT方案]]；事件保存、两阶段调用、代表帧与证据帧分离等设计见 [[02_Projects/哨兵AGENT/哨兵AGENT实现方案]]。既有实现文档记录单摄像头初始设计，本文的四路处理作为实验分支验证，不把设计草稿当成已部署状态。

## 2. 先确定证据是否存在，再判断模型哪里出错

一次错误结果可能来自采集、采样、定位或分类。先沿数据流检查，可以避免把所有错误都归因于 Prompt。

| 检查顺序 | 要回答的问题 | 不满足时的处理 |
|---|---|---|
| 原始事件 | 保存窗口是否包含关键动作，目标是否可见？ | 检查采集频率、前后窗口、遮挡与相机覆盖 |
| API 实际输入 | 关键证据是否被采样并以可用清晰度提交？ | 调整候选帧选择、缩放和裁剪；不能要求模型推断未提交画面 |
| 时间定位 | 已提交的证据是否进入输出区间和证据帧？ | 比较阶段定义、定位 Prompt 与粗到细采样 |
| 接触判断 | 正确片段中，模型能否区分可见接触、未接触和不确定？ | 检查局部细节、时序表达与判别规则 |
| 标签映射 | 观察正确后，是否映射到正确动作与部位？ | 检查类别边界、对照示例及业务上下文 |

人工提供正确视角、动作片段及邻帧，建立分类诊断基线；另用人工审核的可见事实文本进行分类诊断。若事实文本能正确分类、图像输入不能，优先排查感知与输入表达；若事实文本明确仍分类错误，再改判别规则。人工事实是诊断辅助输入，不能把该组结果当作自动视觉识别效果。

## 3. 如何组织四路图像，避免跨视角拼接关系

每个事件先建立输入清单，记录相机 ID、源帧 ID、采集时间或演示顺序、图像路径、尺寸与预处理版本。派生裁剪图还要记录父图和裁剪区域。模型看到的每张图使用事件内唯一的输入图 ID，并明确绑定相机和时间；四宫格则为各子图保留同样的绑定关系。

同一相机内按时间排序，不把四个相机在同一时刻的图像交替排列成一条虚假的连续动作序列。时间同步情况单独记录；时间不可靠时，不依据输入顺序推断跨相机先后关系。相机到自车的绑定来自配置，不能仅凭图像排列猜测。

第一轮保持事件、源帧、模型和判断要求一致，比较以下输入形式：

| 组别 | 输入方式 | 主要检验 |
|---|---|---|
| V0 | 现有四宫格 | 保存可复现基线 |
| V1 | 同样四宫格，增加边框、相机名和视角约束 | 显式边界与指令能否减少误绑定 |
| V2 | 四路作为独立图片输入同一次请求，按相机分组 | 图像分离的增益 |
| V3 | 每路时序独立请求，汇总带出处的观察 | 请求级隔离的增益与调用成本 |
| V4 | 在 V2 或 V3 的固定配置上增加单路去畸变 | 几何预处理的额外收益与细节损失 |

V1 同时增加了视觉标识和文字规则，只能判断整组措施的效果；若有效，再分别去掉标识或文字做消融。V4 需先核对标定输入、输出视野和重采样效果；去畸变与跨相机坐标关联分别处理，不能把去畸变图当成已有跨相机身份对应。原图始终保留，检查接触区域是否被裁掉或拉伸。

输入形式可能改变有效分辨率和费用。先在每路目标清晰度尽量可比的条件下比较表示方式，再在固定事件预算下比较实用效果；分别报告结果，不把增加像素和 token 的收益全部归给拆图。当前 API 型号的多图能力、像素限制和实际请求结果需要在开跑时记录确认。

跨视角汇总只聚合有相机和帧出处的观察；未提供经过验证的关联信息时，不合并不同视角的人物身份，不用 A 相机的脚与 B 相机的车证明接触。相互矛盾的观察保留为待复核项，不能靠多数投票消除。

## 4. 如何定义 preaction、action、postaction

本计划将阶段标签用于描述一个候选动作的时间结构，而非提前赋予危险属性。用户提到的 `proaction` 暂按“动作后阶段”理解，本实验统一写作 `postaction`；尚未确认具体开源数据集及原始术语，以下是项目自定义协议，不声称复现某数据集标准。

| 阶段 | 定义与边界 | 不能单独推出的结论 |
|---|---|---|
| preaction | 与候选动作连续关联的接近、准备过程，止于动作执行开始前 | 接近车辆、抬腿准备不证明危险 |
| action | 候选动作实际执行区间，从执行开始到本次执行结束；接触可能发生在其内部 | 存在 action 不等于存在接触或危险 |
| postaction | 与同次动作关联的回收、恢复或离开过程，止于该后续过程结束或下一动作开始前 | 离开、回头等行为不证明恶意 |
| unknown | 片段与候选动作相关，但阶段归属无法可靠判定 | 不能为凑齐阶段补写未观察过程 |

例如踢正步与踢车都可能具有“抬腿准备—向前摆腿—收腿落地”。两者的区别需要另外检查腿脚与车辆的关系。阶段标注回答“动作到哪一步”，接触标注回答“是否与对象发生接触”，分类回答“是否满足目标类别”。对于持续刮擦、拉拽等动作，分别制定执行起止规则，不能把踢击边界直接套用到所有类别。

标注员先看完整事件，以观察为依据划分候选动作，再标阶段与接触；不能只看预先选出的所谓实施帧。先用开发集的一小批事件试标，记录歧义并修订规则，随后冻结标注版本。关键接触和争议边界经第二人复核或独立复核流程裁定；没有可靠真值的样本保留“不确定”，不强行成为危险或正常真值。

阶段标注遵守以下约定：

- 每次动作分别分配 action_id，并绑定相机内的人员标识；该标识不构成跨相机身份。
- 输入从动作中途开始或提前结束时，只标可见部分，记录左截断或右截断，不要求三个阶段齐全。
- 连续多次踢击分别编号；多人可在不同动作记录中存在时间重叠。同一动作中已确定的阶段不重叠。
- 背景或与候选动作无关的片段不强制分配阶段。没有候选动作时返回空动作列表；空列表本身不证明事件安全。
- 帧区间端点为闭区间，端点必须是本次提交的输入图 ID。输入稀疏时，区间只表示采样分辨率下的范围，不声称精确到未提交的时刻。
- 人工真值同时保留原始时间边界及不确定范围。评测时将输入图 ID 映射回时间；缺少真实时间则只报告帧序指标。

阶段定位先覆盖整个事件，返回多个候选区间，再从原始序列补取密集邻帧细化。细化预算设上限，并保留一定全局覆盖，避免第一轮漏掉真动作后只能围绕错误区间继续搜索。阶段一定位和阶段二分类可以分别调用，也可先在单次请求中验证协议；阶段语义不规定必须增加多少次 API 调用。

## 5. 输出协议如何分开阶段、接触和分类

为避免上一轮 `not_supported` 被理解成“没看清就是没有接触”，本实验使用更明确的接触枚举：`contact_observed`、`no_contact_observed`、`unknown`。第二项只在所判断区间有可见证据支持未接触时使用；若关键过程遮挡、缺帧或仅有二维投影重叠，应使用 unknown。视觉支持接触仍不等于证明冲击力度、损伤或恶意。

每个动作记录包含阶段列表、支持区间判断的证据帧、接触状态及证据、分类结果。以下是虚构格式样例，不是项目实测：连续画面能看到摆腿过程，但脚部与车门的空间关系不清楚，因此阶段可以确定，接触和类别仍无法确认。

```json
{
  "schema_version": "phase_evidence_v1",
  "event_id": "demo_event",
  "actions": [
    {
      "action_id": "cam_left_a01",
      "camera_id": "cam_left",
      "actor_local_id": "person_01",
      "observed_action": "抬腿并向前摆动",
      "segments": [
        {
          "phase": "preaction",
          "start_frame_id": "q_left_101",
          "end_frame_id": "q_left_103",
          "observation": "人员靠近车辆并抬起右腿"
        },
        {
          "phase": "action",
          "start_frame_id": "q_left_104",
          "end_frame_id": "q_left_107",
          "observation": "右脚向前摆动并经过车门附近"
        },
        {
          "phase": "postaction",
          "start_frame_id": "q_left_108",
          "end_frame_id": "q_left_110",
          "observation": "右脚落地，人员继续行走"
        }
      ],
      "left_truncated": false,
      "right_truncated": false,
      "evidence_frame_ids": ["q_left_103", "q_left_105", "q_left_108"],
      "contact": {
        "status": "unknown",
        "contact_frame_ids": [],
        "evidence_frame_ids": ["q_left_105", "q_left_106"],
        "observation": "脚部与车门区域投影重叠，无法确认接触"
      },
      "classification": {
        "status": "insufficient_evidence",
        "labels": [],
        "target_part": "unknown",
        "intent_status": "unknown",
        "missing_evidence": ["需要能区分脚部经过车门前方与实际接触的画面"]
      },
      "representative_frame_id": "q_left_105"
    }
  ]
}
```

`contact_frame_ids` 仅记录支持实际接触的帧；unknown 时保持为空，另用 evidence_frame_ids 说明为何不能确认。代表帧可用于展示候选动作，但在证据不足时 UI 必须标为“候选动作代表帧”，不能标为“危险实施帧”。分类仍需接收完整证据集合和必要邻帧。

阶段一先返回动作记录中的定位与观察部分；阶段二补充接触和分类字段。模型输出与后端诊断状态分开：API、JSON 或 ID 校验失败记录 processing_failed，不改写成业务上的 insufficient_evidence。动作级分类沿用原有 classified、non_target、other_dangerous、insufficient_evidence 定义；多动作的事件级告警规则在实验配置中明确，初始按“任一动作满足目标标签则产生目标告警，同时保留其余动作状态”统计，不静默丢弃未知记录。

后端检查 ID 是否属于本次实际输入、相机是否匹配、时间端点是否有序、同一动作阶段是否冲突、参考图是否被错误引用、标签是否在原有集合。对接触为 unknown 却输出必须有接触证据的目标标签等矛盾，记录为协议失败并复核。校验只能发现结构和部分语义矛盾，不能验证图像中的接触事实。

## 6. Prompt 与示例库如何提供判别边界

先用明确规则建立无示例基线，再增加示例，才能知道改善来自哪里。Prompt 将输入分成 EVENT、REFERENCE、DEFINITIONS：事件帧是本次证据，参考样例只解释类别边界，标签定义约束输出。报警只说明分析入口，不证明危险行为已经发生。

阶段定位 Prompt 初稿：

```text
定位 EVENT 中可见的人车交互候选动作，不预设危险已经发生。
输入图均绑定相机、唯一图 ID 和时间或顺序。
逐相机、逐人物、逐次动作返回 preaction/action/postaction 区间；
无法确定阶段时可使用 unknown，缺失阶段不补写，无候选动作可返回空列表。
action 表示动作执行，不等于接触或危险。
用简短 observation 描述可见变化，区间端点和证据只能引用本次事件输入图。
没有明确关联资料时，不跨相机合并身份或拼接接触关系。
按 phase_evidence_v1 的定位字段输出，不推测未观察到的过程。
```

分类 Prompt 初稿：

```text
依据 EVENT 的候选区间、原始图像及邻帧判断动作、接触与目标部位。
上一阶段的 observation 是待核对的模型观察，不是已确认事实。
分别评估 contact_observed、no_contact_observed、unknown；
画面未覆盖关键过程或只有二维重叠时，不能据此确认接触或未接触。
检查正常动作是否也能解释观察，再按 DEFINITIONS 映射标签。
REFERENCE 仅用于比较判别边界，不得成为本事件的证据。
没有业务授权、充电状态等资料时，不推断恶意拔枪；意图保留 unknown。
证据不足时保留可见动作、缺失信息与 insufficient_evidence。
返回协议字段和简短可核查的视觉依据，不要求长篇推理文本。
```

示例要展示从观察到判断的差异：一组可包含真实踢车、相似抬腿但未接触、关键过程遮挡三种片段，分别标阶段、接触依据与分类。不只展示动作幅度最大的单帧，不把“姿态相似”当成类别等价，也不把车身未明显运动作为排除接触的充分依据。

现有危险参考库仍只保存已确认危险实施帧。本实验另设正常与不确定对照示例集，并维护各示例的来源事件、相机、阶段、接触真值、审核状态和预处理版本。动态检索可从不同集合召回互补示例；记录无匹配或失败，不因一定要凑齐正负例而塞入无关样本。检索相似度不作为危险概率。

开源样本只能作为待审的补充候选：接入前核对数据集名称、版本、许可、阶段定义与本项目的映射，并检查其视角和清晰度是否适用于鱼眼场景。具体数据集尚未确认，本轮不虚构数据来源，也不依赖它才能启动本地实验。

## 7. 按什么顺序做对比，才能解释结果

开始前冻结模型标识与可用版本、请求参数、Prompt、输入清单、预处理、示例库和人工标注版本。数据按来源事件划分开发集、示例集和保留测试集，同一事件所有相机、邻帧及派生裁剪均归入同一分组；尽量进一步隔离人物、车辆和场景。测试集不进入检索索引，也不用于调 Prompt。

先在开发集选择配置，最后一次性在保留测试集比较完整基线与候选方案。样本量以实际可获得事件为准，报告各类数量；小样本结论只用于决定下一轮采集方向。对易混淆固定子集安排同配置重复调用，记录波动，不能只保留成功的一次。

| 顺序与组别 | 固定条件与改变量 | 要回答的问题 |
|---|---|---|
| B0 冻结基线 | 保存现有真实请求、响应及人工复核结果 | 当前失败分布是什么？ |
| V0—V4 视角实验 | 固定人工选定源帧和判别要求，比较第 3 节输入形式 | 主要受空间混淆还是几何细节影响？ |
| P0 结构化基线 | 固定输入形式、帧和无示例条件，输出动作、接触、分类，不要求阶段 | 建立可检查字段的对照 |
| P1 阶段协议 | 在 P0 上增加阶段定义与阶段输出，其他字段和规则一致 | 阶段约束本身是否改善定位或分类？ |
| P2 接触判据 | 在 P1 上增加明确的接触/未接触/未知边界与正常解释检查 | 细化判据是否减少姿态误判？ |
| P3 固定示例 | 在 P2 上增加审核过的对照片段 | few-shot 是否带来稳定增益？ |
| P4 动态检索 | 用动态选择替换固定示例，尽量匹配示例数量与图像预算 | 检索选例是否优于固定例？ |
| T0 人工区间诊断 | 固定选定 Prompt，人工提供正确片段 | 证据较充分时的分类能力如何？ |
| T1 自动定位 | 全窗口固定采样，由模型定位；其余与 T0 对齐 | 自动采样与定位造成多少损失？ |
| T2 粗到细定位 | 在 T1 上增加候选区间邻帧细化 | 额外取帧和调用是否值得？ |
| E0 端到端复验 | 原流程与组合方案使用相同保留事件集 | 整体效果、拒判、成本和延迟是否可接受？ |

P0 已有结构化结果，P1 的比较才能区分“阶段约束”和“仅换成 JSON”的影响。V3、T2 等会增加请求或图像预算，既报告自然运行成本，也在预算可比条件下报告结果，不能只给准确率。逐步实验可以定位主要收益，但不能证明因素相互独立；最后仍需 E0 检查组合后是否发生退化。

## 8. 如何评测，并决定下一步

标注和指标分层对应前述数据流。评价阶段定位时，不要求 action 等于接触区间；评价接触时，不把参考图相似度或模型自评置信度当成真值。

| 层级 | 指标与统计口径 | 判读用途 |
|---|---|---|
| 输入覆盖 | 人工确认存在可见关键证据的事件中，API 提交帧覆盖该证据的比例；注明帧预算 B | 区分证据未提交与模型未识别 |
| 空间归属 | 至少发生一次无依据跨相机人车关联的事件数 / 评测事件数；另报关系判断总数 | 检查是否靠少输出关系掩盖问题 |
| 时间定位 | 各阶段时间 IoU（交并比）、起止边界误差、动作漏检与额外区间数 | 检查定位是否可靠，而非只挑到漂亮帧 |
| 证据选择 | 输出证据帧命中人工接触证据的事件比例、所选帧精确率及帧数量；在存在可见接触证据的子集计算 | 防止输出所有帧虚增召回 |
| 接触判别 | 接触、未接触、未知的混淆矩阵；人工未知样本单独统计 | 区分视觉关系错误与类别错误 |
| 危险分类 | 逐类 Precision/Recall、宏 F1、正常事件误报率；拒判计入已知危险样本的未检出 | 防止通过拒判隐藏危险漏检 |
| 覆盖与代价 | 拒判率、已判定子集准确率、API/协议失败率、费用、P50/P95 延迟 | 同时观察效果、可用性和成本 |

时间 IoU 为预测与真值区间交集时长除以并集时长；按相机、人物和动作实例匹配，匹配规则及容差在开发集上冻结。缺失阶段单独统计，不把未出现的阶段按完美匹配计分；人工边界本身不确定的样本记录容差或单列分析。帧序数据只给离散区间和帧误差，不能伪造秒级精度。

正常误报率的分母包括所有人工确认正常事件，另报这些事件中的拒判和处理失败；危险召回也不能只在模型愿意给结论的样本上计算。安全相关取舍应结合误报与漏检共同选择，不预设拒判率越高越好。现有告警后事件集只能评估告警后的分析链，不能据此声称系统端到端危险召回已验证；后者还需覆盖本地未报警的危险事件。

同一事件在不同配置中作配对比较，列出“修复、退化、无变化”的数量和代表事件。样本允许时按事件而非按相邻帧估计区间不确定性。数值验收目标尚未提供，开跑前在实验配置中固定可接受的危险召回、正常误报、拒判、延迟和费用边界；未约定目标时只报告相对变化，不宣称达到生产验收。

根据结果选择后续动作：拆图有效则优先固定输入协议；原图中存在但提交帧缺失则改采样；人工片段能分类而自动流程不能则改定位；人工事实文本正确但视觉输入错误则继续检查视觉证据；正确观察仍分类错误则改规则和示例。检索导致误报升高时，检查召回是否过度集中于危险样本和背景相似性，不能直接扩大图库。

## 9. 首轮执行清单与结果记录

首轮先收集三类失败事件及对应正常对照，保留原始四路时序、实际 API 输入和响应；完成事件隔离、阶段/接触标注及复核后，冻结 B0。随后执行 V 系列、P0—P3 与 T0/T1；只有固定示例已有可解释收益或出现明确选例需求，再执行 P4，避免先建大库却无法定位收益。T2 和 E0 按预算逐步接入。

每个实验保存 experiment_id、配置与 Prompt 版本、模型标识、源事件清单、实际输入图 ID、人工标注版本、示例 ID/索引版本、原始响应、校验结果、费用和耗时。多次尝试分别保存 attempt_id；模型观察、人工真值和人工修正分开记录。

实验结果记录至少回答：比较哪两组、改变了什么、评测事件及各类数量、主要指标差异、修复与退化的具体案例、费用变化、未解决问题、下一步保留或回退什么。所有性能结论必须链接到实际结果记录；本文当前没有运行结果。

尚待执行时补齐的输入为：实际千问模型与 API 配置、事件采样频率与图像预算、四路同步情况、去畸变所需标定资料、人工标注负责人及复核安排、测试集规模、数值验收目标。开源数据集及术语对齐是可选后续工作，不阻塞使用本地样本验证项目阶段协议。
