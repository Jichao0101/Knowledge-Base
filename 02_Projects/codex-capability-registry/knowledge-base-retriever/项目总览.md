# 1 knowledge-base-retriever 子项目总览

## 1.1 子项目定位

`knowledge-base-retriever` 是面向问题分析、方案设计和写前影响发现的轻量只读 skill。它的核心不是建设检索引擎，而是由 agent 把问题描述拆成能命中历史记录的检索面、关键词和 `rg` 查询，再由脚本在授权范围内执行确定性搜索、读取命中 Markdown 的相关 section，并形成可交给写入侧使用的原文证据包。

第一版只做五件事：

1. 接收问题描述、必填 `authorized_paths` 和可选上下文。
2. 由 agent 拆解 query facets 并输出结构化 query plan。
3. 由 agent 生成多组 `rg` 查询。
4. 由脚本在 `authorized_paths` 内执行 query plan。
5. 由脚本读取命中 Markdown 的相关 section，并输出 `retrieval_package`。

它必须兼容弱结构、旧结构和其他版本 Markdown 知识库；即使没有 Schema v2、retrieval header、Traceability Index 或治理型 frontmatter，也应能依靠路径、文件名、标题、heading、链接、正文和少量 frontmatter 完成最低能力检索。

## 1.2 触发条件

- 问题分析或方案设计可能受历史决策、既有修复或 active constraint 影响。
- 用户要求查找历史方案、修改记录、失败模式、验证证据或被替代结论。
- 知识库高风险写入前需要影响发现。
- Structure Builder 请求一个基于必填 `authorized_paths` 的 `retrieval_package`。

普通事实问答、纯机械修改或明确不依赖历史上下文的任务不必无条件触发。

## 1.3 Query Planning

Retriever 必须先把自然语言意图拆成 query facets，不能直接把整段用户描述交给单次关键词匹配。

| 检索面 | 内容 |
|---|---|
| 目标对象 | 项目、模块、组件、文档、API、配置项、文件路径 |
| 操作意图 | 新增、修改、替代、删除、迁移、修复、回退 |
| 问题表现 | 症状、错误文本、失败模式、异常行为 |
| 行为约束 | 必须保持、禁止发生、兼容性和验证边界 |
| 名称变体 | 中英文、缩写、旧名称、新名称、代码符号 |
| 历史类型 | current、fix、decision、validation、incident、superseded |
| 结构关系 | overview、正反向链接、同项目/模块、归档路径 |
| 时间状态 | 当前结论、历史方案、已替代方案、待验证方案 |

每个 query term 应记录来源：用户原文、可选上下文、路径派生、标题派生、alias 扩展、领域扩展或上一批命中扩展。不得把模型扩展词伪装成用户明确输入。中文分词、同义词扩展、旧名称推断和症状归类属于 agent 的 Query Planning 职责，不写入执行脚本。

## 1.4 检索批次

多轮可以保留，但不得做成 workflow、状态机、自动 agent loop 或 research loop。每个 phase 只是跑一批 `rg` 查询，合并结果，再决定是否需要下一批查询。

默认批次如下：

1. **精确锚点批次**：路径、代码符号、错误文本、配置键和明确标题。
2. **名称变体批次**：中英文、缩写、旧名、新名和常见同义表达。
3. **结构入口批次**：overview/current、项目或模块入口、链接和同目录记录。
4. **历史记录批次**：fix、decision、validation、incident、maintenance、superseded 和 archive。
5. **弱结构回退批次**：文件名、heading、正文全文和少量 frontmatter。

结果合并只需要形成阅读优先级，不需要实现复杂排序系统。优先级主要来自精确锚点、结构接近度、记录状态、来源多样性和命中 section 可读性。strong/medium/weak 或 authoritative/supporting/historical 只影响阅读顺序，不允许索引摘要直接成为事实结论。v0.1 脚本只执行 agent 给定的 query plan，不自行扩展 term 或理解问题。

## 1.5 授权与失败语义

- 查询规划、目录枚举、`rg` 搜索、候选合并、链接扩展和原文读取都必须限制在授权路径内。
- `authorized_paths` 是 retriever 的必填输入；缺失时不得执行搜索，也不得退化为全库扫描。
- 未授权目录不得进入候选集，也不得通过预建全库索引间接泄露路径或摘要。
- 无命中只能报告 `no_match_within_authorized_scope`，不能报告“没有历史方案”。
- 命中 current、fix、decision、validation 或 supersession 记录时必须读取对应 Markdown 原文 section。
- Retriever 可把 `protected`、`guarded`、`critical` 等词当作普通检索词或候选信号，但不得依赖这些 Schema v2 / Builder / AGENTS 治理概念作为强前提。
- 原文不可读、索引过期、结构关系断裂或 query plan 覆盖不足时必须显式报告 limitation。

## 1.6 输出契约

Retriever 输出版本化但只读的 `retrieval_package`：

```yaml
retrieval_package_version:
generated_at:
authorized_paths: []
authorized_paths_required: true
change_or_analysis_intent:
optional_context:
query_plan:
  facets: []
  terms: []
  rg_batches: []
queries_executed: []
candidate_documents: []
source_sections_read: []
candidate_decisions: []
candidate_constraints: []
candidate_fixes: []
candidate_supersessions: []
unresolved_ambiguities: []
recall_limitations: []
```

每项候选约束、候选决策、候选修复和候选替代关系都必须引用原文路径、section 或行号范围。Retriever 不负责到处计算 hash；若输入索引或调用方已提供 hash，可原样携带为可选字段。Package 是单次运行派生物，不是事实源；Builder 只消费该契约，不拥有其检索实现。

## 1.7 与 Structure Builder 的边界

- Retriever 拥有 Query Planning、`rg` batch 生成、候选合并、原文 section 读取和检索限制表达。
- Structure Builder 拥有文档结构、retrieval header / Retrieval Summary authoring、写入风险分类和 gate decision。
- Retriever 不执行知识库事实写入，不提升知识、不修改 metadata、不关闭 supersession 冲突。
- 两个 skill 可以共享概念和交换格式，但不共享实现权威；任一方不得通过复制对方规则形成第二权威。

## 1.8 验证计划

建立覆盖真实历史问题的固定基准集，至少评测：

- Query Plan facet 覆盖率。
- Recall@5、Recall@10 和首个相关结果出现位置。
- fix/decision/current/validation 的来源类型覆盖。
- 无结果时的正确降级表达。
- 授权边界泄露次数，目标为 0。
- 对旧名称、中文近义表达、路径变化和 superseded 方案的召回率。

第一版只使用 `rg`、路径和 Markdown 结构完成批次检索。只有固定基准证明该轻量方案不足时，才比较 FTS5 trigram、外部分词、BM25 或 embedding 混合检索；比较结果不得反向扩大第一版实现范围。

退出条件：固定基准达到约定 Recall@5/10，授权泄露为 0，无结果不会被表达为不存在历史上下文，且无 Schema v2 或 Traceability Index 时仍可完成最低能力检索。

## 1.11 非目标

- 不成为知识库事实源或新的 current 入口。
- 不判断知识真伪，不自动关闭冲突或提升 evidence level。
- 不执行写入、移动、删除、promotion 或 supersession。
- 不要求目标知识库先迁移到统一 schema。
- 不因为存在预建索引而扩大授权读取范围。
