# 1 语义冲突门禁优化 - 2026-06-24

## 1.1 背景

原 Structure Builder 门禁混合了两类保护：

- 目标类型保护：目标是 `current`、`guarded`、`critical`、`verified` 或入口文件。
- 语义冲突保护：本次写入可能覆盖历史修复、约束、决策或 supersession。

本轮调整将目标类型降级为谨慎信号，不再单独触发用户确认或 `manual_review`。

## 1.2 已实现变化

- `gate-decision-table.yaml` 删除 `status_verified`、`protection_critical`、`protection_guarded` 直接复核规则。
- 新增 `semantic_conflict`、`high_risk_field_change`、`replacement_delete_or_promotion` 三类复核条件。
- `kb.py` 新增语义冲突判定：只有命中 fix / decision / validation / incident 且存在匹配词或 retrieval_package 原文来源时，才作为具体冲突。
- `minimal-apply-check` 不再因 current/guarded/critical/verified 目标类型要求用户确认。
- `guarded_or_critical_target` 不再作为完整 preflight 的独立高风险 change class。
- 回归测试覆盖 guarded verified 目标无冲突可放行、具体 fix 冲突要求复核、current 轻量 append 不因目标类型确认。

## 1.3 当前门禁语义

要求复核或阻止的条件收敛为：

- 发现具体语义冲突。
- 高风险变更缺少足够 retrieval/source 覆盖。
- 修改 metadata/status/evidence/current group 等高风险字段或结构。
- 执行结论替代、delete、move、promotion 或 supersession。
- 违反 append-only、授权范围、policy 可读性、双向 supersession 或 hash 一致性约束。

`current`、`guarded`、`critical`、`verified` 和入口文件本身只影响谨慎程度与报告解释，不再作为独立复核理由。
