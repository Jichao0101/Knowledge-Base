# 1 结构归位门禁降噪优化 - 2026-07-03

## 1.1 背景

知识库执行 J6 候选集中和 Builder/Retriever 项目文档归位时，旧流程暴露出三类噪声：

- 目录移动被 `preflight` 的文件目标假设阻断，只能拆成逐文件 preflight。
- `move/delete/promotion` 被混为一类高风险操作，结构归位也会触发 `manual_review` 或 source read 要求。
- `manual_review` 的非零返回码会打断 shell 循环；mandatory `hash-check` 对单人本地维护收益很窄。

本轮目标是把结构归位与语义高风险写入解耦，保留授权、append-only、supersession、正式提升和写后 lint 等真正有用的约束。

## 1.2 已实现变化

- 新增结构类 change class：`structure_relocate`、`archive_move`、`index_path_sync`。
- `move` 不再默认进入 full semantic preflight；`semantic_delete`、`protected_delete`、formal promotion、supersession、conclusion replacement 等仍保留高风险路径。
- `minimal-apply-check` 支持结构类目录 target，目录内 Markdown 会进入 target snapshot，不再要求拆成逐文件检查。
- `preflight` 对结构类目录 target 不再因 `target.is_file()` 假设返回 blocked。
- `manual_review` / `blocked` 默认返回码改为 0；新增 `--strict-exit-code` 供 CI 或严格模式保留 `allow=0`、`manual_review=2`、`blocked=3`。
- `hash-check` 默认只检查规则、skill 内容、policy、目标文件和已读 source sections；新增 `--check-vault-fingerprint` 才校验整个授权范围 Markdown 指纹。
- `SKILL.md` 与 `references/governance-tools.md` 已同步为“结构归位 scope-check + post-lint；语义高风险 full semantic preflight”的流程。

## 1.4 当前语义

- 结构归位、同库分组、候选内容集中、项目文档迁移、路径索引同步：使用 `minimal-apply-check` 做 scope check，写后跑 lint。
- 正式知识提升、结论替代、supersession、protected rewrite、metadata/status/evidence level 变化、semantic/protected delete：继续使用 full semantic preflight。
- `hash-check` 是可选并发证据，不是单 agent 本地维护的默认必经步骤。

## 1.5 风险与后续

- 这不是安全沙箱；不按流程执行的 agent 仍可直接写文件。Builder gate 的定位是决策辅助和审计提示。
- 后续可增加 `relocate-check` 专用命令，显式输出 source/target move manifest、受影响 wikilink 和需要同步的入口文件。
- 后续可在 lint 中补结构归位后的 move manifest 完整性检查，减少对人工 diff 的依赖。
