# 1 知识库维护治理项目总览

## 1.1 项目目标

本项目不以“建设更强的知识库系统”为目标，而以以下结果为目标：

> 在问题分析阶段尽可能找到相关历史方案、修改和约束，并在写入阶段防止已有修复、约束和当前事实源被静默覆盖。

## 1.2 当前事实源

| 内容 | 当前入口 | 状态 |
|---|---|---|
| Structure Builder 子项目 | [[02_Projects/Knowledge-Base/knowledge-base-structure-builder/项目总览]] | active，负责 authoring、indexing-prep 和写入治理 |
| Retriever 子项目 | [[02_Projects/Knowledge-Base/knowledge-base-retriever/项目总览]] | active v0.1，负责 agent-led Query Planning、授权范围内 `rg` 搜索和原文 section 证据包 |
| 当前结构状态 | [[02_Projects/Knowledge-Base/知识库结构审计_current]] | active audit |
| 外部参考证据 | [[04_Sources/知识库工程/2026-06-22_LLM-Wiki-v2与pro-workflow来源证据卡]] | source card，不是正式知识 |

## 1.3 默认读取顺序

1. 本项目总览。
2. 涉及结构化、规范化或写入治理时读取 [[02_Projects/Knowledge-Base/knowledge-base-structure-builder/项目总览]]。
3. 涉及问题分析、历史方案检索或写前影响发现时读取 [[02_Projects/Knowledge-Base/knowledge-base-retriever/项目总览]]。
4. 需要核对当前结构状态时读取 [[02_Projects/Knowledge-Base/知识库结构审计_current]]。
5. 需要核对外部参考时读取来源证据卡及其原始链接。

## 1.4 当前阶段

- 阶段 0 至 3B 的首版 skill-owned rules/tools 已实现，详见 [[02_Projects/Knowledge-Base/Current Maintenance Records/知识库治理Skill阶段0至3B实现记录-2026-06-22]]。
- metadata、只读 lint、Traceability Index、preflight gate 和 hash check 已通过单元测试与真实知识库只读集成验证。
- 项目已拆分为 Structure Builder 与 Retriever 两个子项目；现有阶段 0 至 3B 实现归入 Structure Builder 的当前实现基线，Retriever 已完成 v0.1 skill 实现。
- 仓库 `AGENTS.md` 是目标仓库本地政策，不再作为 skill 资产或要求与 skill 版本同步。
- 当前 Traceability 子串匹配不具备 Query Planning 能力，不等同于可靠历史上下文检索。
- Retriever 第一版已收缩为必填 `authorized_paths`、agent-authored query plan、`rg` batch execution 和 source section 读取，不建设 plan/workflow/多后端检索系统，也不依赖 Schema v2 的 protected 概念或重 hash 计算。
- Retriever v0.1 已在 `/mnt/d/codex-capability-registry/skills/knowledge-base-retriever` 落地；下一步应进入真实项目测试和历史问题基准，而不是继续堆叠 v1 功能。
- DMS Tracking A/B 评测未证明 Fix Registry 能净提升检索质量，且暴露聚合摘要抢 rank 与仍需追读原文的风险；Structure Builder 已移除 Fix Registry 实现，当前改为支持原始 fix / decision / validation 文档的 Retrieval Summary lint 与 patch proposal。
- Builder 默认 timestamped reports 调整为每类最多保留最新 3 条，避免 `reports/kb/` 无限增长。
- 父级实施方案已删除，避免与两个子项目形成第三个方案权威；阶段 0 至 3B 的历史实现证据继续由实现记录保存。
- 两个子项目暂不建立五份 current 文档组；各自总览承担当前设计入口，形成长期独立实现与验证事实后再评估 current 化。
- 后续若该项目进入长期实现和反复维护，再按 current lifecycle 评估是否创建 design/spec/implementation/validation current 文档组。

## 1.5 非目标

- 不建设通用知识图谱平台。
- 不以 SQLite、搜索索引或报告替代 Markdown 事实源。
- 不自动推断知识真伪或为每条 claim 赋予浮点概率。
- 不自动提升正式知识、解决 supersession 冲突或删除历史记录。
- 不在基准评测前直接引入向量检索。
- 不让 Structure Builder 和 Retriever 共享检索或门禁的实现权威。

## 1.6 当前未解决项

- Schema v2、preflight report、Traceability Index 和历史文档缺省解释已形成首版实现，但尚未经过独立 review 或长期运行验证。
- 现有索引构建和原文读取尚需改为全链路授权范围约束，不能先扫描全库再过滤。
- Retriever 的 v0.1 实现已完成，但轻量 Query Planning 的真实项目召回率、Builder 交换契约和历史问题基准集尚未验证。
- Structure Builder 的下一步重点是 Retrieval Summary / Retrieval Anchors lint、patch proposal 与 report retention 验证；Fix Registry 不再作为当前实现能力或优化主线。
- `知识库结构审计_current.md` 仍承载较多历史维护流水，等待阶段 4 去历史化；本次 retriever 状态同步命中 `manual_review` 门禁，需人工确认后再同步该 current 文件。
- 中文全文检索技术选型必须等待轻量 `rg` 基线与召回基准结果。
