# 1 知识库维护治理项目总览

## 1.1 项目目标

本项目不以“建设更强的知识库系统”为目标，而以以下结果为目标：

> 防止已有修复、约束和当前事实源在后续写入中被静默覆盖，并保证高风险写入能够追溯到相关 Markdown 原文和验证证据。

4. 需要核对外部参考时读取来源证据卡及其原始链接。

## 1.4 当前阶段

- 阶段 0 至 3B 的首版 skill-owned rules/tools 已实现，详见 [[02_Projects/Knowledge-Base/Current Maintenance Records/知识库治理Skill阶段0至3B实现记录-2026-06-22]]。
- metadata、只读 lint、Traceability Index、preflight gate 和 hash check 已通过单元测试与真实知识库只读集成验证。
- 仓库 `AGENTS.md` 已补齐写前门禁与自动化禁区硬政策，并同步到 skill 的知识库 AGENTS 模板；工具细节继续留在 skill 内。
- 中文检索 tokenizer 基准尚未执行；当前 Traceability 召回不等同于完整全文检索。
- 暂不建立五份 current 文档组：当前实现仍由单一 active 方案和一份实现记录完整覆盖，尚未形成需要五份 current 分工维护的长期模块边界。
- 后续若该项目进入长期实现和反复维护，再按 current lifecycle 评估是否创建 design/spec/implementation/validation current 文档组。

## 1.5 非目标

- 不建设通用知识图谱平台。
- 不以 SQLite、搜索索引或报告替代 Markdown 事实源。
- 不自动推断知识真伪或为每条 claim 赋予浮点概率。
- 不自动提升正式知识、解决 supersession 冲突或删除历史记录。
- 不在基准评测前直接引入向量检索。

## 1.6 当前未解决项

- Schema v2、preflight report、Traceability Index 和历史文档缺省解释已形成首版实现，但尚未经过独立 review 或长期运行验证。
- `知识库结构审计_current.md` 仍承载较多历史维护流水，等待阶段 4 去历史化。
- 中文全文检索技术选型必须等待阶段 6 基准结果。
