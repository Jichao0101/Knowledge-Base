# knowledge-base-retriever 子项目总览

## 1. 子项目定位

`knowledge-base-retriever` 是面向问题分析、方案设计和写前影响发现的只读 RAG / historical-context skill。它独立兼容弱结构、旧结构和其他版本 Markdown 知识库；即使没有 Schema v2、retrieval header 或 Traceability Index，也尽量从授权范围内的路径、文件名、标题、heading、链接、正文和少量 frontmatter 找到历史方案、修改记录和约束。

## 2. 触发条件

- 问题分析或方案设计可能受历史决策、既有修复或 active constraint 影响。
- 用户要求查找历史方案、修改记录、失败模式、验证证据或被替代结论。
- 知识库高风险写入前需要影响发现。
- Structure Builder 请求一个授权范围明确的 `retrieval_package`。

普通事实问答、纯机械修改或明确不依赖历史上下文的任务不必无条件触发。

## 3. Query Planning

Retriever 必须先把自然语言意图拆成检索计划，不能直接把整段用户描述交给单次关键词匹配。

| 检索面 | 内容 |
|---|---|
| 目标对象 | 项目、模块、组件、文档、API、配置项、文件路径 |
| 操作意图 | 新增、修改、替代、删除、迁移、修复、回退 |
| 问题表现 | 症状、错误文本、失败模式、异常行为 |
| 行为约束 | 必须保持、禁止发生、兼容性和验证边界 |
| 名称变体 | 中英文、缩写、旧名称、新名称、代码符号 |
| 历史类型 | current、fix、decision、validation、incident、superseded |
| 结构关系 | overview、正反向链接、同项目/模块、归档路径 |
| 时间状态 | 当前结论、历史方案、已替代方案、待验证方案 |

每个 query term 应记录来源：用户原文、路径派生、标题派生、alias 扩展、领域扩展或上一轮命中扩展。不得把模型扩展词伪装成用户明确输入。

## 4. 多轮检索流程

1. **精确锚点轮**：路径、代码符号、错误文本、配置键和明确标题。
2. **概念扩展轮**：同义词、中英文、缩写、旧名、新名、症状和行为表达。
3. **结构扩展轮**：overview/current、链接、反向链接和同项目模块记录。
4. **历史扩展轮**：fix、decision、validation、incident、maintenance 和 archive。
5. **弱结构回退轮**：文件名、heading、正文全文和少量 frontmatter。

结果排序应同时考虑语义相关性、精确锚点、结构接近度、记录状态和来源多样性。strong/medium/weak 或 authoritative/supporting/historical 只影响阅读优先级，不允许索引摘要直接成为事实结论。

## 5. 授权与失败语义

- 查询规划、目录枚举、索引构建、匹配、链接扩展和原文读取都必须限制在授权路径内。
- 未授权目录不得进入候选集，也不得通过预建全库索引间接泄露路径或摘要。
- 无命中只能报告 `no_match_within_authorized_scope`，不能报告“没有历史方案”。
- 命中 protected、current、fix、decision 或 validation 时必须读取对应 Markdown 原文。
- 原文不可读、索引过期、结构关系断裂或 query plan 覆盖不足时必须显式报告 limitation。

## 6. 输出契约

Retriever 输出版本化但只读的 `retrieval_package`：

```yaml
retrieval_package_version:
generated_at:
authorized_paths: []
change_or_analysis_intent:
query_plan:
  facets: []
  terms: []
  retrieval_rounds: []
queries_executed: []
candidate_documents: []
source_documents_read: []
historical_decisions: []
active_constraints: []
superseded_alternatives: []
unresolved_ambiguities: []
recall_limitations: []
```

每项约束、决策和替代关系都必须引用原文路径、section 和 hash。Package 是单次运行派生物，不是事实源；Builder 只消费该契约，不拥有其检索实现。

## 7. 与 Structure Builder 的边界

- Retriever 拥有 Query Planning、检索轮次、召回、排序和检索限制表达。
- Structure Builder 拥有文档结构、retrieval header 规范、写入风险分类和 gate decision。
- Retriever 不执行知识库事实写入，不提升知识、不修改 metadata、不关闭 supersession 冲突。
- 两个 skill 可以共享概念和交换格式，但不共享实现权威；任一方不得通过复制对方规则形成第二权威。

## 8. 验证计划

建立覆盖真实历史问题的固定基准集，至少评测：

- Query Plan facet 覆盖率。
- Recall@5、Recall@10 和首个相关结果排名。
- fix/decision/current/validation 的来源类型覆盖。
- 无结果时的正确降级表达。
- 授权边界泄露次数，目标为 0。
- 对旧名称、中文近义表达、路径变化和 superseded 方案的召回率。

第一版优先使用 `rg`、路径和 Markdown 结构完成多轮检索。只有基准证明不足时，再比较 FTS5 trigram、外部分词、BM25 或 embedding 混合检索。

## 9. 当前状态与下一步

- 当前为设计阶段，尚未创建 skill 实现。
- 下一步先固化 query-plan 与 `retrieval_package` schema，再建立历史问题基准集。
- 不依赖 Structure Builder 的 Schema v2 或 Traceability Index 才能工作；存在这些派生结构时可以利用，但必须保留无索引回退路径。

## 10. 实施路线

1. 固化八类检索面、term origin、检索轮次、停止条件和 limitation 语义。
2. 先使用 `rg`、路径、标题、heading、链接和正文实现授权范围内的无索引基线。
3. 为 current、fix、decision、validation 和 protected 命中记录原文 section、行号与 hash。
4. 版本化 `retrieval_package`，使 Builder 能验证而不接管检索实现。
5. 建立覆盖旧名称、中文近义表达、路径变化、superseded 方案和无结果场景的基准。
6. 仅在基线未达标时比较 FTS5 trigram、外部分词、BM25 或 embedding 混合检索。

退出条件：固定基准达到约定 Recall@5/10，授权泄露为 0，无结果不会被表达为不存在历史上下文，且无 Schema v2 或 Traceability Index 时仍可完成最低能力检索。

## 11. 非目标

- 不成为知识库事实源或新的 current 入口。
- 不判断知识真伪，不自动关闭冲突或提升 evidence level。
- 不执行写入、移动、删除、promotion 或 supersession。
- 不要求目标知识库先迁移到统一 schema。
- 不因为存在预建索引而扩大授权读取范围。
