# 1 knowledge-base-structure-builder 子项目总览

## 1.1 子项目定位

`knowledge-base-structure-builder` 是面向 Markdown 知识库结构化、规范化、写入治理和 indexing-prep 的 authoring skill。它把知识库维护成可稳定召回、可追溯、可执行写前门禁的形态，但不拥有自然语言 Query Planning、历史上下文召回或相关性排序的实现权威。

## 1.2 核心职责

- Bootstrap、Migration、Maintenance 和 current lifecycle。
- 知识、项目、候选、来源和归档的分层放置。
- 入口、overview、current 文档组、链接和 supersession 维护。
- 生命周期与门禁 frontmatter 的 schema、lint 和兼容解释。
- retrieval header 的 authoring 规范、完整性检查和过期检查。
- 可重建 metadata、trace/indexing projection 的准备能力。
- 基于目标风险、授权、原文读取证据、change policy 和 hash 的确定性写前门禁。
- 写后 lint、入口同步和结构审计。

## 1.3 明确不负责

- 从自然语言变更意图生成检索词和检索面。
- 同义词、旧名称、中英文别名和问题症状扩展。
- 多轮历史检索、结果排序和召回充分性判断。
- 把没有检索命中解释为不存在历史约束。
- 为弱结构或其他版本知识库提供通用 RAG 能力。
- 将目标仓库 `AGENTS.md` 打包进 skill 或与 skill 版本绑定。

## 1.4 与 retriever 的协作契约

写入前需要历史影响分析时，Structure Builder 消费 Retriever 生成的 `retrieval_package`，但不复制其查询和排序实现。Structure Builder 只验证：

1. 检索是否限定在本次授权范围。
2. 高风险目标是否完成规定检索轮次和原文读取。
3. package 引用的来源 hash 是否仍有效。
4. 是否存在 active constraint、历史修复或 supersession 冲突。
5. 当前 change policy 应返回 `allow`、`manual_review` 还是 `blocked`。

Retriever 的低置信度、无结果或未解决歧义不得被 Builder 自动解释为安全。

## 1.5 风险分级门禁

| 变更 | 历史检索要求 | 写入门禁 |
|---|---|---|
| 普通 Inbox 新建 | 无或轻量 | 授权和落点检查 |
| normal 文档追加且不改变结论 | 局部 | target hash 和 append 检查 |
| 项目设计或 current 修改 | 完整 | 原文读取、影响分析和必要时人工复核 |
| guarded、verified、critical 修改 | 完整 | 自动化只生成 proposal 或 patch draft |
| supersede、delete、move、promote | 完整 | 关系、证据和双向 supersession fail-closed |

门禁保持确定、窄接口和可审计，不在 gate 内实现检索策略。

## 1.6 文档三层契约

### 1.6.1 Frontmatter

只保存门禁和生命周期字段：`status`、`evidence_level`、`evidence_refs`、`review_after`、`supersedes`、`superseded_by`、`protection_level`、`change_policy`。

### 1.6.2 Retrieval header

正文中的稳定检索锚点可包含 topic、component/symbol、alias/previous name、symptom/failure mode、affected path、constraint 和 related decision。它只增强召回，不替代正文事实，不允许关键词堆砌。

### 1.6.3 正文

保存完整解释、背景、设计或修复过程、适用边界和验证证据。Retrieval header 与正文冲突时，以正文及其可读取证据为准。

## 1.7 AGENTS.md 边界

目标仓库 `AGENTS.md` 是本地政策文件。Skill 只发现、读取并执行它，不携带权威模板，不自动创建或覆盖它，也不要求它与 skill 版本同步。运行报告可记录 policy path 和 hash，但该记录只用于证明本次运行采用了哪份政策。

## 1.8 当前状态与下一步

- 现有 skill 已实现 metadata、lint、Traceability Index、preflight 和 hash check 的首版。
- 当前检索逻辑仍与 gate 耦合，后续应将 Query Planning 和排序权威移出。
- 索引、候选匹配和原文读取必须统一接受 authorized paths；不得先全库扫描再过滤结果。
- 应移除 `assets/AGENTS.knowledge-base.template.md` 及 Bootstrap 中默认创建或 patch `AGENTS.md` 的行为。
- 在 Retriever 交换契约稳定后，Builder 增加 `retrieval_package` 校验和风险分级 preflight。

## 1.9 实施路线

1. 使目录枚举、metadata、索引、匹配、链接扩展和原文读取统一接受 authorized paths。
2. 从现有 CLI 中移除 query term 生成和相关性排序权威，保留 metadata、lint、indexing-prep、gate 和 hash check。
3. 固化最小生命周期 frontmatter、retrieval header、legacy 缺省解释和 lint。
4. 校验 Retriever package 的版本、授权范围、原文 section/hash、歧义和 limitation。
5. 实现普通新建、非结论追加、current 修改、protected 修改和 supersession 的分级门禁。
6. 继续 current 去历史化、记录迁移、入口同步和 supersession 完整性检查。

退出条件：Builder 不再生成自然语言检索计划；高风险 gate 输入可追溯到本地政策、目标原文、Retriever 原文读取证据和稳定 rule ID。

## 1.10 验收标准

- 自动化直接修改 verified、guarded、critical 或 active-constraint 文档的次数为 0。
- append-only 历史内容不被自动改写或删除。
- 结论替代具备双向 supersession、原因和可读取证据。
- policy、目标或来源 hash 变化会使 preflight 失效。
- 删除缓存后能够从授权范围内的 Markdown 重建派生物。
- `AGENTS.md` 不作为 skill 资产，也不由 skill 默认创建或覆盖。
- Builder 不包含 Query Planning、同义词扩展或相关性排序的第二实现。
